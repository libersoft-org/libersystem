### What was implemented (files and functions)

THE INTERFACE - `src/user/libs/graphics/soft2d/src/workers.rs` (new):
- `pub trait Workers { fn lanes(&self) -> usize; fn run<'u>(&self, lanes: &mut [Lane], units: &mut [Unit<'u>], work: &(dyn Fn(&mut Lane, &mut Unit<'u>) + Sync)); }` - the shape of `soft3d::frame::Workers`, so one application pool serves both backends. `Serial` (the caller's thread, units in order) is the default and the scalar reference.
- `Lane` - everything a unit writes: `raster: Rasteriser`, `pool: Pool` (layer/filter surfaces), `masks: MaskPool`, `spans: Spans`, `tile: Tile`, `clips: ClipStack`, `layers: Vec<Layer>`, `nodes: Vec<Option<Surface>>` (a filtered layer's node table), and `failure: Option<(usize, Error)>` (the first unit this lane failed in). `Lane::scratch_bytes` is what a lane is charged.
- `UnitKind { Bands, Tiles, Rectangles }` and `Unit<'u> { index, first_tile, tiles, access, ran, whole }`; `pub(crate) enum Access<'u> { Band { view, top }, Slot { source, slot, tile, pitch }, Rect { rows: [&'u mut [u8]; TILE_SIZE], tile, layout } }`.

THE BACKEND - `src/user/libs/graphics/soft2d/src/backend.rs`:
- `Soft2d::with_workers(&dyn Workers)` (held from construction like the image source; the `Backend` trait's `prepare`/`render` carry no pool) and `Soft2d::with_units(UnitKind)` (for the benchmark and the tests; the default is `Rectangles`, the measured winner).
- `prepare`: glyphs are placed here (`place_glyphs` -> `Placed::{Edges, Mask, Bitmap}`): each placed glyph's cache key and device origin are computed with the replay's former arithmetic, each distinct key is resolved through the cache once (`GlyphRaster::shared`, a miss decoded by the provider), outline and colour-layer forms are flattened and edge-built at their placed origin, and masks and bitmaps are held as `Arc<GlyphImage>`. Gradient ramps (`ramps`) and blur kernels (`kernels`, `filter::kernels`) are resolved into the prepared list. `LaneShape` records the list's needs (surfaces, scratch extent, clip masks, widest edge list including glyph edges, clip depth, layer depth, largest filter graph) and `LaneShape::reserve` reserves a lane to them.
- THE CEILING ORDER: the first lane is reserved and the optional decoded copies are given back newest first against `lane_bytes + bins` exactly as before (the refusal before any pixel is unchanged); lanes beyond the first are added one at a time only while they fit in what is left, up to `min(pool lanes, units)`; the cost that exists only with several lanes (the tile-cut unit table, `units * size_of::<Unit>()`, and for `Tiles` the intermediate) is charged with the second lane; a frame with one lane is cut into bands. The comments that called a copy "the same picture" and its loss "time and nothing else" were corrected (`backend.rs` at the ceiling loop, `paint.rs` at the copy) to say it can move a pixel.
- `render`: the shader table and the unit table are recycled from frame to frame (`recycle`, in-place collect over an emptied vector); the `work` closure skips a unit already `ran` (a unit handed out twice is replayed once), skips units after the lowest failure, asks the cancellation before every unit and sets a shared `stopped` flag so every lane stops at its next unit; `verdict` returns the lowest failing unit's error (min over the lanes' `failure`), then `Cancelled`, then `IncompletePool` if any unit never ran. Units are built by `band_units` (one contiguous band per unit, memory order handled for bottom-left targets), by the `Tiles` arm (a slot of `intermediate` per unit, target read-only during the run, `assemble` copying only units that finished whole) and by `rectangle_units` (every target row cut into its tiles' parts; each unit holds its tile's row parts).
- `src/user/libs/graphics/soft2d/src/target.rs`: `Tile::load`/`Tile::store` take the unit's `Access` (band view, read-only source + slot, or row parts through `part_layout`); the encoder is told absolute coordinates in every case, so the dither is position-dependent exactly as before.
- `glyph.rs`: cache entries are `Arc<GlyphImage>`; `GlyphRaster::shared` returns the shared form; `get` keeps its signature; eviction drops only the cache's reference. `clear` still bumps the generation, and the prepared key still carries it.
- `filter.rs`: `evaluate` takes the lane's node table and the prepared kernels (no per-tile allocation); `BlurKernel` type. `clip.rs`, `paint.rs`, `raster.rs`: reservations and prepared ramps.
- `Sync` supertraits: `ImageSource: Sync` (`target.rs`) and `Cancellation: Sync` (`backend.rs`); `GlyphProvider` does not gain it (called only at prepare).
- `src/user/libs/graphics/render2d/src/lib.rs`: `Error::IncompletePool`.

### Material decisions

- THE UNIT, BY MEASUREMENT. The plan names row bands, tiles through a tile-major intermediate, or tiles through a disjoint-rectangle writer, and requires the choice to be measured. All three were built. `soft2d-bench --scaling` was run three times (host idle, no guest) and the median of the three medians taken per cell. Tiles in place (`Rectangles`) are the fastest at every count from 4 to 64 on all five scenes; at 2 workers the intermediate leads on three scenes by at most 1.4 %; at 1 worker all three are the same (banded) frame. Bands cap at 3.6x-5.3x (8 units; 7 for image-resample), tiles in place reach 7.5x-15.9x. The table and the verdict are in `docs/PERF.md`. `Rectangles` is the default; `Bands` and `Tiles` stay selectable so the benchmark can repeat the comparison (bands are also what a one-lane frame is cut into).
- THE RECTANGLE UNIT HOLDS ITS 64 ROW PARTS INLINE (`[&mut [u8]; 64]` in `Access::Rect`). A separate table of parts would need a unit borrowing a vector of borrows for its own lifetime (not expressible without unsafe), and per-unit vectors would allocate per frame. Every `Unit` is therefore ~1.1 KiB; the tile-cut unit table is charged with the second lane (`table_bytes`), and clippy's `large_enum_variant` is allowed on `Access` with that reason.
- THE FRAME TABLES ONLY GROW (`finished`, `intermediate`), as the lanes do, so an earlier-prepared list is not refused with `Allocation` because a later prepare cut fewer units.
- THE DEMO ROWS. "The 2D demo rows" were taken to be the live-demo rows (`test2d-sw --frames=600 --phase-frames=60 --size=640x480` in a booted guest): re-measured at `--workers=1` and at the default with the vCPU count stated. The guest-suite rows (192x128, three ports, and the HiDPI pair) are measured by a guest test at whatever the demo's default is; they were annotated with the worker count they were taken at rather than re-measured at both counts (a `--workers=1` variant of that test does not exist, and making one is outside this milestone).
