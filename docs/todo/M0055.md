# M0055 - LiberFS: B+tree directories and dynamic inode allocation

Status: COMPLETE. **The XFS / btrfs / ZFS model**, and the structure everything later audits.

*Condensed 2026-08-08.*

Directory lookup had been a linear scan, and the inode table a fixed array sized at format time - so
the file count was capped and a sparsely used volume wasted the rest.

A B+tree fixes both: **directories indexed by name for O(log n) lookup**, scaling to millions of
entries, and **inodes allocated on demand** from a tree of their own, so a volume never runs out
while it has free space and an empty one wastes none.

The property that keeps it consistent with the rest: **a tree node is just another copy-on-write,
checksummed block** - so the trees inherit the crash atomicity and the integrity checking rather than
needing their own. `fsck` walks both trees and the free map.
