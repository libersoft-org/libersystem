# M0049 - LiberFS: directories and capacity scaling

Status: COMPLETE. *Condensed 2026-08-08.*

The first LiberFS was flat and fixed: one root directory, 32 inodes, 28 direct block pointers per
file (112 kB), one bitmap block (~128 MB of volume). This grew its dimensions and gave it a tree,
keeping the same small Unix-flavoured layout.

- **Nested directories** with path resolution walking segments from the root - and the typed
  `RelativePath` model at the filesystem boundary, a list of validated segments, so `..` and `/`
  injection has nowhere to arise.
- **A multi-block inode table** instead of one fixed block.
- **Indirect blocks**, single and double, lifting the 112 kB file cap.
- **A multi-block allocation bitmap**, lifting the volume cap.

*(Extents replaced the pointer arrays in M0054, and B+trees replaced the fixed inode table in M0055.)*
