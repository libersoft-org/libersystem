# P02M0105 - Locales: language, region, time zone, keyboard and formats

Status: PROPOSED, NOT STARTED. The system has no locale layer at all - not a partial one, none.
TimeService serves UTC and has nowhere to put an offset; the keyboard is a US table compiled
into the input driver; and the words "locale", "time zone" and "currency" appear nowhere in the
tree. This milestone adds the layer, and it is deliberately not "more keyboard layouts": the
missing thing is a policy that consumers can read, because every item people ask for here -
local time, a Czech keyboard, `1 234,56` instead of `1,234.56` - is a consumer of a policy that
does not exist.

P02M0006 already frames it correctly and could not act on it: "the layout is policy, the emitted
bytes are the canonical interface". The layout was understood as policy from the start; there
was simply nowhere to put policy. P02M0006's "(optional, later) Pluggable non-US layouts and
dead-key / compose handling" moves here, because it is one consumer of this layer rather than a
console feature.

## What other systems do, and which parts are worth copying

POSIX/glibc splits locale into categories - LC_CTYPE (character class and case), LC_COLLATE
(sorting), LC_TIME, LC_NUMERIC, LC_MONETARY, LC_MESSAGES, plus the GNU additions LC_PAPER,
LC_MEASUREMENT, LC_NAME, LC_ADDRESS, LC_TELEPHONE, LC_IDENTIFICATION. The split is right and is
copied here: mixed use is the normal case, not the exotic one - an English interface with Czech
dates and a Czech keyboard is what most people outside the US actually want, and a single
"language" field cannot express it.

Three things about the POSIX model are wrong for this system and are deliberately not copied.

First, the locale is AMBIENT. `setlocale` sets global mutable state and `printf`, `strtod`,
`strcoll` and friends silently consult it, which is why writing `1.5` to a config file and
reading it back fails on a German system - the same call formats and parses differently
depending on a global nobody passed. That is exactly the ambient authority this kernel exists
to refuse, and the same argument applies: a formatting function should be TOLD which locale to
use. Here the locale is a value that is passed, never a global that is consulted.

Second, the locale NAME is a string that must match a compiled artifact (`cs_CZ.UTF-8`), and
the `.UTF-8` suffix is a legacy of systems that had other encodings. This system is UTF-8
throughout (P02M0006h), so the encoding is not a variable. Language tags are BCP-47 (`cs-CZ`,
`en-GB`), which is what modern locale data is keyed by and what a browser or a phone would send.

Third, Linux has TWO keyboard layers - console keymaps (`loadkeys`, `/usr/share/keymaps`) and
XKB (`setxkbmap`, rules/model/layout/variant/options) - which do not share data and which
`localectl` papers over with `set-keymap` and `set-x11-keymap`. This system has one input path
already: `keys.rs` is shared by the virtio-input keyboard and the USB HID keyboard by design.
That is an advantage to preserve explicitly, not to rediscover: one keymap format, one loader,
both keyboards.

What IS worth taking: systemd's consolidation of scattered files behind small verbs
(`localectl`, `timedatectl`), because the value is in one obvious place to look rather than in
five files whose names must be memorised; and the CLDR/ICU data model, because per-locale
format patterns are a solved problem and inventing a worse table is not interesting work. BSD's
approach (`kbdcontrol`, `wsconsctl`, a thinner locale layer) is the reminder that most of
glibc's category surface is rarely used - LC_TELEPHONE and LC_NAME exist and essentially nobody
reads them.

## Where the data lives, and the one rule this cannot break

P01M0010 settled it: "a typed `ConfigNode` tree with an IDL schema (no textual `/etc` parsing; text
is only an editable representation)". JSON as the SOURCE OF TRUTH would reverse that decision,
so it is not proposed - but the instinct behind it is right and is served in full, because the
generated bindings already render every record as JSON, CBOR and CLI. So:

- the source of truth is typed records over the IDL, like every other contract here;
- `--json` on each tool exports exactly those records, and an import path accepts them, so
  editing a file and applying it is a first-class workflow;
- locale DATA (keymaps, time-zone rules, format patterns) is a staged artifact on the volume,
  generated at build time from upstream sources, versioned and digest-checked like every other
  staged artifact;
- locale SETTINGS (which language, which zone, which layout) are configuration and live in
  ConfigService, which already exists for exactly this.

Runtime parsing of text is the thing being avoided, not text itself. A keymap that a person
edits is a fine idea; a keymap the driver parses at boot is not.

## Scope

- [ ] A typed locale model in the IDL. A `locale` record carrying the BCP-47 tag and the
  category set POSIX got right: time (formats, first day of week, 12/24 hour), numbers (decimal
  separator, group separator, grouping rule), currency (symbol, code, position, decimal digits),
  measurement (metric/US), and the collation and case-mapping identity. Each category is
  separately settable, because mixed use is the normal case. No category is a string to be
  matched against a compiled blob; every one is a value a consumer can read and act on.
  Currency deserves one explicit note: the locale says how to FORMAT money, not which money the
  user holds. A Czech locale formatting euros is normal, and conflating the two is a common
  design error that makes the field useless the first time somebody travels.
- [ ] Decide the SCOPE of a locale before anything reads one: system, session or process. This
  is the first architectural question and the draft of this milestone missed it entirely.
  Linux answers it with a system default in `/etc/locale.conf` and per-user overrides in the
  environment, which works because the environment is ambient - and this system has no ambient
  state to inherit through. It does have sessions: SessionService mints one per VT, so two
  people on two terminals is already a shape the system supports, and a single global locale
  would make the second one wrong. The recommendation is a system default that a session may
  override and a process inherits from its session at launch, carried explicitly the way every
  other capability is. What must not happen is a locale a program can set for itself and change
  under its own caller.
- [ ] An invariant locale that always exists and never varies. POSIX calls it `C`, and the
  reason it exists is not tidiness: something has to format before any configuration is
  readable, and something has to format output that must not vary. Three consumers need it by
  construction - the boot chain before ConfigService is up, every machine-readable rendering
  (JSON and CBOR stay locale-independent, which is already stated below), and the log journal,
  whose records are UTC and invariant so two machines' logs can be compared. It is also the
  fallback when a requested locale is not staged, which turns a missing language into
  degraded output rather than a failed boot.
- [ ] Fallback chains, because locale data is never complete. `cs-CZ` falls back to `cs` and
  then to the invariant locale, per category, so a region that defines only its currency
  inherits the rest of its language rather than being rejected. CLDR works this way and the
  reason is practical: without it, every locale must define every field, which is how locale
  data sets become unmaintainable. A tool must be able to report which level answered a given
  field, or a wrong format is untraceable.
- [ ] Several layouts active at once, with a switching chord. Setting THE layout is not what
  people do - a Czech user types Czech prose and English commands and switches many times a
  minute, so the model is an ordered list plus a key that cycles it, not a single value. This
  is what `setxkbmap cz,us` plus `grp:alt_shift_toggle` does on Linux and what every desktop
  puts in its status bar. The chord belongs to the console rather than the driver, because it
  must work regardless of which keyboard produced the event, and the active layout must be
  visible somewhere or the user cannot tell why their keys changed.
- [ ] Plural rules, which are needed even with no translated messages. `1 file` / `2 files` is
  the English case and it is the easy one; Czech takes three forms (1, 2-4, 5+), Arabic six,
  Japanese one. Any tool that prints a count needs this, so it belongs to the locale layer and
  not to the message catalogue that is deferred below - `ls` reporting how many entries it
  found is not waiting on a translation workflow.
- [ ] Decide whether the hardware clock is UTC or local time. TimeService reads the RTC as UTC
  today and says so, which is correct and is also the assumption that breaks the moment this
  runs beside an operating system that writes local time to the same chip - the classic
  dual-boot defect, where the clock is wrong by the offset and right again twice a year.
  `timedatectl set-local-rtc` exists for exactly this. Either state the assumption as a
  requirement or make it a setting; leaving it implicit is the option that produces confusing
  bug reports.
- [ ] Confirm the font covers what a shipped locale needs. A locale is only as real as the
  glyphs behind it: the console font is Unscii 2.1 with 2,997 glyphs, which carries Latin
  Extended (so Czech, Polish and the rest of Central Europe render), Cyrillic and Greek - and
  cannot carry CJK, which needs thousands more. So the shipped language set is bounded by the
  font today, and adding a language means checking its script is drawn before its keymap and
  formats are staged. A locale whose text renders as replacement characters is worse than not
  offering it.
- [ ] A build-time locale data set, staged and digest-checked. Generated from upstream CLDR and
  IANA data into typed records, not shipped as upstream text to be parsed at runtime. Ship a
  named subset rather than everything - the full CLDR is tens of megabytes and this is an
  appliance - and make the subset a manifest decision so adding a language is a manifest change
  and not a code change.
- [ ] Time zones with real rules, not an offset. This is the item that sizes the milestone and
  it needs deciding before anything is built, so it is called out rather than discovered: a zone
  is not a number, it is a rule set with daylight transitions and historical changes. Compiling
  a bounded window of IANA transitions (say 1970 through 2100) into typed records at build time
  is the recommendation - it keeps the runtime parser-free, which is the same reason the staged
  images carry compiled artifacts rather than sources. A fixed-offset-only first slice is the
  cheap alternative and it is a trap worth naming: it works until March, when every timestamp in
  the country is wrong by an hour and the bug reports do not say "time zone".
- [ ] TimeService serves local time as well as UTC. UTC stays the wire and storage form - it is
  what logs, filesystems and the network carry, and nothing about that changes. What is added is
  a typed conversion the way `date` and the shell should have had it: given the active zone,
  render an instant. The zone is a capability-scoped setting, so changing it is governed like
  any other configuration change and not a variable any program can set for itself.
- [ ] Keyboard layouts as data, loaded into the one input path. A keymap becomes a staged typed
  artifact - unshifted, shifted, AltGr and dead-key tables - and `keys.rs` reads the active one
  instead of carrying a US table in its source. Both keyboards keep sharing it, which is the
  property Linux lost by growing two systems. Includes dead keys and compose, because that is
  what "non-US" means in practice: `ˇ` then `c` gives `č`, and without it a Czech layout is a
  keyboard that cannot type Czech.
- [ ] Runtime switching that reaches the driver. A layout change is useless if it needs a
  reboot, and the driver holds no ConfigService client today. This is the one piece of real
  plumbing in the milestone: settings change, and the components that care - the input driver,
  TimeService, the console - learn about it. Whether that is a small LocaleService that resolves
  settings plus data and pushes changes, or a subscription on ConfigService that each consumer
  takes, is the design decision to make first; a service is recommended, because resolving
  settings against staged data is real work that three consumers should not each repeat.
- [ ] Formatting as a library that takes the locale as an argument. Numbers, dates, times and
  money, rendered from the typed locale rather than from a global. No `setlocale` equivalent
  exists and none is added: a function that formats differently depending on state its caller
  did not pass is the defect this design exists to avoid. The machine-readable renderings the
  IDL already emits (JSON, CBOR) stay locale-INDEPENDENT by construction - a decimal point in
  JSON is a decimal point everywhere - and only human-facing text is localised.
- [ ] The tools, one verb each, in the shape this tree already uses for commands as binaries.
  `locale` shows and sets the active locale and its categories, `--json` exports and an import
  applies; `keymap` lists the staged layouts and switches the active one; `timezone` lists
  zones and sets the active one. Each is a governed executable with its own manifest and the
  single capability it needs, and none of them edits a file behind a service's back.
- [ ] Collation and case mapping for the shipped languages. Sorting `č` after `c` rather than
  after `z`, and case rules that are not the ASCII ones. Two traps to name because they are the
  classic ones: Turkish dotless `ı` means `toUpperCase` is locale-dependent, and German `ß`
  uppercases to `SS` and changes length - so case mapping cannot be a per-byte table and cannot
  assume the result is the same size as the input.
- Done when: a person can set language, region, time zone and keyboard layout on a running
  system through three small tools and have each take effect without a reboot; `date` shows
  local time with correct daylight handling; numbers and money render in the local convention
  while JSON and CBOR stay unchanged; a Czech keyboard types `č` through a dead key on both the
  virtio-input and USB keyboards; the active locale is a typed value passed to what needs it and
  is not readable as ambient state; adding a language is a manifest change; and tests green on
  all three architectures.
- Explicitly deferred, with reasons rather than as a list: translating system messages (a
  gettext-equivalent) is a separate and much larger milestone - it touches every string in every
  component and needs a catalogue format, extraction tooling and a translation workflow, and
  bundling it here would swallow everything else; input methods for Chinese, Japanese and Korean
  need candidate selection UI and a dictionary, which is an application concern rather than a
  locale one; bidirectional text and complex script shaping need a text engine the console does
  not have; and the full CLDR data set. Named because they are real parts of a complete locale
  layer and are being left out on purpose rather than overlooked: non-Gregorian calendars
  (Japanese era, Buddhist, Islamic, Hebrew), which CLDR supports and which need a calendar
  abstraction rather than a format string; alternative numbering systems and digit shapes
  (Arabic-Indic, Devanagari), which BCP-47 expresses as `-u-nu-arab`; the week data beyond the
  first day (which days are the weekend - Friday and Saturday in much of the Middle East - and
  the minimal-days rule that decides ISO week numbers); and the smaller CLDR patterns for
  percent, relative time ("2 hours ago") and list joining ("a, b and c" against "a, b a c").
  Each is a bounded addition once the layer exists, which is the point of naming them here.
  The POSIX categories nothing reads (LC_NAME, LC_ADDRESS, LC_TELEPHONE, LC_IDENTIFICATION)
  are not implemented merely because glibc has them - if something later needs one, it can be
  added with a consumer to justify it.
- Concept: P01M0010 (ConfigService and the typed-tree, no-text-as-truth rule this follows), P02M0005
  (TimeService, whose UTC stays the storage form), P02M0006/P02M0006h (the single shared input path
  and the UTF-8 console this builds on), P02M0009 (PermissionManager, which governs the tools and
  the settings they change), P02M0031 (commands as governed binaries), and the CLDR/IANA data the
  build compiles from.
