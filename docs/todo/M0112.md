# M0112 - Shell, tools, and renderer cleanup

Status: COMPLETE. The structural code-quality items in userspace.

*Condensed 2026-08-08.*

**The shell's line language moved out of the shell binary.** Trimming, `$NAME` and `${NAME}`
expansion, flag normalisation and `NAME=VALUE` detection now live in `proto::shell`, where they are
host-tested - the shell tree is pinned to a bare-metal target, so pure parsing had to live in a
host-buildable crate to be testable at all. That constraint is worth remembering: **anything in a
`no_std` binary that deserves a unit test has to be moved somewhere a host can build.**

The ~60-command prefix chain collapsed into two data-driven tables - governed tool launches and net
views, each a row of word plus shape - so adding a tool is one table row and the routing reads on one
screen. Only commands that do not fit a shape keep their own arm. `shell.rs` lost about 470 lines
with no behaviour change.

**A shared helper module for the tools crate**: `trim`, `split_args`, the decimal parsers,
`push_decimal` and the receive-then-parse-a-JsonMode handshake, each of which 13+ tools had
re-implemented.

**A glyph render cache, kept because it was measured.** A compile-time table maps every codepoint
below 256 to its glyph index, so the hot range is one array read instead of a binary search over 2997
sorted glyphs. The measurement is the test: a full 80x25 ASCII repaint performs **zero** binary-search
probes, proven by a counter, and a second assertion confirms the cache resolves identically to the
search it replaces.
