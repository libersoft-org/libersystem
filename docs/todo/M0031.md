# M0031 - Interrupt-driven I/O + virtio-input keyboard

Status: COMPLETE.

The three existing drivers were synchronous request-response and busy-polled the used ring. An
RX device - a keyboard - has nothing to poll for, so this is the driver-framework gap that had to be
closed before input could exist.

*Condensed 2026-08-08.*

- **A device's interrupt is an `Interrupt` capability** handed to its userspace driver, so waiting for
  hardware is the same operation as waiting for anything else.
- **The shared virtio transport gained an RX/event-queue mode**: post a batch of device-writable
  buffers and drain them on wake, rather than issuing a request and waiting for its answer.
- `virtio_input` brings the keyboard up and routes keystrokes into the interactive console.

One kernel change underneath: the device table records each virtio device's **IOAPIC GSI**, not its
legacy PIC line - `arch::pci` reads the Interrupt Pin alongside the Interrupt Line. The legacy line
is what a PC BIOS would have used, and it is not what the interrupt actually arrives on.
