# M0047 - Layered console: stream -> grid model -> renderer -> swappable display

Status: COMPLETE. The console had been one monolithic `Term` inside ConsoleService that both kept the
cell grid and drew pixels - and the kernel's own framebuffer console duplicated the whole thing.

*Condensed 2026-08-08 to the layering, which is the part that still matters.*

## The four layers

| layer | owns | knows about graphics |
|---|---|---|
| L1 stream | the byte stream in and out | no |
| L2 `Screen` | the cell grid, primary/alt buffers, dirty tracking | no |
| L3 renderer | glyphs, geometry, drawing | yes |
| `Surface` | the raw pixels behind a trait | yes, and swappable |

`Cell` stores a **logical** `Color`, not a pixel value, which is what makes L2 graphics-free and
therefore testable without a framebuffer. The `Surface` being a trait is what lets a different
display backend slot in underneath without touching anything above it.

**One console, no duplication:** the kernel boot console and ConsoleService render through the same
code rather than each having its own.

L2 also gained a per-row soft/hard wrap flag, which is the difference between reflowing a resized
terminal correctly and shredding it.

The L1 stream tap - routing the raw stream somewhere other than the local display - was added as the
foundation for ssh, telnet and scripted sessions.

## A defect worth remembering

`display_service_restores_the_console_surface` took the **whole suite** down rather than failing on
its own. A test that can do that is a test that owns something global, and finding out which is
always more expensive than the failure looks.
