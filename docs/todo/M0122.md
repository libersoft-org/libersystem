# M122 - Image viewer (the first graphical application)

Status: DONE (2026-07-25).

The first real consumer of M121, runnable from the console before any game
exists: `imgview vol://system/photo.png` takes the screen, shows the image, and a
keypress returns to the shell. Deliberately small - it proves the whole platform
loop (grant -> acquire -> decode -> present -> input -> release) end to end.

- [x] Dependency-free `no_std` image decoders: BMP (uncompressed + RLE) and PNG
      (a vendored inflate, the same zero-dependency discipline as the LZ4 coder).
      Decoders follow the fs-track hostile-input rules: every count, length,
      offset and dimension off the file is bounded before allocation or use - a
      malformed or malicious image errors cleanly, never panics or OOMs
      (host-tested with corrupt fixtures, like the filesystem crates).
- [x] The `imgview` tool: a governed ELF (`imgview <vol://...>`) with the manifest
      grants `volumes + display + input-keys`; it decodes the image, scales it
      to fit the screen (reusing the M121 scaler contract), presents it, and
      serves keys - Esc/q to quit, held arrows to pan after explicit zoom, and
      +/- to change the bounded zoom level. Exiting (or crashing) returns the
      console per the M121 guarantee.
- [x] Tests: host decoder suites over golden and corrupt fixtures; a kernel test
      that launches the staged `imgview` against a stand-in display service and
      asserts the acquire/present/release + key-quit sequence; a live QEMU pass
      showing an actual image on the virtio-gpu scanout (screenshot-verified).
- [x] Add explicit `+` and `-` zoom controls with bounded zoom levels and stable
      centering around the current viewport.
- [x] Make arrow-key panning continuous while a key is held, rather than moving
      only once per discrete key press; key release must stop movement promptly.
- [x] Make Esc exit `imgview` from both the serial/debug console and the
      framebuffer console reached over SPICE, with the same release-and-return
      behavior as `q`.
- [x] Keep fit-to-screen mode stable: arrow keys must not implicitly zoom or pan
      when the whole image already fits the fullscreen viewport. Panning is
      enabled only after explicit user zoom makes the image exceed a viewport
      boundary, and remains clamped to the enlarged image bounds.
- Done when: `imgview` opens a BMP and a PNG from any mounted volume fullscreen,
      zooms explicitly, pans smoothly only across enlarged off-screen content,
      exits through Esc/q on both console paths, survives hostile image files,
      and returns the console on every exit path - the first end-to-end proof a
      sandboxed graphical application can live on this platform, tests green.
- Concept: M121 (the platform layer this consumes), the powerbox/file-picker
      model (a viewer is the natural first picker client later), the NOTES
      "demo showing graphics capabilities" item this realizes.

Result: `imgview` is a governed console-launched ELF with exactly
`volumes + display + input-keys`; it content-sniffs BMP/PNG, decodes into bounded
B8G8R8X8 storage, fits to the acquired surface, switches oversized images to a
native crop on arrow input, and exits on Esc/q with explicit release. Atomic no_std
`bmp` supports indexed/direct Windows and OS/2 rows, bitfields and RLE4/RLE8;
`png` verifies chunks and zlib Adler-32, handles stored/fixed/dynamic DEFLATE,
all standard color types/bit depths, all five filters, transparency and Adam7.
Hostile sizes, tables, runs, chunks and output allocations are checked and capped.
Validation: 22/22 app-library host tests (12 decoder tests including staged golden
BMP/PNG and corrupt/bounded streams), focused x86 process/service/storage/display/input
51/51 with acquire -> nonblank present -> arrow-pan present -> q -> release -> exit,
fmt/gen/diff clean, and x86_64/aarch64/riscv64 userspace builds green. A fresh live
x86 QEMU/VNC pass opened both staged formats through StorageService; screenshots showed
the expected four 400x400 color quadrants on the virtio-gpu scanout, q restored the
console after each run, and the VM shut down cleanly.

Result (interaction completion): `imgview` now uses a bounded viewport model with
explicit 5%-step held zoom from 100% to 800%, center-preserving zoom transitions,
letterboxed fit rendering, and clamped panning only when the explicitly zoomed image
exceeds a framebuffer edge. HID arrow press/release state drives periodic held-key
repeat through `WAIT_PERIODIC`; fit-mode arrows do not alter the view. Foreground
launches enter tty raw mode for the duration of the viewer, so Esc from the serial/debug
console exits through stdin as well as Esc from the focused SPICE/input-key stream, and
raw mode is restored before surface release. The shared `pix` library owns the bounded
viewport blitter and host coverage. The dedicated `imgview` QEMU contract covers fit
arrow no-op, zoom, held-arrow repeat, HID Esc and raw-console Esc: x86_64, aarch64 and
riscv64 each pass 8/8 with smoke tests; pix host tests pass 9/9, keys host tests pass
3/3, the full userspace graph builds for all three architectures, and formatting,
diagnostics and test-tag validation are clean.

Result (terminal and keypad follow-up, 2026-07-25): main-keyboard and numeric-keypad
plus/minus usages (`0x2e`/`0x2d` and `0x57`/`0x56`) share the same held zoom state;
pressing and holding either side produces the same smooth periodic zoom, and release
stops it. The shell routes `imgview` as an interactive foreground tool, so it receives
the duplex controlling-terminal channel and can consume Esc/q from the serial console
as well as the focused SPICE key stream. QEMU's interactive runner now keeps the serial
port on direct `stdio` and its monitor on the unix socket; serial bytes carry a private
envelope through the kernel input channel so they remain deliverable while the
framebuffer is focused on the viewer. Focused x86_64 QEMU coverage remains 8/8,
including both keypad usages, zoom-in/out, held zoom/pan release and both Escape paths;
the console contract passes 11/11, the imgview contract passes 8/8 on aarch64 and
riscv64, the userspace graph builds for both architectures, and formatting, diagnostics
and test-tag validation are clean. A live regression found that the interactive shell
launcher had duplicated the controlling-terminal channel without `RIGHT_WAIT`; imgview's
first `wait_any` therefore returned access denied and immediately released its surface.
The interactive duplicate now carries send, receive, wait and transfer rights. A fresh
`just run spice` pass keeps imgview active after launch and serial `q` releases it back to
the shell prompt. Serial terminal arrows are parsed as bounded ANSI CSI sequences
(`ESC [ A/B/C/D`) and drive the same clamped viewport pan as focused HID arrows;
the sequence bytes are consumed by imgview rather than reaching the shell. A short
nonperiodic deadline resolves a standalone serial Esc as exit without confusing it
with an ANSI sequence prefix. The focused imgview contract covers raw Esc and raw
right-arrow input after explicit zoom.
