# P02M0181 - A platform power-state service

Status: OPEN. Service-contract landing and real-provider completion are separate stages below.
The milestone remains open until both stages and their verification are complete.

`system-power` currently exposes reboot and power-off only. This service owns typed power-source
and thermal state, observation and explicitly granted device controls. Machine shutdown authority
stays with SystemManager through the existing `liber:process@1/system-power` interface. Suspend,
device quiescence/wake, fan curves and vendor policy remain outside this milestone.

## P02M0181 - Dependency order and ownership

- [ ] Land the power vocabulary, provider contract, service and HID/ACPI-shaped fixture gate
  before requiring hardware drivers. That completed contract is sufficient for P02M0099's USB
  HID Power Device implementation to start; it need not wait for this milestone's final checkbox.
  The fixture gate must be labeled service/normalization coverage, never real HID or AML coverage.
- [ ] P02M0099 owns actual HID Power Device descriptor/report decoding through the common HID
  machinery, output-report construction and USB recovery. Its ACPI battery/AC/thermal item owns
  actual namespace method evaluation after the separately listed firmware-node identity and AML
  prerequisites there. The current `src/acpi` bounded table parser publishes no namespace devices.
  Do not implement AML, invent PCI identities for namespace devices, or absorb those prerequisites
  merely to populate this service's test data. Equivalent FDT providers can later use this contract.
- [ ] Retain a final integration item here: after those prerequisites and drivers land, run one
  actual HID producer and one actual ACPI producer through this service with live client assertions
  and retain their owning gates' evidence. This is still required for full completion. Service-first
  work is implementable now; full milestone closure is explicitly dependent on the open ACPI work.

## P02M0181 - Producer, read and control authority

- [ ] Define `liber:power@1` with separate state, operator and internal provider interfaces.
  State grants enumerate sources/thermal zones and subscribe to snapshots and changes. They
  contain no publication or control operations. Read access can be granted broadly by policy but
  still uses a capability; no device or provider connection is handed to a reader.
- [ ] Add a `power-source` provider kind, registry/wire support and generated bindings. Allocate
  unused append-only enum values from the current shared vocabulary. A provider may describe at
  most 16 local sources/zones. DeviceManager owns its binding/publication identity; a source is
  `(publication slot, publication generation, local source ID)`, with the binding generation
  retained for validation. USB collections reuse their controller-owned publication lifetime.
  ACPI providers wait for the real firmware-node identity prerequisite.
- [ ] A driver publishes a typed provider server endpoint through its authorized binding; it
  does not receive a global writable power-service connection. PowerService subscribes/connects
  using the kind-scoped client minted by `provider-catalogue-admin.open-consumer(kinds)` from
  P02M0180's shared infrastructure stage (not its completed Bluetooth stack), reads the provider's
  bounded initial source set and
  receives its updates. Source IDs are interpreted only within that connection. Registry capacity
  is not authorization: manager-side grants restrict the provider connection to PowerService.
  Reuse that stage's 32-client/subscription bound and combined-manifest capacity check; contribute
  this service's subscription requirement and test refusal at the shared cap.
- [ ] The provider stream starts with a coherent snapshot and monotonic provider revision, then
  typed source add/update/remove messages. The service rejects duplicate local IDs, mismatched
  generations, invalid values, regressions and updates for unregistered IDs. Provider disconnect,
  withdrawal, malformed protocol or snapshot timeout marks all its sources unavailable and emits
  removal; the previous healthy value never remains live. A reconnect starts from a fresh snapshot
  and service epoch. Service restart reconstructs state from the catalogue; old public streams
  close and clients reconnect/resynchronize rather than inheriting stale state.
- [ ] CONTROL is a separate platform-wide operator endpoint for discovered device controls,
  minted only for an explicitly authorized administrative component through the existing
  manifest/PermissionManager pattern. It authorizes `set-output(source, outlet, on/off)` and
  `schedule-output-off(source, delay-seconds)` / `cancel-output-off(source)` only when advertised by
  that provider. Cap delay at 86400 seconds and outstanding commands at one per provider. The
  operation turns off the UPS output, not the host OS. The source generation and outlet must match
  a current source; a reader cannot upgrade its connection or smuggle a control through a snapshot.
- [ ] The service validates operator authority, supported operation/range and live generation,
  then dispatches the typed command to the corresponding private provider endpoint. The later HID
  driver owns usage/output-report translation. Return unsupported for read-only ACPI/thermal
  sources. Limit each local control exchange to five seconds without blocking the service loop.
  Provider loss or a reply timeout after possible delivery returns typed indeterminate and is
  never automatically retried. Release the pending slot but keep that source's control state
  uncertain; reconcile with a fresh provider state query before admitting a conflicting action.
  Reconciliation also has a five-second deadline; continued silence leaves controls unavailable,
  while other providers and state clients remain serviceable. The existing system-power client
  remains the route for machine reboot/power-off;
  PowerService receives no such client. Suspend is neither a control verb nor a test shortcut.

## P02M0181 - Normalization contract

- [ ] Put the canonical schema and conversion/validation code in one host-testable pure leaf
  owned by this service. HID and ACPI producer adapters invoke that leaf before publishing, matching
  P02M0099's requirement to publish normalized state. Driver-specific parsing stays in the driver;
  the service checks canonical values rather than repeating source conversions. Test fixtures
  invoke the same source adapters/leaf on explicitly described decoded HID and ACPI data.
- [ ] Every measurement is a tagged value: known, unknown, unsupported or invalid. Never encode
  any of these as zero or the largest integer. Overflow, contradictory source data and malformed
  units are invalid with a bounded diagnostic reason, not clamped healthy values. An absent source
  is distinct from a present source with unknown measurements. Preserve source time as an optional
  field; the service supplies a monotonic receipt timestamp without claiming synchronized clocks.

| Canonical field | Representation and meaning |
| --- | --- |
| Source kind/status | AC, battery, UPS, load or thermal zone; presence and online state are independently known/unknown. Charge state is charging, discharging, idle or unknown; conflicting charge/discharge flags are invalid. |
| Remaining/full/design capacity | Tagged energy in microWh or charge in microAh, unsigned 64-bit. These are different physical quantities. Full and design are separate fields, and source-provided values may differ through wear. |
| State of charge | Basis points, 0..10000. Preserve a valid explicit percentage, or derive remaining/full only when both have the same quantity/unit and full is nonzero. Never use design capacity as full capacity. |
| Voltage/current/power | Voltage is unsigned microvolts; current and power are signed microamps/microwatts, positive into storage (charging) and negative out (discharging). A rate reported without usable direction remains unknown in signed form. |
| Runtime | Unsigned whole seconds or a tagged unavailable state; never infer runtime from percentage alone. |
| Load | Basis points when provided as a rated-load fraction; a source with only watts publishes power rather than inventing a denominator. |
| Temperature/trip points | Tagged absolute millidegrees Celsius or relative millidegree offset from the zone's critical reference, plus a typed passive/active/hot/critical threshold kind and bounded index. Compare only a common reference. These are observations, not fan or shutdown instructions. |
| Alarms | Bounded typed set of on-battery, low/critical capacity, overload, replace-battery, source-fault and over-temperature states, each known active/inactive or unknown, with reported/derived provenance. Unknown vendor usages remain with the HID driver's opaque bounded metadata and are not interpreted as new alarms. |

- [ ] Convert ACPI mWh/mAh capacities to the matching micro-unit by checked multiplication by
  1000; honor the ACPI unknown sentinel before arithmetic. `_BST` present rate is power when its
  power unit is energy and current when it is charge, not always current. Preserve the quantity
  instead of manufacturing the other. Scale ACPI mV to microvolts. For ACPI tenths-kelvin thermal
  readings with absent/zero `_RTV`, compute millidegrees Celsius as `raw * 100 - 273150`
  using checked signed arithmetic. Nonzero `_RTV` means relative values: preserve their signed
  offset/reference and scale by 100, without inventing an absolute Celsius temperature.
  ACPI field definitions are in the [power-source specification](https://uefi.org/specs/ACPI/6.6/10_Power_Source_and_Power_Meter_Devices.html)
  and [thermal-management specification](https://uefi.org/specs/ACPI/6.6/11_Thermal_Management.html).
- [ ] Interpret decoded HID logical values with their Unit/Unit Exponent and signedness in the
  shared conversion leaf, using checked integer/rational arithmetic and truncation toward zero
  only at the final target unit. Preserve the selected canonical unit's precision and invalid
  conversion status. Do not convert charge capacity into energy using instantaneous voltage;
  leave it as charge. Missing nominal voltage is not an error because no such conversion is
  required. Unknown unit encodings cannot become known measurements.
- [ ] Alarm normalization maps reported states and derives only explicitly defined comparisons:
  a known remaining capacity versus a same-quantity source-provided low/critical threshold, and
  a known temperature versus a known trip threshold. Use `<=` for low capacity and `>=` for high
  temperature. Unavailable inputs yield unknown; do not impose a new percentage threshold, invoke
  shutdown or invent hysteresis/power policy. Distinguish a source-reported alarm from a comparison.

## P02M0181 - Consistent bounded subscriptions and wiring

- [ ] A subscription returns one atomic snapshot at `(service epoch, revision)` followed by live
  changes after that revision. Implement the handoff within the service's serialized state loop;
  a separate enumerate call is informational and is not a prerequisite for correct subscription.
  Cap the complete service at 128 sources, eight providers and 16 public subscriptions. Snapshot
  construction and channel allocations are charged before accepting a subscriber.
- [ ] Queue at most 32 change records per subscriber. Coalesce ordinary measurements for a source
  to the latest state and emit at most once per 100 ms per source. Removal and alarm transitions
  are not coalesced away. Each emitted state carries the global revision; revisions may skip after
  coalescing, so a numerical gap alone does not mean overflow. If non-coalescible changes fill the
  queue or the receiver fails to drain within five seconds, close that subscription. Closure
  requires a new atomic snapshot and explicitly means continuity of event history was lost.
  Never block a producer or keep an unbounded removal/tombstone log for a slow reader.
- [ ] Define removal/update ordering for one publication, reject stale updates after removal and
  ensure a replacement generation appears as a distinct source. Enumeration is bounded and sorted
  deterministically. Source admission beyond the service cap returns/reports resource-exhausted
  instead of evicting another source invisibly. Clamp subscriber requests to these service limits.
- [ ] Register `power_service`, its typed protocol leaf and client exports in the service manifest,
  build/generation inputs and service resolver. Service bootstrap receives only its serve roots,
  scoped catalogue and required logging/time capabilities. PermissionManager gets the admin minting
  endpoint and delivers separate `power-state`/`power-control` grants per manifest policy. Define
  state as reconstructible and update every startup/test harness caller when adding roles. Source
  and subscriber disconnect release all charged queues and request slots.

## P02M0181 - Verification and completion

- [ ] Host-test the production normalization and subscription state machines without runtime
  dependencies. Include independently stated HID/ACPI expected values, energy versus charge,
  `0xFFFFFFFF`, relative versus absolute temperature, unknown direction, invalid sentinels/units,
  signed rates, overflow and unavailable
  conversion inputs. Test reported and derived alarm boundaries separately from any policy action.
  Keep tests outside production files and mutate lengths/unit exponents/status flags deterministically.
- [ ] Add test-only in-guest provider endpoints using the production provider wire. One feeds
  decoded HID-shaped UPS data and supports observable fake output controls; one feeds decoded
  ACPI-shaped battery/AC/thermal data. A fixture-control capability can change/remove each source
  and inspect commands, but is held only by the test runner and absent from shipping configuration.
  These are not claims that QEMU attaches a UPS or evaluates battery AML.
- [ ] The standalone `power-service` x86_64 guest gate builds the real service, canonical adapters,
  client and fixtures into a complete test image. Assert both sources enumerate with exact units,
  a source changes during subscription without being missed, a slow subscriber coalesces ordinary
  updates, overflow closes and resubscription recovers the latest snapshot, alarms are delivered
  or continuity explicitly breaks, and provider removal erases its live state. Assert a forged
  source ID/generation and unauthorized publisher/control request are denied. An operator command
  must reach only the specified fixture outlet; a read connection must never do so.
  Make an otherwise connected provider withhold its control reply: assert bounded indeterminate
  completion, no replay, no conflicting control before fresh reconciliation, and continued service
  to another provider. Exercise the same transitions in the production host state-machine tests.
- [ ] Register this gate and its image producer/prerequisites in `check.sh`, verify-model catalogue,
  guest-evidence profiles and the checked release-required exact set. Coverage includes the service,
  conversion leaf, protocol, manifest and provider/grant plumbing, so changes select the proof.
  Run model validation, generation/source-hygiene checks, focused host tests, the x86_64 gate and
  AArch64/RISC-V cross-builds with the implementation.
- [ ] After the separately owned drivers/prerequisites land, add real HID and ACPI provider evidence
  to the integration gates, including actual report/method changes reaching this service. Keep
  this item open if either producer remains a fixture. Do not silently redefine full completion
  when the service-first gate passes.

Done when the read/control/producer boundaries, normalized units, coherent bounded subscriptions
and service-first gates are implemented, and one actual HID plus one actual ACPI source have
published and been observed through this vocabulary. The service contract unblocks their driver
work earlier; no suspend or platform policy implementation is part of that contract.
