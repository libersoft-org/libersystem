# P02M0077 - Kernel hardening: SMAP/SMEP, frame allocator bounds, and channel backpressure

Status: COMPLETE. W^X landed in P02M0074; this is the rest of the low-cost hardening the same review
found in the kernel's memory and IPC plumbing.

*Condensed 2026-08-08.*

**SMEP and SMAP** are enabled on every core, CPUID-gated exactly like NXE - CPUID leaf 7 EBX bits 7
and 20 into CR4 bits 20 and 21, set on the BSP with the descriptor tables and in each AP's bring-up.
The kernel's legitimate user-buffer accesses are wrapped in `stac`/`clac`, and the no-KVM QEMU CPU
model gained `+smep,+smap` so the protection is actually exercised in tests. A kernel bug
dereferencing a user pointer now faults instead of succeeding quietly.

**Channel backpressure got a writable wake.** A sender blocked on a full queue used to yield-spin,
which burns a core to wait for something that will announce itself.

**`heap::grow` leaked its region when the frame pool ran dry mid-map** - the classic shape, where the
failure path of an allocation is the one path nothing exercises.

**A kernel-half page-table entry created after an address space exists was invisible to it.** Every
address space copies the shared high-half mappings at creation, so one added later reached only the
spaces created after it.

**The frame allocator's free-runs table is fixed at 1024 entries and overflow leaks frames.** Bounded
here rather than fixed, deliberately: the fix is a different data structure. That is now
[P02M0120](P02M0120.md).
