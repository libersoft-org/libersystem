# P02M0007 - Pointer/mouse plumbing (virtio-input pointer + InputService)

Status: COMPLETE (2026-06-25). **Deliberately only the plumbing** - no mouse-driven UI stack and no
touch, which belong to the desktop phase and were pulled no further forward than the shared input
transport justifies.

*Condensed 2026-08-08.*

**One `virtio_input` binary self-identifies as keyboard or pointer** from the device's config space,
reading the event-type bits for absolute or relative axes. A keyboard keeps feeding the console; a
pointer reads the axis maxima, normalises to a fixed range and folds motion into text-cell
coordinates.

Events are delivered as a typed `stream<pointer-event>` - and this was the first stream-only
interface in the tree, which **surfaced a latent generator bug**: a dispatch with no non-stream
operation generated unreachable code. It emits a trivial dispatch now.

The plumbing is proven with a test consumer rather than a UI, which is what keeps the milestone from
growing into the desktop phase.
