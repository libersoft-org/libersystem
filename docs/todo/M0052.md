# M0052 - LiberFS: copy-on-write (toward the modern FS)

Status: COMPLETE. The structural change that turns LiberFS into the base everything later is built on.

*Condensed 2026-08-08.*

Overwriting in place means a crash mid-write can leave a file half-old and half-new. Copy-on-write
writes changed data **and the metadata above it** - inode, then the table, then the superblock - to
newly allocated blocks, and frees the old ones only after the new root is committed.

**The commit is a single atomic pointer swap**: a versioned superblock makes a write all-or-nothing
across a crash, replacing the ordered-writes-plus-fsck model for the common path.

The groundwork clause is the one worth remembering: **keeping an old root reachable instead of
freeing it *is* a read-only snapshot.** The structure was laid here deliberately without building the
snapshot user interface, which came later - so snapshots cost almost nothing to add when they were
wanted.

The test that defines it: a simulated crash mid-write always leaves either the complete old file or
the complete new one, never a torn mix, and an old root still mounts read-only.
