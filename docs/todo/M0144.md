# M0144 - LiberFS: what a mount may still lose, and what a parser may not quietly repair

Status: COMPLETE. A second audit of LiberFS by the same party, after M0143 closed. Verified claim by
claim; all findings held.

The rule this round adds to M0143's: **a parser may not repair what it reads.** Clamping an
impossible value into a possible one destroys the evidence that the medium is damaged, and every
check downstream then agrees with a structure that was invented by the parser.

*Condensed 2026-08-08.*

- **One unreadable or unsupported superblock slot was ignored when the other one parsed.** Two slots
  exist so that one can be wrong; treating a failure as absence gives up the redundancy.
- **An ambiguous GPT probe still ended in formatting the whole disk.** M0143's rule applied to the
  filesystem and not to the partition table. *(M0146 finished this, and found that the negative case
  - no GPT signature at all - was still as dangerous as before.)*
- **The parser clamped impossible extent fields into possible ones** before anything could object.
- **`next_inode` was checked against one number instead of against the highest one in use.**
- **The superblock's label was validated when written and not when read.**
- **An unknown inode type kept the volume writable while its blocks went unmarked.** Fixed by
  treating an unknown type as file-shaped - which then opened a regression M0146 had to close, because
  the delete path was never taught the same rule.
- **`collect_dir_entries` still had no visited set**, so the live namespace was exponential even
  after `fsck`'s walk was fixed.
- **The free maps were still infallible allocations.**
- **The structural pass could overflow on a logical offset near the ceiling**, and **`dir.size += 1`
  could overflow on a damaged volume.**
- **`fsck` verified file metadata thoroughly and directory structure barely.**

## What this round cost the next one

Three of M0146's ten findings were regressions introduced here, each a consequence of a fix that was
itself correct: reserving an unknown-type inode's blocks without teaching DELETE to release them,
rewriting the directory walk iteratively and reversing the order it documents, and refusing an
allocation in the structural pass by returning silently. None had a test that would notice.
