# P02M0187 - A media import service

Status: OPEN. It closes when every item below is done, and not before.

A camera is an object source, not a block volume. Applications receive read-only import authority
for typed metadata and bounded sequential reads. The service owns PTP session/container validation,
pagination, identity and completion. P02M0099 owns USB Still Image binding, endpoint I/O and class
cancellation/reset. This plan supplies that driver's protocol consumer with one PTP parser.

The service is source-only: it has no destination storage capability and publishes no files.
Delete/capture, MTP/vendor extensions, automatic resume and a filesystem view stay unsupported.
This is the service destination authorized on 2026-09-21, with protocol validation performed once
at the service boundary instead of duplicated in the USB transport.

## P02M0187 - Interfaces and authority

- [x] Add `src/idl/import.lsidl`, package `liber:import@1`, with device/storage enumeration,
  `open-enumeration`, cursor `next/close`, object `open-read` and transfer `read/status/cancel`.
  Cursors/transfers are separate capabilities owned by the granting client context. Bound every
  list, string and byte field. Ordinary clients have no raw command, catalogue/backend, destination
  writer, delete or capture operation. Reject unknown opcodes and malformed requests. A future
  mutation capability is outside this milestone and does not block the useful read-only path.
- [x] Define a private versioned `ptp-transport` contract: attach, send one command container of
  at most 32 bytes, pull at most 4096 bulk-IN bytes, receive event chunks of at most 32 bytes with
  at most 8 buffered events per provider, cancel the active
  transaction, and recover/reset. Its sole production consumer is `media_import_service`. The
  driver owns descriptors, USB completion, short packets/stalls, class cancellation/reset and
  withdrawal. It bounds transport frames before copying. The service alone validates PTP container
  lengths/types/codes, transaction IDs, sessions, operation allowlist and data/response sequencing;
  all incoming bytes remain untrusted. No PTP dataset parser is duplicated in the USB driver.
  Command acceptance is all-or-none; an uncertain send invalidates the session rather than
  replaying it. A temporarily empty pull returns `again`, never an implicit final response. Event
  overflow invalidates the content epoch so dropped change notifications cannot preserve stale
  object authority.
- [x] Add `ptp-transport` consistently to provider kinds in `device.lsidl`, `driver-protocol`,
  manifest schema and DeviceManager conversions, allocating an unused value alongside the other
  new kinds. Use catalogue `subscribe/open` and live withdrawal, full binding/provider identity
  and an attachment epoch. Admit one consumer and one active transaction per device. Refuse
  unsupported versions; invalidate the epoch on removal/reset/failed recovery before another ask.
- [x] Support the standard read-only subset: GetDeviceInfo, OpenSession, CloseSession,
  GetStorageIDs, GetStorageInfo, GetObjectHandles, GetObjectInfo and GetObject. Require these
  capabilities before advertising a usable device, returning typed `unsupported` if unavailable.
  Incrementally deliver GetObject bytes; no GetPartialObject, native enumeration paging, random
  seek or vendor fallback is required. Private session/recovery controls do not grant mutation of
  stored objects. The [named PTP reference](https://raw.githubusercontent.com/gphoto/libgphoto2/master/camlibs/ptp2/ptp.c)
  confirms GetObjectHandles uses storage/format/association selectors, not page offsets, and
  GetPartialObject concerns bytes. That LGPL reference is observational only; implement independent
  protocol code under the repository's licensing rule.

## P02M0187 - Bounded enumeration, metadata and identities

- [x] Parse upstream containers incrementally before allocating declared lengths. GetObjectHandles
  admits at most 65,536 handles per enumeration (256 kB of IDs), covering the motivating 40,000
  objects. Check count, arithmetic, container length and final response before exposing a snapshot.
  Return an explicit enumeration-limit result above that bound, never truncation or arbitrary
  allocation. Keep only bounded IDs and fetch metadata lazily by page. Cap GetStorageIDs at 32
  storages; cap device/storage-info datasets at 8192 bytes and ObjectInfo at 4096 bytes.
- [x] Return at most 2 metadata records and 8192 encoded bytes per page including the envelope.
  Each record carries scoped identity, numeric format with known/unknown interpretation, optional
  size/capture time, parent identity or no-parent and bounded filename. Preserve the bounded
  original ObjectInfo dataset as opaque bytes with an unparsed marker, alongside typed fields.
  Both representations share a 4096-byte encoded record budget; refuse records that do not fit,
  rather than truncate unknown fields. Decode strings/timestamps fallibly, preserving unknown
  typed values and original bytes where interpretation fails. No image decoding belongs here.
- [x] Advertise limits of 8 providers, 16 granted clients, 8 cursors and 8 transfers globally,
  at most one cursor and one transfer per client and per provider, and a 4 MB aggregate data budget.
  Snapshots consume at most 2 MB; pages, metadata, command/data/event buffers and pending replies
  are charged before allocation to the remainder. Each active device retains at most one 4096-byte
  object chunk and one bounded pending reply. Hard admission limits return `exhausted`; `again`
  means another same-device transaction is completing, never a hard size limit. Size IPC buffers
  for complete generated frame maxima. Other devices/clients/heartbeats remain serviceable.
- [x] Obtain a complete bounded handle snapshot in one upstream transaction, then release that
  transaction before client pagination. A stopped cursor holds only bounded snapshot state and
  expires after 60 seconds of inactivity. Each page issues at most two serialized metadata reads.
  A stalled transfer stops bulk reads rather than queueing more object data. Cancel after 30
  seconds without device progress or client demand. Cancellation, over-limit or malformed input
  allows at most 2 seconds for cancellation/session recovery, then makes the provider unavailable
  if synchronization cannot be restored. Never drain an attacker-declared huge response forever.
  Session recovery advances its epoch; other devices remain usable.
- [x] Scope device/storage/object/parent identity to full provider identity, PTP session and content
  epoch; cursors/transfers also carry their owning capability context. Reject cross-device,
  cross-client and stale references before dispatch. The snapshot covers the handle list only:
  metadata is current when fetched, and the device is not an immutable filesystem. Reported
  object/storage changes or invalidated metadata advance content epoch and stale old objects/
  cursors. A missing object is stale, not empty success. Revalidate metadata before reading and
  reject changes from the returned identity. Do not promise to detect changes the device neither
  reports nor exposes through distinguishable metadata. Withdrawal, reset, restart or session loss
  invalidates old capabilities; reconnect never resumes using an old numeric handle alone.

## P02M0187 - Completion and destination ownership

- [x] Transfers move through opening, reading and terminal states. `read` returns a chunk with
  exact offset/count or a typed terminal record, never EOF inferred from a short/empty chunk.
  Terminal status remains queryable until closure and carries complete/partial, delivered count
  and removed/timed-out/cancelled/corrupt/stale/device-error cause. Complete requires the expected
  byte count, valid GetObject data framing and the successful matching final PTP response.
  Accept only ordinary representable container sizes, at most `u32::MAX - 12` object bytes;
  sentinel/unknown or contradictory lengths are unsupported/corrupt, not allocation requests.
  A zero-byte object still requires the validated final response.
- [x] Cancellation, owner exit or lost consumer releases its buffers and cancels outstanding work
  within the recovery deadline. Failure after bytes is partial; failure before bytes is also
  non-complete with count zero. Service/channel loss without a terminal result is incomplete/
  unknown to the client. There is no automatic resume, rollback or fabricated final response.
- [x] State the consumer obligation in client documentation: publish a normal completed destination
  only after complete terminal status. A storage consumer may use `volume.open-writer`, commit
  only on completion and abort on partial/error/closure within that writer's existing size cap.
  Larger imports need a separately specified staging consumer, not an unbounded promise here.
  The guest probe uses a bounded transactional destination and proves mid-transfer failure leaves
  its previous contents unchanged. The import service itself receives no storage grant.
