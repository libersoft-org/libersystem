# P02M0111 - Streams as pending operations, and a harness that can move the clock

Status: COMPLETE.

Three separate reviews found that one client can stop StorageService, and three times the answer was
a deadline. **A deadline bounds the harm; it does not remove it.** The service is still unavailable
while it waits, because the receive runs synchronously inside the serve loop.

*Condensed 2026-08-08.*

## The harness can move the guest clock

A kernel test could not reach a deadline without waiting for it in real time, so the deadlines had no
tests. With the clock movable, two became testable: an idle stream hitting its deadline, and a list
consumer that never reads.

A bound nothing can reach is a bound nobody has checked.

## Streams became pending operations

`OP_WRITE_STREAM` creates a pending write and **returns**; the serve loop goes back to its other
clients and picks the stream up when there is something to do. The outbound direction works the same
way, so a listing whose consumer has stopped reading no longer holds the service.

The test that matters is not that a stream works - it is that **a second client is served while a
stream is pending**.

Once streams cannot block the loop, the deadlines stop being the defence and become what they should
have been: a bound on how long a stream may sit idle before it is abandoned.
