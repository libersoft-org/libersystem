# P01M0006 - DeviceManager + virtio transport

Status: COMPLETE.

DeviceManager enumerates the devices and launches the matching driver for each, **handing it only
that device's capabilities** - which is the whole point: a driver is an ordinary process, and its
authority is exactly one device.

*Condensed 2026-08-08.*

The kernel scans PCI config space, identifies virtio devices by vendor id, and parses each one's
virtio PCI capabilities to resolve its MMIO BAR and the offsets of its common, notify, ISR and device
structures. A device table built at boot is exposed through three syscalls - count, info, and an
acquire that mints a `DeviceMemory` capability for one device's BAR - plus the DMA buffer mapping a
driver needs to program the device with a physical address.

One kernel rule had to be relaxed to get here: the init package could be mapped only once, and both
ServiceManager and DeviceManager need it. The rule became address-space-aware rather than global.

The shared virtio transport - discovery and virtqueues - is one crate all the drivers use, so a
transport fix reaches every device rather than one.
