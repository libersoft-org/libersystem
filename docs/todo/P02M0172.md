# P02M0172 - DMA isolation policy is registry data, not a kernel device-type list

Status: PLANNED. DMA POLICY PREREQUISITE. QEMU SECURITY FOLLOW-UP.

## Goal

Make every staged driver declare whether it performs no DMA, requires translated DMA, or is an
explicitly trusted untranslated exception, and make kernel admission enforce that declaration from
the trusted generated registry.

P02M0153 defined the policy vocabulary, but the current production decision is still a hard-coded
kernel `IOMMU_REQUIRED_TYPES` list containing only virtio-net. Every other device type silently
defaults to `TrustedUntranslated`. That contradicts the registry-policy claim and blocks an honest
cross-architecture enforcing rollout: adding a driver should not require another kernel name/type
arm before it can be protected.

This milestone extracts and closes the open "declared DMA policy per driver" prerequisite in
P02M0099. It implements no IOMMU backend.

## Work

- [ ] **M1 - the manifest has a required closed DMA-policy field.** Every `role = "driver"` row
  declares exactly one of `none`, `iommu-required`, or `trusted-untranslated`; non-driver rows cannot
  declare it, unknown values are rejected, and absence is rejected rather than defaulted. Migrate
  every current driver row deliberately. `none` is an enforceable non-bus-mastering claim mode: the
  driver may receive its validated MMIO and interrupt resources, but PCI bus mastering remains off
  and the binding cannot mint a DMA buffer/address or activate another DMA path. It is not merely a
  statement that the current driver happens not to ask.

- [ ] **M2 - one generated identity carries selection and policy.** Give each generated registry
  entry a stable ID and keep its policy attached to that ID. DeviceManager passes the ID of the exact
  priority/fallback candidate it is attempting, not a free policy scalar. Kernel admission validates
  that privileged handoff against a table generated from the same manifest and the concrete device,
  then stamps entry ID, policy and the newly minted binding generation on the claim. A fallback
  candidate therefore carries its own decision rather than inheriting the first matching row's.
  Propagate one trusted boot-profile value, fixed before driver admission, which distinguishes
  `enforcing-required` from the explicit `no-iommu` degraded profile. The public run/image path
  produces that value and the matching QEMU topology together; the direct profiles trust the named
  harness as part of their TCB, while an authenticated-loader profile binds it into authenticated
  boot metadata. Controller absence alone is never authority to degrade.

- [ ] **M3 - admission has no permissive fallback.** Remove `IOMMU_REQUIRED_TYPES` and the implicit
  default to `TrustedUntranslated`. On an `enforcing-required` profile, both DMA-capable policies are
  translated and either refuses if enforcement is absent or failed. On the explicit trusted
  `no-iommu` profile, `iommu-required` refuses and only `trusted-untranslated` may enter the existing
  loud degraded inventory; an unexpected controller/profile mismatch is refused rather than silently
  reclassified. A `none` claim uses M1's non-mastering path on either profile and refuses every DMA
  activation. An unknown, missing, stale-generation, entry/device mismatch or profile mismatch
  refuses rather than choosing the least restrictive answer.

- [ ] **M4 - policy changes select and rebuild every consumer.** Ensure the shared manifest is an
  input to the generated userspace registry, kernel admission data, image metadata and verification
  model, and bind the profile value into the direct or loader/kernel boot contract as appropriate.
  A one-line policy or profile change cannot leave a kernel from the old decision beside
  DeviceManager or an image from the new one.

- [ ] **M5 - hostile policy fixtures prove the boundary.** Host tests reject missing/unknown fields,
  fields on services, existing same-priority ambiguous overlaps and stale/mismatched entry IDs. A
  positive different-priority overlap with different policies proves that an intentional fallback
  is valid and that each attempted entry reaches the kernel with its own policy and generation.
  Kernel/guest tests prove the full M3 profile/policy matrix, including MMIO/IRQ but no BME/DMA for
  `none`; fail mutations that restore the permissive default or infer degraded authority merely from
  controller absence; and assert that the current image has no staged driver without an explicit
  classification.

## Dependencies

- P02M0153 owns `DmaAddress`, IOMMU backend admission and the three policy outcomes.
- P02M0161-P02M0166 own registry selection, binding generations, rollback, stop and reporting.
- P02M0099 remains the driver roadmap; future DMA-capable items consume this mechanism rather than
  adding another policy arm.

## Definition of done

- Every staged driver has one validated DMA policy from the manifest.
- Kernel admission enforces the exact attempted entry's policy and profile, including a usable but
  non-bus-mastering `none` claim, with no device-type list or silent trusted-untranslated default.
- Policy, binding identity/generation, operator reporting and rebuild selection cannot drift.

## What this milestone refuses

- A new IOMMU backend, endpoint migration, native hardware or a physical-machine claim.
- Treating every driver as malicious on a profile with no translating hardware; explicit degraded
  exceptions remain possible and visible.
- A free-form policy language. Three closed outcomes are the complete current admission contract.
