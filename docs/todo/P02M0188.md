# P02M0188 - A trusted administrative path for high-risk operations

Status: OPEN. It closes when every item below is done, and not before.

**THE OPERATION THIS IS FOR CANNOT BE UNDONE.** P02M0099's DFU item asks for firmware download and
manifestation to be exposed "only through a dedicated high-risk capability and explicit trusted UI/
admin policy", and names that path as unowned. Writing firmware to a device is not a privileged
operation in the ordinary sense - it is one where a mistake or a lie leaves hardware that no longer
boots, and where "the user clicked yes" has to mean the user, not a window that said so.

**SO THE MILESTONE IS THE PATH AND NOT THE OPERATION.** What is missing is the mechanism by which
this system can say: a human at this machine, and not a process, authorised THIS action on THIS
target. Every high-risk operation this system ever grows - firmware, disk erasure, key export -
wants the same mechanism, and each one inventing its own is how a system ends up with several.

**AND IT EXISTS BECAUSE THE OWNER SAID SO (2026-09-21)**, answering P02M0099's question about the
nine unowned destinations.

## The shape

- [ ] A typed `liber:admin@1` interface: a request names the ACTION and the TARGET in terms a
  person can read, and the answer is a single-use capability scoped to exactly that pair. Single-use
  and scoped, because a reusable one is a standing authority and a broad one authorises what nobody
  looked at.
- [ ] THE CONFIRMATION IS NOT THE REQUESTER'S TO DRAW. A process that renders its own confirmation
  dialogue is a process that can render anything; the path this milestone owns is one the requester
  cannot paint over, and that constraint is what makes it TRUSTED rather than merely typed.
- [ ] Every grant recorded: what was asked, against what target, when, and what answered. An
  irreversible action with no record is one nobody can investigate afterwards.
- [ ] A DECLINE IS A NORMAL OUTCOME AND NOT AN ERROR, and the requester is told so in a way it
  cannot distinguish from a person simply saying no - because a requester that can tell "declined"
  from "no path available" can pick the second and retry.
- [ ] Target identity validated against what the target reports about itself, so an image aimed at
  one device cannot be confirmed against another.
- [ ] Host tests over the request and grant state machine, including expiry, reuse and mismatched
  targets.
- [ ] A guest gate over the observable effect, registered in the verification model in the same
  change.

## Definition of done

Done when a high-risk operation can only proceed with a single-use capability scoped to one action
and one target; when the confirmation path cannot be drawn by the requester; when every grant and
every decline is recorded; when reuse, expiry and target mismatch are host-tested; and when the
guest gate and its model entry land with the code.

## What it unblocks

P02M0099's **USB Device Firmware Upgrade (DFU)**, and it is the mechanism any later high-risk
operation in this system should reach for rather than inventing a second one.
