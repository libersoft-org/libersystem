# P02M0188 - A trusted administrative path for high-risk operations

Status: COMPLETE (2026-10-14) for phase 2; NOT TESTED ON REAL HARDWARE - not part of phase 2, which is QEMU and what
can be tested on it (the owner, 2026-10-13). It closed when every item below was done, and not before.

P02M0099's DFU requirement needs a dedicated high-risk capability and explicit trusted
confirmation before firmware mutation. This milestone owns that authorization path. USB
binding, DFU transfers, manifestation, signed-image checks and recovery remain in P02M0099.
The owner requested this missing destination on 2026-09-21.

The first implementation uses one protected confirmation surface and one active request.
It does not require a compositor, an extensible policy language, a general key store or
secret entry. In particular, P02M0182 cannot use an action confirmation as a PIN-entry
interface. Complete the generic path against a bounded executor fixture before implementing
the DFU adapter; that fixture does not establish USB firmware-update completion.

## P02M0188 - Contracts and authoritative operation identity

- [x] Add `src/idl/admin.lsidl` for `liber:admin@1`, its generated protocol/client crate and
  manifest-owned `admin_service`. Ordinary `admin-request` clients can request, cancel
  their request and receive `Declined` or a grant channel. They cannot register executors,
  report a human answer, inspect other requests or obtain privileged display/input,
  journal or executor endpoints. PermissionManager mints a fresh request connection per
  authorized launch, attaching trusted component identity and binding the exact launching
  task internally; requester-supplied names or PIDs are never attribution. The initial
  operator policy permits requesting firmware download on registered DFU targets, always
  requiring this confirmation; ordinary tools get no request grant by default. Only the
  test image permits the probe action. The
  broker's factory records this action/target scope and preparation enforces it. Allocate
  new capability values without renumbering or colliding with the other destination-service additions.
- [x] Give the private request factory a `@rights(wait) handle<task>` argument using
  `liber:process@1.task` and its existing kernel Process type guard. Extend PermissionManager's
  `grant_for_task` to duplicate the exact task returned by the prepared launch with only
  `WAIT | TRANSFER`, and transfer that observer with trusted identity/scope before releasing
  the launch. The factory retains it with the request connection; clients cannot supply
  or replace it. No `MANAGE`, `DUPLICATE`, process lookup or PID-based authentication is
  needed. Failure to bind or register observation grants no request endpoint and follows
  existing failed-launch cleanup. Close the observer on factory rejection or connection
  teardown after invalidating its requests/grants; retain it across individual request
  declines while that connection remains usable.
- [x] Define initial actions `FirmwareDownload` and test-image-only `ProbeWrite`; reject
  unknown actions. Separate readable labels from the canonical operation descriptor:
  version, action, executor identity/epoch, live target instance/generation, parameters,
  payload length and SHA-256 digest. Bound labels to 128 UTF-8 bytes and the descriptor
  to 4096 bytes; escape control characters and render through the service's own template.
  Neither labels nor VID/PID/root port constitute target identity.
- [x] Define private executor operations `prepare`, `revalidate`, `execute` and `cancel`.
  ServiceManager wires registered executors to AdminService; a client cannot register its
  own channel as an executor. Preparation checks the caller's target scope and resolves
  its selector through that backend. The backend freezes the operation and returns a
  prepared-operation handle plus canonical descriptor. Copy payloads into bounded,
  backend-owned storage or pin an immutable version; a read-only handle with another
  writable alias is insufficient. Each action declares its payload/transfer/deadline
  bounds; unsupported bounds decline. The broker holds the preparation and digest, not
  a second image copy. The initial firmware adapter slot returns decline until installed.
- [x] Require the DFU adapter in P02M0099 to supply live USB binding/interface identity and
  attachment generation, including full downstream port path where needed. Query target
  compatibility through that same binding, validate signed image metadata where available,
  and bind the exact image and all mutation parameters before confirmation. `usb.list` is
  not this authority. Disconnect, replacement or reset that loses identity invalidates
  preparation. Revalidate immediately before the effect and serialize its start with
  withdrawal; never reselect a target by display name. Unverifiable targets decline.

  installation and fresh presentation before input can authorize; restore the prior live
  surface on exit. Display reset, lost scanout or revoked session cancels the request.

## P02M0188 - Single use and enforcement

- [x] Keep authoritative broker states `Prepared -> AwaitingAttention -> AwaitingDecision
  -> Granted -> Consumed -> Completed/Failed/OutcomeUnknown`; decline, expiry and cancellation
  are terminal before consumption. Use the kernel monotonic clock and runtime conversion
  for deadlines. Grants expire 30 seconds after confirmation and bind the immutable
  preparation, original launch observer and requester connection. Never restore executable
  grants from disk.
- [x] Watch each bound task with the existing kernel `wait`/`wait_any` mechanism alongside
  request/grant channels and asynchronous replies, including during preparation and every
  journal wait. Termination invalidates that launch's connection, pending request and
  unconsumed grant independently of channel peer lifetime; restore the prompt/focus and
  cancel preparation. An invalid observer or inability to observe also fails closed.
  Recheck task readiness before issuing a grant or admitting redemption, and after each
  journal acknowledgment before issuing authority or dispatching. Process termination
  must win over queued approval/redemption/reply work when both are ready; check readiness
  explicitly rather than rely on wait-array ordering. Nonblocking `wait` checks use an
  already-reached nonzero deadline; zero means an unbounded wait. Correlate asynchronous
  completions with the broker epoch/request sequence and retain terminal cancellation so a late
  acknowledgment cannot revive it. If consumption committed while the owner died, keep
  that grant spent, record that no dispatch occurred, and never retry it.
- [x] Return a fresh channel served by that grant record with only necessary IPC/transfer
  rights and no `DUPLICATE`. `execute()` supplies no replacement parameters. Serialize
  execute/cancel/expiry/owner loss: validate record, original request context, live owner
  and deadline, commit consumption, and leave `Granted` before dispatching once to the
  private executor. Revalidate owner liveness, request connection, cancellation and deadline
  after storage acknowledgment and immediately before dispatch. This final check is the
  broker's execution-admission boundary; termination observed before it prevents dispatch.
  Death concurrent with or after that final check follows the consumed/no-retry and
  post-start cancellation limits below; observation cannot make process exit and IPC atomic.
  Nonduplicability is defense in depth; the server transition makes repeated or concurrent
  requests single-use. Forged channels or numeric tokens
  cannot address a broker grant or invoke its private executor. Transfer delegates exactly
  that operation; it does not authenticate a holder's PID or change journal attribution.
  The original launching task and request connection must both remain live after delegation;
  transferring either endpoint never rebinds ownership to the recipient.
- [x] The mutating endpoint is the executor's private broker connection. No public mutation
  operation accepts a client boolean or bare descriptor as authority. The executor binds
  execution to its own prepared object and epoch, rejects cancelled, mismatched or already
  started preparations, and rechecks expiry/target under its start guard before at most
  one attempt. Read/discovery handles cannot invoke it. Keep this generic adapter seam
  here and real DFU execution in P02M0099.
- [x] Broker/executor disconnect or restart invalidates unused grants. Never automatically
  retry consumed operations, including on lost replies: return `OutcomeUnknown` and retain
  consumed state while live. Read restart journals for investigation, never to recreate
  authority. Expiry limits admission to an effect, not unsafe mid-flash interruption.
  Executors declare bounded operation deadlines and honest failure/unknown outcomes;
  post-start cancellation cannot promise rollback. The probe can prove exactly one
  successful effect; physical hardware has an at-most-one-attempt guarantee.

## P02M0188 - Decision records and failure behavior

- [x] Own a small structured journal in AdminService using a bootstrap-minted writable
  `volume-admin.open-directory` grant for `vol://system/admin-audit` on disk-backed LiberFS.
  Use bounded transactional writer commits and propagate their errors. `writer.flush`
  only reports staged length; LogService `emit` ignores persistence failure and the
  PermissionManager audit is in memory, so neither suffices. Additional ordinary log
  diagnostics are optional. Expose an operator-only read view, no requester journal
  capability. This is not a tamper-proof archive against an administrator who already has
  unrestricted system-volume write authority; no new general logging service is required.
- [x] Record broker epoch, request/sequence and launch correlation, trusted requester,
  canonical action/target/parameters digest, event (`requested`, `granted`, `declined`,
  `consumed`, outcome), internal reason, monotonic time and optional TimeService UTC with
  provenance.
  RTC/SNTP wall time can move and never sets expiry. Exclude payload bytes and secrets.
  Reserve record space at admission, retain at most 1024 records per segment and four
  segments, and rotate only completed segments. Bound each complete encoded record to
  8192 bytes, including framing/identity/descriptor, and each segment to 8 MB including
  its header; stop at whichever count/byte cap comes first. This fits the existing 64 MB
  transactional writer cap. Reject an oversized request before granting; its diagnostic
  record contains a bounded refusal reason instead of oversized input. Pin active records;
  decline if they prevent rotation. Expose the oldest retained sequence to readers.
- [x] Commit request and approval before issuing a grant, and consumption before effect
  dispatch. Failure issues no authority/effect. Record every decline, including unavailable
  path, before responding and attempt the same persistent backend. A preallocated
  256-record emergency ring retains storage-failure records with an eviction count and
  oldest sequence, replaying retained entries when storage returns. All decisions are
  recorded within this bounded retention policy. Committed grants/consumptions survive
  restart/reboot within retention; outage declines can be lost on crash or ring eviction
  and must never be described as durable. These failures still return normal `Declined`.
  If recording the outcome fails after an effect, leave a durable consumed record with
  unknown outcome and admit no further approvals until storage recovers.
