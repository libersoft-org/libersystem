# M0070 - Journal persistence (LogService on the volume)

Status: COMPLETE. The journal lived in memory and died with the machine.

*Condensed 2026-08-08.*

LogService gained a volume client - delivered **late**, on its control channel the moment
StorageService mounts, because LogService starts first. Records are appended to a per-boot file as
**structured records, never rendered text**, so a later reader is not parsing prose.

**Records are never written per emit.** Appends are batched, flushed on a timer and immediately on
severity at or above error - the one class where losing the tail matters more than the write cost.

The whole capped sequence is rewritten per flush, because the volume's write is create-or-overwrite
and the per-boot cap keeps it small. The consequence is worth stating: **a torn write can lose at
most the tail batch, never the file's framing.**

`log --boot <n>` reads a previous boot's journal. Rotation caps the size per boot and the count
across boots, oldest deleted, with both caps as config keys defaulting from the volume's size.
