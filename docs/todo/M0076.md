# M0076 - LiberFS: code quality

Status: COMPLETE. Crate-internal cleanups with no behaviour change intended.

*Condensed 2026-08-08.*

- **The `begin()` / `finish()` transaction discipline was hand-copied by every mutating API** - eight
  sites, each able to forget. A `mutate` wrapper enforces it, and it is where the read-only gate
  lives, so building the wrapper *was* the enforcement fix. All ten mutating APIs run through it.
- **Manual byte offsets** in the inode parser, the superblock and the snapshot serializer became named
  constants. The extent overflow chain and the snapshot chain turned out to be **the same layout
  written from two sets of magic numbers**; they share a header now, so the parsers and serializers
  cannot drift.
- **`FsError::Invalid` meant too many things** - bad path, wrong inode kind, non-empty directory,
  duplicate snapshot name. Split into `BadName`, `IsDir`, `NotDir`, `NotEmpty` and `Exists`, with
  `Invalid` left for genuinely invalid operations. The service can give a real message now.
- `read_file` duplicated `read_at`; both are thin wrappers over one range read, so `read_file` costs
  no extra lookup. Reading a directory fails `IsDir` rather than the misleading `NotFound`.
- The per-block allocation churn was already mostly gone with the caches; the one remaining hot
  allocation rides a reusable scratch member. **A scratch pool for the cold paths was deliberately not
  added - complexity without a measurement behind it.**

Three test gaps were closed, and one is worth noting for how it was done: a real 64-bit FNV hash
collision is impractical to find, so the colliding-hash test drives the pure leaf helpers with
synthetic equal-hash records instead of hunting for one.
