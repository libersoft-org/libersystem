# M0102 - LiberFS: revisit under the fs-track discipline

Status: COMPLETE. A fresh full-source pass (2026-07-04) applying the rule-set the FAT, ISO9660 and
UDF tracks had built. The earlier hardening held; this found one crash-consistency hole and three
gaps the sibling backends had already closed.

*Condensed 2026-08-08.*

**The commit path could orphan a superblock.** `commit` treated a failed post-superblock flush like
any other failure: it aborted, memory reverted to the old generation and the fresh blocks went back
to the pool - **but the new-generation superblock may already be durable**. A later transaction
reuses those blocks, and a crash before its commit point mounts the orphaned higher generation whose
trees have been overwritten.

The rule that came out of it: **once the superblock write is attempted, the transaction may never
roll back.** The new generation is adopted either way, and a failed durability flush costs
writability - the volume degrades to read-only, because the device is failing and the in-memory state
matches whichever superblock survives.

- **`load_snapshot_table` and `load_spill` walked their chains with no step bound**, so a
  CRC-consistent forged cycle hung the mount. CRC32C is forgeable offline, and the test proves it: it
  builds a genuinely self-vouching cycle by solving the CRC fixpoint.
- **The live read paths trusted on-medium block pointers without the pool gate.** Past the pool's end
  that is another partition's data on a shared device - and a tree-node read surfaces it as file
  names. Every read path gates now, as the mark walks already did.
- A rename replacing a damaged empty directory freed the inode but dropped blocks only for a file,
  leaking its tree nodes forever. Both paths share one drop.
