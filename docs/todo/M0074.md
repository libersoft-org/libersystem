# M0074 - LiberFS: allocator and free-map scaling

Status: COMPLETE. The performance milestone: **nothing here changes the on-disk format.**

Two O(volume) costs sat on every write path.

*Condensed 2026-08-08.*

- **`derive_free` walked the whole volume after every commit** - the live tree, the previous
  generation, everything. The free map is incremental now: every path that stops referencing a
  committed block records it on the transaction's dead list, so a commit updates rather than rebuilds.
- **The allocator was O(pool) per block and O(pool²) per large write.** Next-fit cursors on both ends
  - data scanning up, metadata scanning down, each wrapping once - with byte-wide bitmap scanning
  using leading and trailing zero counts.
- **Checksum blocks cost 2-3x I/O amplification.** Slot edits go to an in-flight write cache that
  reaches the device once, on eviction or at the commit barrier.
- **Nothing was cached at all** - every operation resolved its path from the root. A bounded inode
  cache (64 entries, spill chains pre-loaded, pathological extent maps skipped) plus a bounded node
  cache, invalidated on free and on abort.

**The extent spill chain was assessed and deliberately kept**, recorded rather than silently skipped.
The arithmetic: extents merge up to 1024 blocks (4 MB) each, so even a 1 GB contiguous file needs few
enough that a linked list costs nothing worth a format change.
