# M0125 - Native executable artifacts (`.lsexe`)

Status: COMPLETE (2026-07-15).

Every native userspace executable has one explicit, system-identifying suffix, while command entry
stays ergonomic.

*Condensed 2026-08-08.*

The decisions worth keeping are all about **not letting spelling become policy**:

- **One launch normalizer**, shared by the shell, PermissionManager and ProcessService. Three
  independent normalizers would be three chances to disagree about what a name means.
- **Ambiguity is rejected at image construction**, not resolved at runtime by guessing from a
  filename. If two artifacts could answer to one command word, the image does not build.
- **Policy cannot be bypassed by spelling.** Capability lookup, command aliases and completion all
  resolve through the canonical name, so `foo` and `foo.lsexe` cannot reach different grants.
- **Full process identity**: ProcessService records the canonical artifact basename, so what `ps`
  shows is what the manifest declared.
- Shell completion strips one validated `.lsexe`, which is the whole of the ergonomic concession.

`PKGARCH1` keeps its existing magic; the suffix is a naming rule, not a format change.
