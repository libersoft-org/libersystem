# P02M0034 - Capacity quick wins (the limits-audit small fixes)

Status: COMPLETE. Buffers and rings that were simply too small, where raising them was cheap and
self-contained.

*Condensed 2026-08-08.*

Network request and reply buffers to 1024 and 4096 - a DNS name alone can be 253 bytes plus framing,
and `ss` with a handful of sockets overflowed the old reply. Line-editor history 32 → 512. Terminal
scrollback 100 → 1000, verified to stay lazy: the buffer lives in the screen structure, which exists
only for opened display VTs, so an unopened VT still costs nothing. The virtual-terminal set became
uncapped, since a VT's cost is its own grid.

**The journal went from 32 records to 4096, and that exposed a second defect.** A limited query
returned the *oldest* matches, which a deep journal makes useless - it now returns the newest, and
the `log` command asks for one reply's worth while the full journal streams.

The general lesson: raising a bound changes which end of a collection matters, and a query written
against a tiny buffer often has the wrong end baked in.
