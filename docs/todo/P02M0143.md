# P02M0143 - Six holes an outside audit found that are worth closing, and the ones that are not

Status: OPEN. HARDENING. NOT A PHASE-2 COMPLETION GATE.

## Goal

Close the findings of an external architecture audit that have a bounded fix, and record why the
rest are refused.

The audit scored the architecture 8.3 and named thirteen gaps. Its facts hold up - every claim below
was checked against the tree - but its remedies are sized for a system with users, hardware and a
second protocol version, and this one has none of those. Seven of its findings would cost more than
the whole of phase 2 and are refused by name in "What this milestone refuses" below. Six have a fix
measured in days. Those six are this milestone.

A seventh, the boot-tail divergence between architectures, is already P02M0142 and is not repeated
here.

## What is there now

Measured on 2026-08-22 by reading the tree.

- `CMD_BUS_MASTER` is set at three call sites in `arch/common/pci/mod.rs` and cleared at NONE. A
  device whose driver has died keeps bus mastering enabled for the life of the boot.
- `sys_dma_buffer_phys` hands back a physical address as a plain integer under `Rights::READ`. The
  number outlives the buffer, the mapping and the process.
- `ResourceAccount` charges memory, DMA, queued IPC bytes, handles, wait-set registrations, threads
  and stack. Page tables are not among them: `arch/*/paging.rs` calls `frame::allocate()` directly.
- The build computes a sha256 per staged artifact - `check-staged-image.sh` says so in its own first
  line - and the loader reads none of it. It verifies nothing about the kernel it jumps to.
- A channel message is a `Vec<u8>` and a `Vec<Capability>` in a `VecDeque<Message>`. Every send
  touches the kernel heap. No benchmark measures a raw channel round trip; `storage-roundtrip-perf`
  measures a service call through the whole stack.
- `rt::receive_roles` checks a bootstrap handle's tag, kernel object type and rights floor and
  ceiling. A capability arriving in an ordinary LSIDL message is checked for none of those.

WHAT IS ALREADY BETTER THAN THE AUDIT ASSUMED, so that nothing here is fixed twice:

- Selective revocation of a delegated branch already exists ONE LAYER UP: PermissionManager mints a
  connection per grant and revoking one is closing that channel. The audit's example - revoke `A`'s
  delegation to its plugin without touching `B` - needs no kernel change.
- The in-kernel ELF parser is already fuzzed by two gates, `malformed-dynamic` and
  `malformed-symbol-relocation`, which is the risk that moving it to userspace would address.
- The ordered bootstrap the audit wants replaced by a `BootstrapBundle` is already typed and
  fail-closed through `receive_roles`. Its remaining gap is that four services of twenty-three use
  it, which is P02M0141's M6 and M7, not a new design.
- Released DMA frames go through `frame::retire`, not back to the allocator. Today's bus-mastering
  hole is therefore a LEAK rather than a use-after-free, and M1 keeps it that way deliberately.

## Work

- [ ] **M1 - Bus mastering is switched on and never off.**
  - Three sites enable `CMD_BUS_MASTER`. Nothing clears it - not when a driver exits, not when a
    device is released, not when `sys_device_quiesced` confirms the device stopped.
  - Clear it on the paths that already exist: device release, and the quiesce that already frees the
    DMA frames and the MSI vectors. The syscall is the natural place because it is already the
    claim "this device has stopped".
  - AND ENABLE IT LATER THAN NOW. Two of the three sites set it during enumeration, before any
    driver is bound. A device that is bus-master-capable before anything owns it is capable for no
    reason.
  - THIS IS NOT AN IOMMU AND DOES NOT PRETEND TO BE. A device with bus mastering off cannot write
    anywhere; a device with it on can still write anywhere it was programmed to. What this closes is
    the window after a driver dies, which is the window nothing was watching.

- [ ] **M2 - A physical address must not outlive what it describes.**
  - `sys_dma_buffer_phys` returns an integer. Once a driver has it, unmapping the buffer, closing the
    handle or killing the process takes nothing away.
  - Refuse the call for a buffer that is not currently mapped and bound to a device, so the number is
    only obtainable while the thing it names is real. That does not make the number revocable -
    integers are not - but it removes the case where one is handed out for something already gone.
  - WRITE DOWN WHAT REMAINS, in the threat model, in one sentence: a driver that recorded the address
    earlier still holds it, and without an IOMMU nothing can take it back. Saying so is the deliverable
    for the part that cannot be fixed here.

- [ ] **M3 - Every allocation userspace can provoke needs an accounting owner.**
  - Page tables first: a process that maps pages makes the kernel allocate frames for its own tables,
    and nothing charges them to that process's Domain. A mapping loop is therefore a way to consume
    kernel memory without touching a limit.
  - Then the rest of the sweep: kernel metadata behind channels, events and timers, IRQ bindings, and
    anything else reachable from a syscall that allocates.
  - THE RULE, AND IT IS SHORT: an allocation a userspace call can cause has a Domain that pays for it
    and a limit that can refuse it. Where a charge would be wrong - boot-time, kernel-internal - the
    `ALLOC-OK` marker the tree already uses says so at the site.
  - Domains already carry the machinery. This is finding the uncharged paths, not inventing a
    mechanism.

- [ ] **M4 - The loader verifies what it loads.**
  - The build already computes a sha256 for every staged artifact. Emit those into a boot manifest
    the loader reads, and refuse to boot a kernel or a package whose bytes do not match.
  - NO SIGNING, NO KEYS, NO A/B SLOTS, NO ANTI-ROLLBACK COUNTER, NO TPM. Those need a key holder, an
    update channel and a recovery story, and this project has none of the three. What this item buys
    is the difference between "the build was internally consistent" and "this is the image that
    build produced", which is worth having on its own and is the step everything else would build on.
  - BE HONEST ABOUT WHAT IT PROVES. A digest checked against a manifest that travels beside the image
    detects corruption and accident. It does not detect an attacker who can rewrite both. That is the
    line where signing starts, and this milestone stops there rather than implying it went further.

- [ ] **M5 - Measure IPC before optimising it, then remove the allocation.**
  - MEASUREMENT FIRST AND IT DOES NOT EXIST YET. Nothing benchmarks a raw channel round trip today;
    the closest figure goes through the storage service and the whole stack. An optimisation with no
    before is a change, not an improvement.
  - Then the fix: a small inline payload carried in a preallocated slot, so an ordinary control
    message costs no kernel heap traffic. Large payloads keep going through shared buffers, which is
    what the protocol already does.
  - The number goes in the same report the other `*-perf` markers use, so a later regression is
    visible where the existing ones are.
  - NOT IN THIS ITEM: direct sender-to-receiver handoff, cancellation, deadlines, multi-flight
    requests. Each is a protocol change wearing an optimisation's clothes.

- [ ] **M6 - A capability received in a message is checked like one received at bootstrap.**
  - `receive_roles` checks tag, kernel object type, and both a floor and a ceiling on rights, and
    closes everything already taken when it refuses. A handle arriving in an ordinary LSIDL message
    gets none of that: a service takes what it is given.
  - Generate the same check from the interface declaration, so a method that expects a channel with
    send and receive rights refuses a memory object, and refuses a channel carrying MANAGE.
  - THE MODEL IS ALREADY THERE. `RoleKind::object_type`, `required_rights` and `maximum_rights` are
    the vocabulary; this is applying them to the second place capabilities cross a boundary.

## Dependency order

```text
M1 --> M2        both are the DMA boundary, and M1 is the half that matters
M3               independent
M4               independent
M5 (measure) --> M5 (change)
M6               independent, and closest to work already landed
```

Nothing here blocks anything else. M1 and M3 are the two with a security argument; M6 is the
cheapest because the vocabulary exists.

## Definition of done

- No device has bus mastering enabled while no driver owns it, and the quiesce path clears it.
- `sys_dma_buffer_phys` refuses a buffer that is not currently bound, and the threat model states in
  one sentence what a driver that already read the address can still do.
- Page tables are charged to the Domain that caused them, and a sweep for other uncharged
  userspace-triggered allocations has been done and its result written down - including the paths
  that are deliberately not charged.
- The loader refuses to boot bytes whose digest does not match the boot manifest, and the milestone
  text says plainly that this is integrity and not authenticity.
- A raw channel round trip has a published number from before the change and after it.
- A capability arriving in an LSIDL message is refused when its object type or rights do not match
  the declaration, generated from that declaration rather than written by hand.

## What this milestone refuses, and why

Recorded because the audit asked for each of these, and a later reader should find a decision rather
than an omission.

- **An IOMMU.** Three architectures of device-side page tables, and under emulation it would prove
  almost nothing. M1 and M2 narrow the window it would close; the rest stays in the threat model.
- **A general pager: `VmObject`, copy-on-write, page cache, swap.** The system has no `fork`, no
  file mapping and an immutable image loaded from a package. This is a subsystem built for
  requirements that do not exist.
- **A capability derivation tree with selective revocation in the kernel.** It puts an indirection on
  the hottest path in the kernel to solve a problem the service layer already solves with a
  connection per grant.
- **Priority classes, priority donation, NUMA placement, tickless scheduling, admission control.**
  The scheduler has no priorities, so priority inversion cannot occur. Adding priorities in order to
  need donation invents the disease and the cure together.
- **Moving the ELF loader, the dependency resolver and PCI enumeration into userspace.** It trades
  about a thousand lines of kernel for a wider kernel API - map into a foreign address space, seal
  an image, a load transaction - and the parsing risk is already fuzzed by two gates.
- **LSIDL wire evolution: field IDs, flexible records, protocol negotiation, side-by-side major
  versions.** Nothing in this tree is versioned yet by an explicit project rule. Wire evolution
  before a version two is machinery for a migration nobody has to do.
- **Formal specification of kernel invariants.** Twenty-six gates, a verification model and property
  tests are proportionate at this stage. A formal model of nine subsystems is a research project that
  would not change a line of the kernel.
