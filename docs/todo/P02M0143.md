# P02M0143 - Runtime ownership: lifecycle, state, and fail-closed recovery

Status: PLANNED AFTER P02M0142. SYSTEM-ARCHITECTURE FOUNDATION. NOT A PRODUCT, RELEASE OR UPDATE
GATE.

## Goal

Give every long-lived part of the current userspace a clear owner, lifecycle, state class and
failure outcome. Make SystemManager the persistent owner of the control-plane branch and make
ServiceManager execute the generated plan without becoming a new general orchestrator.

The simplest safe system-level recovery remains valid: when the control plane cannot be recovered
using the existing bounded service restart mechanism, reboot the development guest. This milestone
does not implement workload adoption or transparent recovery of arbitrary open resources.

## Version ownership rule

`v1` remains open until the project owner explicitly says otherwise. Completing this milestone
means that its current acceptance criteria and standing gates pass. It does not freeze an API, ABI,
schema, file format, machine description, product profile or release line. Breaking `v1` changes
remain allowed when all in-tree producers, consumers, generated files and tests migrate together.
Only the project owner may declare `v1` closed or start a successor version.

## Scope

This milestone defines common runtime semantics and ownership. It reuses rather than replaces:

- P02M0011 for service watchdog, restart budget, backoff and dependency teardown;
- P02M0010 and kernel Domains for resource accounting and enforcement;
- ConfigService for configuration storage and delivery;
- P02M0098 for driver-specific generations, teardown and rebinding; and
- individual services for their own persistent formats and recovery logic.

No new resolver, second restart engine, general migration framework, high-availability control
plane, remote operations or product/update mechanism belongs here.

## Work

- [ ] **M1.1 - Define one small lifecycle for managed deployments.**
  - Use a common set of states: absent, starting, ready, degraded where meaningful, stopping,
    failed and stopped/replaced.
  - Keep desired state separate from the state actually observed at runtime.
  - Attach `DeploymentId`/`ServiceId`, `BootId` and a new `InstanceEpoch` to every start and lifecycle
    transition.
  - Give transitions a reason and monotonic sequence so an old event cannot overwrite a newer
    instance.
  - Continue evolving this vocabulary inside `v1` as concrete services expose missing semantics.

- [ ] **M1.2 - Classify ownership of service state.**
  - Classify every long-lived deployment as ephemeral, reconstructible, durable, external or
    session-owned.
  - Name the state owner, storage location where applicable and expected result of process restart
    and whole-guest reboot.
  - Keep the concrete schema and persistence implementation with the service that owns the data.
  - Do not promise that a replacement process inherits an open file, socket, watch, session or
    stream; the default result is an explicit loss/error.
  - Add service-specific reopen or replay behavior only when that service actually implements it.

- [ ] **M1.3 - Make readiness, health and restart policy explicit.**
  - A started process is not automatically Ready, and one successful bootstrap reply is not
    permanent health.
  - For each managed service declare readiness, health detector, restart/escalation class, retry
    budget, backoff and terminal result.
  - Reuse the P02M0011 watchdog and restart machinery rather than adding another supervisor.
  - A restarted service receives a new `InstanceEpoch`; stale endpoints and late events remain tied
    to the old instance.
  - Bound waits and control messages needed for readiness, health and shutdown using the current
    timeout/cancellation conventions.

- [ ] **M1.4 - Keep SystemManager resident as the control-plane owner.**
  - SystemManager remains alive after bootstrap and owns exactly the ServiceManager/control-plane
    branch created from the generated plan.
  - It observes ServiceManager health and owns the escalation decision when that branch fails.
  - Keep root-Domain `MANAGE` authority inside SystemManager and expose only a narrow local
    SystemPower request service to components such as the power-button path; those clients must not
    receive root-Domain management authority.
  - It does not absorb per-service wiring, application policy, driver policy or ordinary data-plane
    work.
  - ServiceManager remains the one service supervisor and executes the P02M0142 plan.
  - If SystemManager itself is lost, use the existing first-userspace recovery/reboot ladder; do not
    create an in-place SystemManager resurrection framework here.

- [ ] **M1.5 - Align supervision, failure and Domain ownership.**
  - Build the declared Domain/resource hierarchy from the P02M0142 projection.
  - Make supervision owner, failure parent and resource parent the same by default; record and check
    the few real exceptions.
  - Ensure bulk termination removes the complete owned branch without enumerating every process in
    handwritten cleanup code.
  - On unrecoverable ServiceManager/control-plane loss, stop advertising the branch as healthy and
    reach a declared reboot or terminal failure outcome.
  - Do not preserve or adopt workloads across that failure.

- [ ] **M1.6 - Connect resource and configuration declarations to their existing runtimes.**
  - Make each long-lived deployment use its declared or inherited ResourceManager profile for the
    limits already supported by the system.
  - Declare admission/backpressure behavior for current connection and queue types where a bounded
    mechanism already exists; add new mechanisms only under the subsystem that needs them.
  - Apply the owner, type, default, validation and live-or-restart behavior declared for current
    config keys by P02M0141.
  - Keep ConfigService as the value store and ResourceManager as the policy/enforcement owner.
  - Reject a missing required profile/schema reference instead of silently applying unrelated
    defaults.

- [ ] **M1.7 - Exercise a finite development fault matrix.**
  - Cover clean boot, selected service crash/hang, non-restartable service failure,
    ServiceManager loss, SystemManager loss, device/provider loss, resource denial and invalid
    configuration/state.
  - For each row state the detector, owner and expected bounded outcome: restart with a new epoch,
    explicit failure, branch teardown or guest reboot.
  - Verify that no ownerless userspace branch remains reported as healthy.
  - Run scenarios through P02M0104 and register their ownership/selection through P02M0118.
  - Record measured development behavior without introducing production SLO, release or support
    claims.

## Definition of done

- SystemManager stays resident and owns the ServiceManager/control-plane branch without duplicating
  ServiceManager's per-service supervisor role.
- Every current long-lived deployment has a state owner, lifecycle identity, readiness/health rule
  and restart or escalation outcome.
- Restarted services receive a new epoch; stale endpoints and events cannot be presented as the new
  instance, and generic subresource continuity is not promised.
- Supervision, failure, Domain and resource ownership follow the generated plan or carry an explicit
  checked exception.
- Existing ResourceManager and ConfigService consume the declared profile/schema references; no
  parallel policy service or database is introduced.
- Control-plane failure reaches a declared fail-closed result without an ownerless branch remaining
  healthy.
- The finite development fault matrix passes through existing test infrastructure.
- Completing the milestone leaves `v1` open for continued coordinated change.

The implementation records exact scenario commands and results in dated evidence sections. The
evidence describes the current development system and never closes a release or `v1`.
