# P02M0143 - Desktop profile, portals and the application ecosystem

Status: PLANNED AFTER P02M0142. FUTURE DESKTOP PRODUCT-PROFILE GATE. NOT A PHASE-2 COMPLETION GATE.
Completion also requires P02M0098, P02M0103s/a/b/c/d, P02M0105, P02M0106 and P02M0136. The desktop
consumes their provider, graphics, locale, identity and text contracts plus the principal,
delegation, lease, service-epoch, package and resource contracts of the general platform; it does
not create desktop-only alternatives to them.

## Goal

Define and prove the system architecture that turns LiberSystem's current fullscreen graphics,
input, audio and application mechanisms into a multi-application desktop platform.

The missing layer is not another renderer. It is composition and policy: graphical sessions and
seats, a compositor/window system, focus and secure input routing, user-mediated portals, per-app
namespaces, an honest stable application contract, accessibility, suspend/resume and a product
profile with its own failure and compatibility guarantees.

Task prefixes are global within this three-milestone architecture track: `M1.x` is the appliance,
`M2.x` the general/server platform and `M3.x` the desktop/application platform.

## Decisions fixed by this milestone

- The desktop is a distinct product profile, not a superset checkbox on the appliance or server.
  Reference VM appliance, physical edge appliance, server, desktop and later AI profiles share a
  core but keep separate prerequisites, MachineProfiles, threat models, SLOs and exit criteria.
- P02M0103 owns image, WSI, Render2D/Render3D and backend contracts. This milestone owns window,
  session and composition policy above those primitives; the compositor does not become a renderer,
  font shaper or device driver.
- P02M0106 owns accounts, authentication, login and the base lock model. This milestone binds those
  principals and sessions to seats, displays, input, portals and app Domains; it does not add a
  second credential store.
- A user or app identifier is not authority. Apps receive explicit capabilities, and sensitive
  user-mediated grants are scoped, leased, revocable, visible and audited.
- M3.5 owns one canonical sensitive-grant family and the trusted user decision. M3.4 consumes it for
  clipboard/DnD/capture enforcement and transport; M3.8 consumes it for device-stream lifecycle and
  privacy indicators. Those tasks do not invent competing clipboard or `CaptureGrant` types.
- There is no ambient global filesystem, clipboard, microphone, camera, screen-capture or input
  authority. Path-oriented application hosts see only a namespace composed from delegated objects.
- The native Liber capability/LSIDL boundary remains canonical. Any WIT Component Model/WASI,
  POSIX, Wayland/X11 or foreign toolkit support is a userspace adapter with an explicit product
  compatibility contract, not a kernel personality.

## Relationship to existing milestones

- P02M0091 supplies today's surface, raw-input and PCM application capabilities.
- P02M0103s/a/b/c/d supplies the normative WSI/common graphics, Render2D, software backend and 2D
  conformance required by the first desktop profile. Its 3D and foreign-GPU tracks are optional.
- P02M0105 supplies locale, region, time-zone, keymap and formatting policy.
- P02M0106 supplies accounts, AuthService, login, identity-bearing sessions and lock/unlock.
- P02M0136 supplies shaping, fallback, BiDi, layout, caret and selection geometry.
- P01M0012 supplies the file-picker/powerbox prototype to generalize; P02M0098 supplies dynamic
  device/provider lifecycle and hotplug.
- P02M0012 and P02M0130 supply the current Liber component ABI and SDK seam. This milestone defines
  a stable Desktop App Profile above it.

P02M0135, P02M0103's 3D track and P02M0099 are not hard gates for the QEMU desktop profile. This
milestone does not implement Mesa/OpenGL/Vulkan, POSIX, X11/Wayland compatibility, a physical GPU
matrix, mobile shell, remote desktop, cloud sync, an app store, browser/office suite, DRM or an AI
runtime.

## Target shape

```text
account principal
      |
      v
SessionDomain @ SessionId/Epoch ------ session-scoped authority / resources
      |
      +-- desktop shell
      +-- compositor / window policy ---- Display + seat authority
      +-- portal broker ----------------- user-mediated derived capabilities
      +-- AppDomain @ AppId/InstanceEpoch
             |          |          |
             |          |          +-- leased media/device grants
             |          +------------- composed namespace roots
             +------------------------ window/surface endpoints

application / toolkit
      |
Desktop App Profile + LSIDL
      |
Render2D / optional Render3D + shaped text       (owned by existing milestones)
      |
surface/present contract
      |
compositor -> DisplayService -> display provider
```

## Work

- [ ] **M3.1 - Add `DesktopProfile v1` to the product-profile catalog.**
  - Consume P02M0141's catalog and add only the desktop profile's prerequisites, MachineProfile
    overlays, threat/fault model, service-level objectives and exit criteria. Do not revise the
    appliance or server contract from inside the desktop track.
  - Define the finite `DesktopProfile v1` user journeys: provision/login, lock/unlock, launch/quit,
    multi-window interaction, file choice, clipboard, notifications, media permission, device
    hotplug, suspend/resume, logout, update and recovery.
  - State what survives an app crash, compositor crash, session-service crash, logout, system-epoch
    replacement, suspend and reboot, with RTO/RPO and visible user outcome.
  - Qualify the exact QEMU MachineProfile and architecture tier used for desktop conformance. Physical
    displays, GPUs, touch hardware and power controllers are not implied.
  - Keep physical edge, mobile and AI work in separate future profile gates; do not hide their
    hardware, authority, privacy or resource-scheduling promises inside desktop completion.

- [ ] **M3.2 - Define graphical sessions, seats and secure-attention ownership.**
  - Bind P02M0106's authenticated principal and SessionId to one `SessionDomain`, session resource
    root, locale, namespace, desktop shell and set of app Domains.
  - Define `SeatId`, output/input membership and epochs. Multiple principals/sessions cannot share
    focus, surfaces, private clipboard or input events unless an explicit sharing capability says so.
  - Give the trusted login/lock surface an unspoofable secure-attention path and the minimum display
    and input authority needed to take control from an ordinary session.
  - Lock detaches display/input authority without killing background work according to P02M0106;
    logout terminates the SessionDomain and revokes portal/media/clipboard grants.
  - Define switching, headless session, failed login service and session recovery behavior without
    allowing the compositor or shell to read the credential store.

- [ ] **M3.3 - Define and implement the compositor/window-system contract above P02M0103.**
  - Define stable identities and epochs for compositor, output, workspace, window and surface roles,
    including ownership, parent/child relationships and teardown.
  - Specify window-role create/configure/ack/map/unmap behavior, atomic resize and
    scale/orientation/output changes plus bounded window event queues. Consume P02M0103's existing
    WSI damage, present and frame-completion contract rather than restating it here.
  - Decide the P02M0091 surface migration explicitly: the compositor either provides a compatible
    facade with the old semantics or applications cross a new versioned boundary. A silent change in
    who receives or presents the same endpoint is not compatibility.
  - Support multiple surfaces and applications, stacking/occlusion, multi-output placement, logical
    versus physical coordinates and frame scheduling without exposing scanout authority to clients.
  - The compositor owns scene composition, focus policy and final presentation. Applications own
    content; Render2D/3D backends own drawing; DisplayService/provider owns hardware presentation.
  - Decide compositor crash semantics: either clients re-register/recreate through explicit epochs
    and tokens, or the session restarts as one failure group. Prove the chosen behavior; do not imply
    transparent recovery merely because a new compositor process starts.

- [ ] **M3.4 - Make focus, input routing and inter-application data transfer explicit authority.**
  - Route keyboard, pointer, touch and future input only through the active seat/focus policy, with
    serial/generation checks that reject stale events after focus or device-epoch changes.
  - Define grabs, shortcuts, secure attention, pointer confinement, synthetic input and background
    input policy. Ordinary apps cannot globally observe keys or inject trusted input.
  - Model clipboard and drag-and-drop as brokered, typed transfers with source, destination, offered
    formats, user gesture, size/resource bounds, cancellation and a per-transfer capability issued
    under M3.5's canonical grant family.
  - Screen content access uses M3.5's separate capture grant; knowing a SurfaceId or being able to
    present a window does not authorize reading another surface or the composed output.
  - Specify behavior when focus owner, source app, destination app, input device or compositor dies
    during a transfer.

- [ ] **M3.5 - Generalize the powerbox into a production portal family and app namespaces.**
  - Define portals for open/save/file/directory, clipboard, notification, screenshot/screen share,
    microphone, camera and other sensitive desktop resources selected by the profile.
  - Every request records requesting `AppId/InstanceEpoch`, principal/session, user gesture, resource
    class, requested rights and purpose. The trusted portal UI shows the real requester and scope.
  - A successful choice returns only the selected object/stream with attenuated rights, scope,
    lease, revocation owner and audit identity. Cancellation and denial are normal typed outcomes.
  - Define the one canonical sensitive-grant descriptor/family used by clipboard, capture and
    media portals, including principal/session/app/resource epochs, rights/direction, lease,
    revocation and indicator metadata. Enforcement remains in the owning broker/service.
  - Compose a path-oriented host namespace only from granted directory/volume roots. An app cannot
    enumerate a global volume registry or infer objects outside its namespace.
  - Define persistence of remembered grants, revalidation across app/update/resource epochs, visible
    indicators and revocation on logout, uninstall or resource removal.
  - Portal UI and grant decision are separated from the specialized grantor's actual capability so
    neither a label nor a forged dialog can mint authority.

- [ ] **M3.6 - Freeze `Desktop App Profile 1` and its compatibility policy.**
  - Define stable `AppId`, signed package identity, application descriptor, activation model,
    single/multi-instance policy, window roles, associations, notifications, background execution,
    resource profile, config and app-state schema.
  - Publish a boundary matrix for native Liber ABI, LSIDL services, the current Liber core-Wasm
    world and any chosen Component Model/WASI adapter. State which is normative and which are
    optional adapters; do not use "WASI" as an umbrella claim.
  - Choose whether `Desktop App Profile 1` is native-only, Liber-Wasm-capable or includes a specific
    WIT/Component/WASI version. If an adapter is included, define import world, limits, failure,
    threading/async and capability-to-host-object semantics exactly.
  - Define compatibility windows, feature negotiation, deprecation, package update and app-state
    migration. An incompatible app is refused before receiving authority.
  - Keep system `.lslib` and private image internals lockstep unless separately promoted to a public
    app ABI with an explicit support commitment.

- [ ] **M3.7 - Define the toolkit, text, locale, IME and accessibility seams without duplicating them.**
  - Define a reference toolkit contract over Render2D, shaped glyph runs and window events: layout,
    widgets, theme, scaling, invalidation, focus traversal and semantic actions. The toolkit is not
    the compositor protocol.
  - Consume P02M0105 locale/keymap/format settings and P02M0136 shaping/BiDi/fallback/caret geometry;
    no second font parser, shaper or locale database is introduced in the shell or compositor.
  - Define an IME/text-input protocol with focus, surrounding text, selection, composition,
    commit/cancel and privacy modes for credentials and other sensitive fields.
  - Publish a semantic accessibility tree with stable node epochs, roles, state, relationships,
    bounds and actions through a capability-gated broker. Accessibility authority is part of the
    confidentiality TCB and is scoped to the active session.
  - Cover keyboard-only navigation, focus visibility, magnification/screen-reader consumption and
    malformed/stale semantic updates. Certification beyond the declared baseline is not implied.

- [ ] **M3.8 - Define media, capture and device-session privacy/lifecycle.**
  - Make playback, recording, microphone, camera and screen capture separate capability classes with
    session/app scope, direction, device scope, lease and visible activity state, represented by
    M3.5's canonical grant family rather than media-only grant metadata.
  - Define policy for exclusive/shared devices, default selection and switching without giving apps
    a global device catalog or raw DeviceManager authority.
  - Consume P02M0098 provider epochs for display, input, audio and later camera hotplug/rebind; stale
    device endpoints fail and cannot attach to a new physical instance accidentally.
  - Specify what the compositor, portal broker, media services and shell may observe and audit; an
    accessibility grant does not silently imply capture, and playback does not imply recording.
  - Lock revokes or pauses capture, microphone, camera and other foreground-sensitive grants so an
    already-open endpoint cannot continue recording behind the lock screen. Only explicitly declared
    background playback/work may survive with its narrowly retained authority.
  - Cover unplug, service replacement, session switch, lock, suspend, logout and app crash while a
    stream or capture grant is active.

- [ ] **M3.9 - Add suspend/resume and desktop power lifecycle as a system transaction.**
  - Define prepare, quiesce, veto/timeout, checkpoint, device suspend, platform transition, resume,
    rebind and completion states with one coordinator and bounded deadlines.
  - Classify each service, app and exported resource as resumable, reconstructible, restart-on-resume
    or session-ending. Persist only state whose owner/schema contract permits it.
  - Invalidate device/output/input epochs on resume where hardware identity is not preserved and
    require clients to re-resolve/recreate rather than use stale mappings.
  - Keep power authority narrow: shell policy may request suspend or shutdown without receiving
    root-Domain management or update authority.
  - Test power loss and failure during prepare/resume; the terminal outcome is a usable resumed
    session, a defined session restart or system recovery, not a half-resumed desktop.

- [ ] **M3.10 - Freeze desktop failure, resource, privacy and observability profiles.**
  - Assign compositor, shell, portal broker, accessibility broker, session services and apps to
    explicit supervision/failure/resource Domains with protected budgets for login, lock and
    recovery paths.
  - Bound surface/image bytes, event queues, clipboard/transfer bytes, portal requests, semantic
    trees, background CPU, audio/capture work and app connection counts with fair admission.
  - One hostile or memory-heavy app cannot starve compositor input/presentation, lock screen,
    another session or the system recovery reserve.
  - Extend lifecycle observability with session-safe redaction, focus/window/output/device epochs,
    portal grants, privacy indicators and suspend state. Apps cannot enumerate other sessions from
    the graph.
  - Publish property-specific trust views for secure attention, session isolation, input privacy,
    screen/media confidentiality, package provenance and update integrity.

- [ ] **M3.11 - Publish the SDK/profile conformance suite and independent-consumer proof.**
  - Generate SDK types, package descriptors and compatibility metadata from the normative app,
    portal, window, input, text and lifecycle schemas rather than maintaining handwritten mirrors.
  - Provide conformance tests for app launch, windows, frame/event flow, portals, namespaces,
    clipboard/DnD, IME/accessibility, media grants, state migration, resource pressure and epochs.
  - Build at least two independently structured applications against the published SDK/profile; the
    reference shell and image viewer alone cannot define the contract by being its only consumers.
  - Test the oldest supported app/profile version on the newest compatible release and refuse an
    unsupported package before launch. Bind results to exact SDK, profile and release identities.
  - Document only guarantees tested by the public conformance kit; private shell behavior is not an
    accidental application API.

- [ ] **M3.12 - Migrate one complete desktop profile and close it under lifecycle churn.**
  - Assemble a finite QEMU desktop product from the shared SystemSpec fragments and prove that two
    principals receive isolated sessions and two apps receive independent surfaces, namespaces,
    state and resource accounts.
  - Exercise login/lock/unlock/logout, focus changes, multi-output/scale, app/compositor crash,
    clipboard/DnD, portal denial/grant/revoke, media privacy, device hotplug and suspend/resume.
  - Inject stale epochs, slow/hostile apps, queue/resource exhaustion and failures during portal,
    compositor and power transitions; verify the declared recovery outcome and protected control
    paths.
  - Prove that an app cannot intercept or synthesize the secure-attention chord; keep capture and
    microphone endpoints open across explicit revoke and lock and require further use to fail.
  - Migrate and then roll back or recover one app-state schema according to its compatibility
    contract. Query accessibility from another session and from a credential field and prove the
    broker redacts both rather than exposing their semantic text.
  - Compare desired and observed authority/lifecycle/resource graphs and reject ambient global
    resources, cross-session leakage, unowned durable state or an unversioned compatibility edge.
  - Publish `DesktopProfile v1`, the app SDK/profile, security/fault matrix, support limits and exact
    conformance evidence without claiming physical hardware, full WASI, POSIX or 3D support.

## Definition of done

- Two principals have isolated graphical sessions; surfaces, input, clipboard, private app state,
  namespaces, portal grants and observability do not cross without an explicit sharing capability.
- Lock removes ordinary session display/input control without killing declared background work;
  logout terminates the SessionDomain and revokes its leased sensitive grants.
- Multiple applications and outputs follow the versioned compositor/window contract, and app or
  compositor failure produces the documented epoch/recovery result.
- An unprivileged app cannot enumerate volumes, capture input/screen/audio/video or contact an
  undeclared service. A portal returns only a user-selected scoped object/stream with audit and
  revocation.
- The exact Desktop App Profile distinguishes native ABI, LSIDL, Liber Wasm and optional future
  adapters, and its oldest supported version passes on the newest compatible release.
- Text, locale, IME and accessibility consume the shared platform seams; suspend/resume and device
  churn cannot revive stale authority.
- Hostile application load cannot starve compositor, secure attention, lock or recovery budgets.
- One QEMU `DesktopProfile v1` and at least two independent applications pass the security, fault,
  resource and compatibility matrix, with exact release/MachineProfile evidence.
- At minimum, the milestone adds and passes repository gates equivalent to:

```sh
./check.sh --gate desktop-profile
./check.sh --gate desktop-app-contract
./check.sh --gate portal-authority
./verify.sh --profile desktop-reference
git diff --check
```

The concrete commands, profile hashes, compatibility pairs, failure injections and results are
recorded in dated evidence sections in this file. A working fullscreen demo or renderer test is not
desktop completion.
