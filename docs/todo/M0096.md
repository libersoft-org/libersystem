# M0096 - ISO9660: first-pass audit (hostile-media panics and unbounded reads)

Status: COMPLETE. The first full audit pass over the ISO9660 backend (2026-07-04), under the
hostile-media discipline the FAT track built: the crate reads foreign install and optical media, so a
malformed disc must error cleanly - never panic the storage service, never allocate without bound.

*Condensed 2026-08-08.*

- **Two slice panics on a malformed directory record**, either of which took the storage service down
  on a mere listing: a record whose identifier ends exactly at the record boundary put the system-use
  offset one past the end, and a Rock Ridge "NM" entry of length exactly 4 built an inverted range.
- **`read_extent` allocated from the medium's own u32 claim before any device read.** A forged root
  length of 0xFFFFFFFF mounted and the first listing tried to allocate 4 GB. The Volume Space Size is
  read now, the mount refuses a zero count or a root past it and probes the last claimed block, and
  every extent is gated against the block count before allocating.
- **The logical block size was never read** - 2048 was assumed. A legal 512- or 1024-byte volume
  mounted and read garbage from wrong positions. Refused at mount: the recorded assumption became a
  gate.
- **Multi-extent files were not detected**, so such a file read back silently truncated to its first
  extent. Refused rather than served short.
- Listing contract fixes: empty-named records are skipped, directories report size zero, and the
  special records carry the names `.` and `..` so paths through them work the same way they do on the
  FAT backend.
