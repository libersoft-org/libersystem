# P02M0185 - A bounded event and timestamp vocabulary, and the MIDI wire over it

Status: OPEN. It closes when every item below is done, and not before.

**AUDIOSERVICE CARRIES PCM AND THIS IS NOT PCM.** P02M0099's USB MIDI item keeps MIDI routing
outside AudioService's PCM stream, and the reason is not tidiness: a PCM stream is a continuous
flow whose correctness is a rate, and a MIDI stream is discrete events whose correctness is ORDER
and TIME. A service built for the first delivers the second late, reordered, or coalesced, and
every one of those is a wrong note.

**AND THE VOCABULARY IS THE PART THAT DOES NOT EXIST.** The item says so: the shared bounded
event/timestamp vocabulary it names does not exist. That vocabulary is not MIDI's - it is what any
source of timed, ordered, bounded events needs - and building it inside the MIDI driver would give
it MIDI's shape.

**AND IT EXISTS BECAUSE THE OWNER SAID SO (2026-09-21)**, answering P02M0099's question about the
nine unowned destinations.

## The shape

- [ ] A bounded event/timestamp vocabulary, separate from any transport: an event is a bounded
  payload, a monotonic timestamp and a source identity, and a queue of them has a declared depth and
  a stated behaviour when it is full. STATED, because "what happens when the queue fills" is the
  only question that matters and the one such vocabularies usually leave out.
- [ ] A typed `liber:midi@1` over it: endpoints, cable and group identity preserved, ordering
  preserved, SysEx with a declared size cap, and malformed packets refused rather than
  reinterpreted.
- [ ] MIDI 1.0 EVENT PACKETS FIRST AND UMP ONLY AFTER THE VOCABULARY IS IN, which is the order the
  driver item asks for and the reason this milestone exists at all.
- [ ] Host tests over the packet decode, the ordering guarantees and the SysEx bounds, with the
  malformed and truncated cases.
- [ ] A guest gate over the observable effect, registered in the verification model in the same
  change.

## Definition of done

Done when the event vocabulary exists independently of MIDI and something other than MIDI could
use it; when a client holding a MIDI endpoint capability receives events in order with their
timestamps and cable identity intact; when queue-full behaviour is declared and tested rather than
discovered; and when the host tests and the guest gate land with the code.

## What it unblocks

P02M0099's **USB MIDI**.
