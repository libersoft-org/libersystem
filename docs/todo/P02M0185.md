# P02M0185 - A bounded event and timestamp vocabulary, and the MIDI wire over it

Status: OPEN. It closes when every item below is done, and not before.

This owns the transport-independent vocabulary and minimal MIDI endpoint service required before
P02M0099's USB MIDI driver work, as requested by the owner on 2026-09-21. Ordered timed events
stay outside AudioService's PCM stream. It does not introduce a general event broker, MIDI routing
daemon, sequencer or output scheduler. A deterministic producer proves the serving path before
USB transport exists.

## P02M0185a - Shared vocabulary and serving arrangement

- [ ] Add `src/idl/event.lsidl` (`liber:event@1`) for bounded source identity, event sequence,
  timestamp and terminal/discontinuity records, with generated runtime-free wire types. Put
  reusable queue/sequence decisions in `service-logic::bounded_event`; they must depend on
  neither MIDI types nor `rt`/IPC. A non-MIDI unit fixture instantiates the same vocabulary and
  bounded queue, proving reuse without building another service.
- [ ] Add `src/idl/midi.lsidl` (`liber:midi@1`) and a separate versioned `midi-device.lsidl`
  contract, their generated clients/bindings, and a minimal `midi_service` binary in the existing
  services crate. Add manifest source/program/service/dependencies, build inputs, `SERVE`,
  private `ADMIN` and `CATALOGUE` bootstrap roles. Append positional roles and update all affected
  launchers/harnesses. There is one service with endpoint queues, not a new generic broker.
- [ ] The initial supported direction is MIDI 1.0 receive. Public enumeration reports protocol,
  direction and bounded endpoint/cable metadata. Opening output or UMP returns typed unsupported;
  no output operation is silently accepted. Preserve cable identity as 0..15. Group is absent
  for MIDI 1.0, not a fabricated group zero. UMP parsing/group semantics and USB transmit are
  later P02M0099 work after this vocabulary exists, with explicit API version/capability additions.
- [ ] Add `midi` to device IDL, driver-protocol constants, system-manifest kind mapping,
  DeviceManager conversions and generated registries. Allocate an unused append-only value
  alongside P02M0180-P02M0188. Subscribe continuously, open per-consumer channels and process
  withdrawals. Admit at most four providers, eight receive endpoints/provider, one receiver per
  endpoint and 32 public connections. A second receiver returns busy; there is no fan-out policy.
- [ ] PermissionManager receives a private MIDI-admin factory from ServiceManager and, only for
  an explicit `midi-input` grant, mints a receiver scoped to one live provider publication and
  endpoint. Inventory access alone cannot open input. Add the security vocabulary and launch
  policy; ordinary clients get neither provider nor catalogue access. Connection counts are
  capacity, not authorization. Close, explicit admin revocation or grant endpoint death ends
  that receiver; device replacement requires a fresh grant.
- [ ] Mint each input grant with a `WAIT | TRANSFER` observer of its exact prepared client
  task using PermissionManager's existing `grant_for_task` mechanism. Owner termination retires
  the receiver even if its endpoint was duplicated/transferred; watch the task independently of
  channel closure and grant no task-management rights. Failed prepared launches revoke the grant
  and release its bounded receiver slot through the same cleanup path.
- [ ] The producer wire negotiates protocol/bounds, lists endpoints, opens/stops receive,
  delivers bounded batches and reports source loss/discontinuity. Its first encoding is a batch
  of at most 64 USB-MIDI 1.0 event packets plus host-receipt time and endpoint identity. Raw
  packets stop at the service's transport adapter; public clients see typed MIDI chunks over
  the generic event envelope. Stage the pure decoder in the existing host-testable driver
  library; MidiService uses that same decoder through the library, with no hardware access.
  P02M0099 later owns USB descriptors, interface/endpoint binding, transfers and unplug detection.
- [ ] Bound catalogue subscriptions/connections for the manifest's actual combined service set,
  including the other new destinations; eight shared client slots are insufficient. Keep finite
  admission/refusal and test reclaiming slots after failed opens and disconnects.

- [ ] Reuse P02M0180's shared catalogue infrastructure stage: private
  `provider-catalogue-admin.open-consumer(kinds)`, held only by ServiceManager, mints this
  service's kind-scoped catalogue connection. DeviceManager checks the actual publication
  kind/generation on both subscribe and open. This depends on that infrastructure stage, not
  completion of Bluetooth functionality. Use its bounded 32-client/subscriber admission and
  combined manifest-budget check; do not duplicate its factory or rely on an unchecked filter.

## P02M0185b - Time, identity and order

- [ ] The shared timestamp is host monotonic nanoseconds since boot from `clock_ns()`, with
  semantics identifying host receipt. The producer samples when a transport completion/batch
  becomes available, before enqueueing; all packets in that completion may share a timestamp.
  Preserve the sampled value through decoder, queues and delayed reads. Never substitute
  `clock()` ticks or TimeService wall-clock seconds. Endpoints across reboot are different
  lifetimes, so their timestamps must not be compared as one timeline.
- [ ] USB MIDI 1.0 supplies cable/CIN and MIDI bytes, not device timestamps. The API therefore
  promises host receipt time, not original performance time. If a later producer supplies device
  timing, it needs a separately qualified clock-domain/unit field and explicit validity; it
  cannot overwrite the host timestamp. See [USB-IF MIDI 1.0, section 4](https://www.usb.org/sites/default/files/midi10.pdf#page=16).
- [ ] Guarantee transport observation order within one endpoint across all its cables. Assign
  event sequence in packet order and retain stable order at equal timestamps; never sort by
  timestamp. Distinct endpoints are independent and are not merged. A batch cannot reorder
  cables; any raw-byte subdivisions stay at their original position. Sequence exhaustion ends
  the endpoint rather than wrapping into a previous sequence.
- [ ] Source identity contains service incarnation, catalogue publication/binding generation,
  endpoint identity and receiver generation. Cable is an additional field, not the source's
  lifetime. A withdrawn/reused slot cannot resurrect queued events from the old connection.

## P02M0185c - MIDI chunks and bounded SysEx state

- [ ] Use explicit fragment delivery, not unbounded complete-message assembly. A MIDI event
  carries up to three MIDI bytes and a typed kind: complete short message, SysEx start,
  continuation, end, or raw-byte chunk. SysEx fragments include a per-cable message generation
  and start/end flags, including a single start+end fragment. The shared vocabulary itself
  permits at most 64 payload bytes; MIDI's smaller bound is enforced by its adapter.
- [ ] Validate four-byte USB packet alignment, cable range/advertised membership, CIN length,
  padding and status/data consistency before emitting. Reserved or unsupported encodings return
  a typed protocol fault, never reinterpret bytes as another message. Support the standard
  single-byte CIN form as raw-byte chunks as well as parsed packets; apply the same SysEx
  start/end/count tracking to both forms. Do not assume every CIN single-byte packet is realtime.
- [ ] Track one bounded state per source/endpoint/cable, at most 16 cable states/endpoint.
  SysEx's whole-message cap is 64 kB including delimiters across all fragments, with checked
  accumulation and a two-second inactivity deadline. Retain counters and minimal parser state,
  not assembled message payloads. MIDI realtime bytes pass in original order without terminating
  or counting toward a SysEx payload. Consumer documentation requires treating fragments as
  incomplete until the matching end and respecting explicit aborts.
- [ ] On cap crossing, malformed continuation, interrupted non-realtime message, inactivity or
  reset, abort the partial SysEx and report its message identity/reason. Discard invalid remainder
  until an end or fresh valid start; preserve realtime events. A new start first aborts an old
  incomplete message. Unknown/malformed bytes never turn a truncated message into a successful
  end. Disconnect discards all partial state. Consumers can recover at a new message boundary.
- [ ] For malformed transport packets whose affected cable cannot be identified, reset all
  partial cable states and expose a source discontinuity. For a known cable, reset only that
  cable. Bound abort/error records in the same event accounting as data. If integrity metadata
  cannot be queued, terminate the receiver as specified below rather than silently lose it.

## P02M0185d - Queue integrity and endpoint lifetime

- [ ] Each receiver has a fixed 256-event queue and at most 32 kB encoded queue storage,
  including event envelopes and integrity records; admission checks both limits. Across the
  maximum 32 endpoints this is at most 1 MB queue storage, plus explicitly bounded batch and
  cable-state storage. There is no allocation proportional to the total length of a SysEx.
- [ ] On queue saturation, stop that receiver, discard its queued/partial data and retain a
  terminal `overflow` state outside the full queue. The next read/status returns that reason;
  no dropped event sequence may appear continuous. Opening a new receiver requires an explicit
  action and new generation. A slow endpoint must not block others or the service event loop.
- [ ] Use pull reads over the receiver endpoint and bounded producer batches, not an unbounded
  push channel into the client. Source removal, provider failure, permission loss and service
  shutdown discard queued/partial data and leave a terminal outcome available to pending/next
  reads; abrupt service death is also visible as channel closure. Stop/close frees the bounded
  receiver slot. Revoked/dead source handles never transparently reopen a replacement.
- [ ] If the producer reports that transport input was lost, terminate the affected endpoint
  with `source-discontinuity` rather than claim the surviving stream is complete. Ignore late
  batches with retired provider/receiver generations. On reattachment start fresh identity,
  queue and cable state, with no stale events or unterminated SysEx inherited.

## P02M0185e - Verification and completion

- [ ] Host-test production generic queue and MIDI decoder/state routines: packet/CIN/status
  and truncation errors, interleaved cables, raw-byte mode, realtime inside SysEx, start/end
  variants, cap crossing over many small fragments, timeout/abort and successful recovery.
  Assert retained timestamps under delay, equal-timestamp order, endpoint independence,
  exact/full bounds, terminal outcome under saturation, unplug mid-message and replacement.
  Keep test modules outside production Rust files.
- [ ] Add a test-image-only bounded MIDI producer that implements the real private wire and
  normal catalogue publication/open through a test-only binding/publication harness. It sends
  scripted raw event packets to the production decoder, with deterministic cable/payload/time,
  malformed and oversized sequences, overload and withdrawal/republication. A real granted
  client uses MidiService's public IPC. Do not substitute precomputed public replies or require
  a MIDI gadget absent from the current USB helper.
- [ ] Register `./check.sh --gate qemu-midi-service` with its image/fixture producer,
  finite x86_64 guest run, artifact digest and guest-log evidence in verify-model. Cover new
  service/wires, generic queue, decoder, grant/bootstrap and catalogue integration. The gate
  proves IPC/queue behavior; USB transfer and UMP coverage belong to the later driver gate.
- [ ] Guest assertions check exact bytes/cables, fragment identity/boundaries, receipt timestamps
  and equal-time ordering after delayed consumption; ordinary-access denial and explicit
  output/UMP unsupported results; saturation with a readable terminal reason; unplug during
  SysEx and reattachment without stale events. Test independent endpoints and slot reclamation.
  Run focused host tests, generated-binding/manifest checks and all three target cross-builds.

- [ ] In the guest authority/cleanup proof, duplicate a granted endpoint before terminating
  its launching task; verify the retained copy cannot continue operations and owned resources
  follow the same bounded teardown. Exercise prepared-launch failure after minting as well.
- [ ] Complete gate registration in `check.sh`, verify-model `GATES`,
  `GATES_THAT_BOOT_A_GUEST`, image inputs/producers and component coverage, plus
  `src/tools/verify-model/model/release-required.toml` and its exact-set regression tests.
  Register fixture/build prerequisites explicitly; a release run must build the right test
  image and execute the gate rather than only recognize its name.

Done when the generic bounded vocabulary is usable independently of MIDI, a granted receive
client gets correctly ordered MIDI 1.0 chunks with host receipt time and cable identity, SysEx
bounds and recovery are enforced across fragments, loss/removal cannot be silent, and registered
host/guest checks pass. This unblocks P02M0099's USB MIDI transport; it does not claim UMP,
transmit scheduling, physical device timing or live USB transport.
