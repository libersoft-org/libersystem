# P02M0138 - PermissionManager changes must select the tests that exercise them

Status: TOOLING. NOT A PHASE-2 COMPLETION GATE.

## Goal

Make a change to `src/user/services/core/src/permission_manager.rs` select the kernel tests whose
assertions can detect a regression in PermissionManager's contract.

The current public plan identifies the changed component as `bin.permission_manager` and emits nine
build keys, but it selects zero kernel tests. The command layer consequently adds an unenumerated
x86_64 full-suite boot whose result cannot be attributed to individual test keys. That is a coverage
correctness failure, not merely a performance problem.

This milestone uses the coverage and selection machinery completed in P02M0118; it does not reopen
or redesign that machinery. It follows P02M0137 in roadmap order but has no technical dependency on
the dynamic-report fix.

## Coverage rule

`covers = ["bin.permission_manager"]` is justified only when the test contains an assertion that can
detect a regression in PermissionManager's contract. Calling `run_permission_scenario` or launching
the binary is not sufficient.

Every new declaration therefore needs a watched-fail probe: make one narrow temporary production
mutation, prove that the intended assertion fails for the intended reason, then restore the mutation.
A boot failure, missing artifact, unrelated panic, timeout or parser failure is not evidence that the
assertion covers PermissionManager.

## Scope

This milestone owns only the twelve declarations above, focused PermissionManager mutation probes,
and verify-model regression coverage for this source path. It does not change the permission fixture,
test IDs, tags, assertions unrelated to a broken oracle, planner algorithms, cost models, history,
QEMU instrumentation, calibration or evidence infrastructure.

- [ ] **M1.1 - Reproduce and freeze the coverage gap.**
  - Save the current JSON plan and lowered commands for
    `src/user/services/core/src/permission_manager.rs`.
  - Assert the current diagnostic shape: owner `bin.permission_manager`, non-FULL plan, nine build
    keys, zero kernel-test keys, no warning, and one unenumerated x86_64 guest step.
  - Record the twelve candidate IDs, their tags and their complete original `covers` arrays.
  - Add a source-level inventory test that fails if a caller is added, removed or silently changes
    its stable ID before the mapping decision is updated.

- [ ] **M1.2 - Prove each proposed coverage edge by watched failure.**
  - Define a small mutation matrix over the actual PermissionManager behaviors asserted here:
    static grants and denials, dynamic requests, minimal tool grants, governed pipeline launch and
    routing, and process-bound display/input/audio grants.
  - Each mutation changes one production decision, keeps the service bootable, and names the exact
    assertion expected to fail.
  - Run the relevant candidate test alone, require that assertion to fail, restore the mutation, and
    require the same test to pass.
  - Record `include` or `exclude` for every candidate. An exclusion names why the assertion belongs
    to another component contract; execution reach alone never upgrades it to `include`.

- [ ] **M1.3 - Update only evidence-backed coverage declarations.**
  - Add `bin.permission_manager` to every candidate classified `include` and to no candidate
    classified `exclude`.
  - Preserve every existing `covers` entry, stable ID, tag and valid assertion.
  - If a mandatory direct policy test did not catch its intended focused mutation, fix that test's
    oracle first and repeat the probe.
  - Keep the final selected ID set explicit in the verify-model regression rather than deriving it
    from function names or from all tests that happen to call the helper.

- [ ] **M1.4 - Make the real planner regression fail on the old behavior.**
  - A plan for the PermissionManager source path remains scoped and preserves the existing target
    policy, but contains the exact evidence-backed x86_64 kernel-test keys.
  - Lowering emits one `TEST_SELECTION=<stable IDs> ./test.sh --arch x86_64` step, never the
    unenumerated full-suite fallback.
  - The regression rejects zero selected tests, an unknown ID, an omitted included ID, an added
    excluded ID and a generic full-suite command with no attributable keys.
  - An unrelated component change does not acquire the PermissionManager test set merely because it
    reaches the same kernel helper.

- [ ] **M1.5 - Exercise the selected tests through the public workflow.**
  - Run the focused verify-model tests and its self-check.
  - Inspect the public JSON plan and lowered command for the PermissionManager path.
  - Run that public workflow on x86_64 and require every selected stable ID to execute and pass.
  - Repeat one focused watched-fail probe through the public workflow so the planner regression is
    proven to select a test that detects the production defect.
  - Leave no temporary production mutation or test artifact in the working tree.

## Definition of done

- Every one of the twelve candidates has a recorded watched-fail inclusion decision.
- Every modified `covers` array is a strict superset of its original declaration; excluded
  candidates remain byte-identical.
- A PermissionManager source change selects a nonempty, exact, attributable test set.
- The old zero-test and unenumerated-full-suite result is a regression failure.
- No fixture, planner heuristic, cost model or history behavior changed.
- These commands pass from the repository root:

```sh
(cd src && cargo test --quiet --manifest-path tools/verify-model/Cargo.toml)
(cd src && cargo run --quiet --manifest-path tools/verify-model/Cargo.toml -- check)
./verify.sh --for src/user/services/core/src/permission_manager.rs --plan --json
./verify.sh --for src/user/services/core/src/permission_manager.rs --allow-shadow
./check.sh --gate test-tags,verify-model,verify-model-tests
git diff --check
```
