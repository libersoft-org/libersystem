# P02M0140 - Retire `just`: one way to run things, and it is a script with flags

Status: COMPLETE (2026-08-19). TOOLING. NOT A PHASE-2 COMPLETION GATE.

## Goal

Remove `just` from the repository. Every recipe becomes a shell script at the repository root taking
flags, the way `build.sh`, `check.sh`, `test.sh`, `run.sh` and `verify.sh` already do.

This is a decision about how the project is driven, not a cleanup of an untidy file. The tree
already has fifteen root scripts with a consistent shape - `./build.sh --arch x86_64 --part libs`,
`./check.sh --gate NAME`, `./test.sh --arch x86_64 --tags service` - and beside them a second,
different way to run things that needs a tool nobody has by default, lives in `src/` rather than the
root, and takes its arguments positionally. One of the two has to go, and the one that goes is the
one that is not already how most of the tree works.

## What is there now

Measured on 2026-08-19:

- 24 recipes in `src/Justfile`: 23 named plus `lab *args`, which forwards to `boot/lab.py`.
  **Corrected in M1.1 to 30**: the pattern used here missed the two recipes with default parameter
  values, `fast-path-check target="x86_64"` and `shared-cache-check mode="quick"`, and four others.
- `just lab` has 12 subcommands of its own: `boot`, `int`, `key`, `log`, `monitor`, `pcap`, `quit`,
  `dev-up`, `dev-down`, `dev-log`, `dev-status`, `dev-rollback`.
  **Corrected in M1.1 to 33**, read from `boot/lab.py --help` rather than from memory. The twenty
  `dev-*` ones already have a root script of their own - `./dev.sh` - which this section did not
  know about either.
- 103 files reference a recipe. 64 of them are generated Rust files whose header says
  ``@generated by lsidl-gen. Do not edit; run `just gen`.`` - so the GENERATOR emits the instruction
  and has to be changed, not just the files it wrote.
- The rest are documentation, milestone records, error messages inside scripts and the `Justfile`
  itself.

## The shape to land on

Every replacement is a root script taking flags, discoverable with `--help`, and named for the thing
it does rather than for the recipe it replaces. Where an existing script already owns the concern,
the recipe becomes a flag on that script instead of a new file - a sixteenth script that does what
`check.sh` does would be the same mistake in a new place.

A proposed mapping, to be settled in M1.1 rather than assumed here:

| recipe | proposed |
| --- | --- |
| `gen`, `gen-check`, `gen-accept-breaking` | `./gen.sh [--check] [--accept-breaking]` |
| `dynamic-report-update` | `./check.sh --refresh dynamic-report` |
| `source-hygiene`, `source-history-hygiene`, `test-tags-check`, `perf-gate`, `shared-libs-verify` | `./check.sh --gate NAME` (several already exist there) |
| `app-libs-test`, `bootproto-host-test`, `services-host-test`, `fs-host-test` | `./check.sh --host-suite NAME` |
| `test-all`, `test-smp-checkpoint` | `./test.sh` flags |
| `loader-aarch64`, `loader-riscv64` | `./build.sh --arch ARCH --part loader` |
| `debug`, `gdb` | `./run.sh` flags |
| `audio-bench`, `image-bench`, `image-mutate` | `./image.sh` flags and a bench script |
| `lab *args` | `./lab.sh SUBCOMMAND` |
| `default` | disappears; `--help` on each script replaces it |

## Scope

This milestone owns the recipes, their replacements, every reference to them in scripts,
documentation and generated-file headers, and the removal of `src/Justfile`. It does not own what
the recipes DO: a replacement runs the same commands with the same arguments, and a behaviour change
smuggled in beside a rename is the thing that makes a migration like this untrustworthy.

### M1.1 - the inventory, frozen, and what it found (2026-08-19)

**Thirty recipes, not twenty-four.** The count in "What is there now" above was taken with a pattern
that missed the two recipes with default parameter values (`fast-path-check target="x86_64"` and
`shared-cache-check mode="quick"`). Corrected here rather than left, because the whole point of
freezing an inventory is that the number is the number.

**Three recipes and two scripts name things that do not exist.** This is the argument for the
milestone, found by doing the inventory rather than assumed by writing it:

- `src/tools/check-fast-path-parity.sh` runs `just shared-libs`, `just shared-libs-aarch64` and
  `just shared-libs-riscv64`. **None of those recipes exists.** `just --dry-run shared-libs` answers
  "justfile does not contain recipe `shared-libs`". The only caller of that script is the
  `fast-path-check` recipe, which nothing calls, so the breakage has never been reported by anything.
- `src/tools/measure-dev-baseline.sh` runs `just shared-libs` for the same non-existent recipe.
- `src/wasm/src/world/tests.rs`, `src/tools/check-host-tests.sh`, `src/user/services/core/*` and

  `src/tools/mkpackages/src/main.rs` name `just img`. Neither recipe exists either.

A tree that instructs its reader to run six commands that are not there is not a tidiness problem.
It is what happens when the instructions and the thing they instruct about are kept in different
places, which is the same reason this milestone exists.

**The four host-test recipes are deleted, and the evidence is that they are strict subsets.**
`./check.sh --gate host-tests` enumerates every crate in the tree containing a `#[test]` from
`verify-model host-suites` - 67 (crate, configuration) pairs - and runs them all. Checked against
that list rather than assumed:

- `app-libs-test`'s 28 crates: all 28 appear in the enumeration.
- `bootproto-host-test`'s one crate: `src/bootproto` appears.
- `fs-host-test`'s six: `liberfs`, `libermemfs`, `fat`, `iso9660` and `udf` appear. The sixth,
  `src/fs/core`, contains **zero** `#[test]`, so that line has never run a test.
- `services-host-test`'s one crate resolves to `src/user/services/core`, which also contains **zero**
  `#[test]`. The services crate with tests is `src/user/services/logic`, and the enumeration has it.

So all four run a subset of what the gate runs, two of them include a line that runs nothing, and the
`--target x86_64-unknown-linux-gnu` they pass is what the gate gets by running from `src/` instead -
which `check-host-tests.sh` states as the reason it runs from there.

**What stays as it is.** `boot/lab.py`'s twelve subcommands are not touched: they are a Python
program's own interface, reached through `./lab.sh` instead of through `just lab`, and renaming them
would be a change to the thing rather than to how it is invoked.


### M1.2 - the replacements, and the diff that proves each one (2026-08-19)

**Three new root scripts.** `gen.sh` (the sixteen-package generator table, three modes),
`lab.sh` (the live-guest subcommands) and `bench.sh` (the three optimized host runs). Each answers
`--help`, each has a `--list`, and each refuses an unknown flag with status 1 - checked, not
asserted.

**Four existing scripts gained flags.** `check.sh` gained `--refresh NAME`, `--staged-image [T...]`,
`--cache-check MODE` and `--fast-path [T] [A...]`, plus two gates (`source-hygiene`,
`source-history-hygiene`); `run.sh` gained `--gdb`; `build.sh` absorbed the two loader recipes.
The argument-taking checks are deliberately NOT in the default set, for the same reason
`--conformance` is not: each rebuilds or re-stages something, and `./check.sh` with no arguments has
to stay the thing a person runs to find out whether the tree is sound.

**Equivalence was measured, not read.** Two harnesses, both throwaway:

- For `gen`, `gen-check` and `gen-accept-breaking`: `just --dry-run` on one side, `./gen.sh
  --dry-run` on the other, normalised for `$out` substitution and diffed. **32, 16 and 32 lines,
  byte-identical.**
- For everything else: the script each side ends in was replaced by a stub that prints its own name
  and arguments, both sides were RUN, and the outputs diffed.

**Two are NOT command-line identical, and that is stated rather than smuggled.**

- `test-all` ran `boot/check-test-tags.sh` then `boot/test-all.sh`, which called `boot/test-kernel.sh
  <arch>` three times with no preflight and no `UEFI=1`. `./test.sh --arch all` runs the tags check
  itself, verifies the build matches the sources, checks the staged image, runs the preflight, and
  passes `UEFI=1` on the two device-tree architectures - which `test.sh`'s own comment says they have
  no other way in without. So the recipe was not a shorter spelling of the supported path; it was an
  older one that had drifted from it. `boot/test-all.sh` had exactly one caller - that recipe - and
  is deleted with it.
- `test-smp-checkpoint` ran `SMP=$(nproc) boot/test-kernel.sh x86_64 smp`. `./test.sh --arch x86_64

  arguments, after the same preflight every other test run gets.

by diffing: `loader-aarch64`, `loader-riscv64` and `shared-libs-verify` become `./build.sh --arch

`LIBER_IMAGE_REBUILD=1` the recipe set by hand.

**The generator emits `./gen.sh` now.** `lsidl-gen` wrote ``Do not edit; run `just gen`.`` into every
generated Rust file and every generated reference page. Changed in `main.rs` and `codegen.rs`,

**176 references rewritten across 26 files** - `boot/lab.py` alone had 72 - plus the documentation
sweep below. Milestone records under `docs/todo` are left alone on purpose: they are what was true
when they were written, and rewriting them would make the history say something that did not happen.

**The documentation named far more commands that were already gone.** `docs/DEBUG.md`,

script and flag that does the thing, and the `dev-*` ones name `./dev.sh`, which is the script that
already owned them.

**`./lab.sh` refuses `dev-*` rather than forwarding it.** `boot/lab.py` answers both `dev-up` and
`up`, so `./lab.sh dev-up` would have worked - and would have been a second spelling of a command

differed only in `LIBER_IMAGE_REBUILD=1`, which is what `--rebuild` is - because collapsing them
would have made the warm measurement measure a cold build.


### M1.4 - deleted, and what "prove nothing needed it" turned up (2026-08-19)

`src/Justfile` is gone. So is `src/boot/test-all.sh`: its only caller was the `test-all` recipe, and
it invoked `boot/test-kernel.sh <arch>` with no preflight and no `UEFI=1` - not the invocation the
supported path has made since those were added. `setup.sh` no longer installs `just` and no longer
lists it among what it installed; `format.sh` no longer has a `just --fmt` branch; `lab.py`'s
build-input list and `verify-model`'s ownership registry name the root scripts instead.

**`build.sh` was the last thing in the build path that needed it.** `step_loader` ran `just
"loader-$arch"` for aarch64 and riscv64 - so `./build.sh --arch riscv64 --part loader`, a root
script, could not run without the tool this milestone is removing. The aarch64 line is one `cargo
build`; the riscv64 recipe was a bash program with its own shebang inside a Justfile, and it is
`src/tools/build-loader-riscv64.sh` now.

**Moving it there found a defect the gates could not see.** `source-hygiene` rejects a script using
`pipefail` that pipes into a reader which can stop early, and the recipe had two of them:
`llvm-readelf -s "$out" | awk '/_pe_image_end/{...; exit}' || true`. `awk`'s `exit` closes the pipe,
so `llvm-readelf` takes a SIGPIPE and the pipeline fails on SUCCESS - and the `|| true` that hides
that also hides a readelf which genuinely failed, leaving an empty answer either way. The gate never
saw it because it scans scripts and a recipe is not one. Both reads go through a `read_elf` helper
now, into a variable, with no pipe at all.

**Proven with `just` unavailable**, by a shim first on `PATH` that prints `NO-JUST: something invoked
'just ...'` and exits 127. All four Definition-of-Done commands pass and none of them printed it:

| command | result |
| --- | --- |
| `./check.sh` | exit 0, every gate and all eleven conformance suites |
| `./build.sh --arch all` | exit 0, three architectures |
| `./test.sh --arch x86_64` | exit 0, 270 passed |
| `git diff --check` | exit 0 |

Three things had to be repaired to get there, each of them a pre-existing failure this milestone
merely stood in front of:

- **`frame-retirement` was red** on `mem/heap/mod.rs:129`, a `frame::deallocate` whose comment gave
  exactly the required reason in the wrong words. The gate wants `NEVER-MAPPED: <why>`; the line now
  says it.
- **`git diff --check` reported 223 findings** in `src/wasm/tests/spec-run-cases.tsv`. The trailing
  tab on those rows is a COLUMN - an assertion whose function returns nothing - and it is in both the
  old and the new file; regenerating the fixture whole (P02M0134) is what made a long-standing
  property visible all at once. `.gitattributes` says that file's whitespace is content.
- **The dynamic report had drifted**, which is what `--refresh dynamic-report` is for and the first
  real use of the flag this milestone added. Regenerated after all three architectures were built,
  in that order, for the reason P02M0137 records.

**One thing the migration exposed and did not fix**: a comment-only change to a shared library's
source rebuilds it, produces an identical object, and leaves its CONSUMERS carrying the previous
provider identity - so `mkpackages` refuses with "audio-proto identity provider chain" and a plain
rebuild does not converge. `./build.sh --part libs --rebuild` clears it. It fails loudly rather than
silently, so it is a usability defect in the shared-library cache rather than a correctness one, and
it belongs to whoever owns that cache.
