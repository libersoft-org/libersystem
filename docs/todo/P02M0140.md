# P02M0140 - Retire `just`: one way to run things, and it is a script with flags

Status: TOOLING. NOT A PHASE-2 COMPLETION GATE.

## Goal

Remove `just` from the repository. Every recipe becomes a shell script at the repository root taking
flags, the way `build.sh`, `check.sh`, `test.sh`, `run.sh` and `verify.sh` already do.

This is a decision about how the project is driven, not a cleanup of an untidy file. The tree
already has fifteen root scripts with a consistent shape - `./build.sh --arch x86_64 --part libs`,
`./check.sh --gate NAME`, `./test.sh --arch x86_64 --tags service` - and beside them a second,
different way to run things that needs a tool nobody has by default, lives in `src/` rather than the
root, and takes its arguments positionally. One of the two has to go, and the one that goes is the
one that is not already how most of the tree works.

## What is there now

Measured on 2026-08-19:

- 24 recipes in `src/Justfile`: 23 named plus `lab *args`, which forwards to `boot/lab.py`.
- `just lab` has 12 subcommands of its own: `boot`, `int`, `key`, `log`, `monitor`, `pcap`, `quit`,
  `dev-up`, `dev-down`, `dev-log`, `dev-status`, `dev-rollback`.
- 103 files reference a recipe. 64 of them are generated Rust files whose header says
  ``@generated by lsidl-gen. Do not edit; run `just gen`.`` - so the GENERATOR emits the instruction
  and has to be changed, not just the files it wrote.
- The rest are documentation, milestone records, error messages inside scripts and the `Justfile`
  itself.

## The shape to land on

Every replacement is a root script taking flags, discoverable with `--help`, and named for the thing
it does rather than for the recipe it replaces. Where an existing script already owns the concern,
the recipe becomes a flag on that script instead of a new file - a sixteenth script that does what
`check.sh` does would be the same mistake in a new place.

A proposed mapping, to be settled in M1.1 rather than assumed here:

| recipe | proposed |
| --- | --- |
| `gen`, `gen-check`, `gen-accept-breaking` | `./gen.sh [--check] [--accept-breaking]` |
| `dynamic-report-update` | `./check.sh --refresh dynamic-report` |
| `source-hygiene`, `source-history-hygiene`, `test-tags-check`, `perf-gate`, `shared-libs-verify` | `./check.sh --gate NAME` (several already exist there) |
| `app-libs-test`, `bootproto-host-test`, `services-host-test`, `fs-host-test` | `./check.sh --host-suite NAME` |
| `test-all`, `test-smp-checkpoint` | `./test.sh` flags |
| `loader-aarch64`, `loader-riscv64` | `./build.sh --arch ARCH --part loader` |
| `debug`, `gdb` | `./run.sh` flags |
| `audio-bench`, `image-bench`, `image-mutate` | `./image.sh` flags and a bench script |
| `lab *args` | `./lab.sh SUBCOMMAND` |
| `default` | disappears; `--help` on each script replaces it |

## Scope

This milestone owns the recipes, their replacements, every reference to them in scripts,
documentation and generated-file headers, and the removal of `src/Justfile`. It does not own what
the recipes DO: a replacement runs the same commands with the same arguments, and a behaviour change
smuggled in beside a rename is the thing that makes a migration like this untrustworthy.

## Work

- [ ] **M1.1 - Freeze the inventory and settle the mapping.**
  - Record every recipe, what it runs, and who calls it. The `lab` subcommands count individually.
  - Decide each destination against the rule above: an existing script's flag where the concern
    already lives there, a new root script otherwise. Record the decision per recipe, including the
    ones that become nothing.
  - A recipe nobody calls and no document mentions is a candidate for deletion rather than
    translation; say so explicitly rather than porting it out of politeness.

- [ ] **M1.2 - Write the replacements, one recipe at a time, proving equivalence.**
  - Each replacement runs the same command line the recipe ran. Diff the two invocations rather than
    reading them: run the recipe, run the replacement, and compare what each executed.
  - Every new or extended script answers `--help` with its flags, and refuses an unknown flag with
    a nonzero status rather than ignoring it.
  - Keep the `Justfile` working throughout, so the tree is never half-migrated at a commit boundary.

- [ ] **M1.3 - Move the references, including the ones a generator writes.**
  - `lsidl-gen` emits ``run `just gen``` into 64 generated files; change the generator, regenerate,
    and confirm `gen-check` (or its replacement) reports no drift.
  - Update documentation, milestone records that describe a live command, and every error message
    inside a script that tells a reader to run a recipe.
  - A search for `just <recipe>` across the tree returns only historical records afterwards.

- [ ] **M1.4 - Delete `src/Justfile` and prove nothing needed it.**
  - Remove the file and `just` from setup documentation and any environment description.
  - `./check.sh` in full, a clean `./build.sh --arch all`, and the guest suite pass with `just`
    unavailable on PATH - which is the only check that finds a call nobody grepped for.

## Definition of done

- `src/Justfile` is gone and no script, document or generated file names a recipe as a live command.
- Every replacement takes flags, answers `--help`, and refuses an unknown flag.
- Each recipe's replacement was shown to run the same command, per recipe, rather than by
  inspection.
- These pass from the repository root with `just` not installed:

```sh
./check.sh
./build.sh --arch all
./test.sh --arch x86_64
git diff --check
```
