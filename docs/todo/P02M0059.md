# P02M0059 - FAT: second-pass findings (the sector-size read bug and the leftovers)

Status: COMPLETE. The second full source pass (2026-07-04).

**The one that mattered: double ratio scaling on the read path.** `cluster_lba` returned a device LBA
and the 512-byte expansion was then applied again. It is `cluster_fs_sector` now - it returns the
filesystem's logical sector and the expansion happens exactly once, inside the read and write
helpers, so there is one place it can be wrong.

*Condensed 2026-08-08.*

- **A hostile NoFatChain `size` was unbounded.** `nfc_run` bounds every such length off the medium: a
  run that would leave the cluster heap is refused.
- **A generated short name could begin with 0xE5**, which marks a deleted entry. It is stored as 0x05
  per the spec and mapped back on read.
- **A new entry set could land after the 0x00 terminator**, where the parser never looks. Everything
  from the first terminator is zeroed before the slot search.
- **Names of only dots, or with trailing dots or spaces**, were accepted; refused now through one
  gate for both families.
