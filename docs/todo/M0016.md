# M0016 - StorageService over a ramdisk + `vol://` access

Status: COMPLETE. A userspace client opens a path on a `vol://` volume through StorageService and
reads its contents over a channel.

*Condensed 2026-08-08.*

**The object is canonical and the URI is a representation.** A `VolumePath` parses `vol://<volume>/<path>`
into its `(volume, path)` pair, and that pair is what everything downstream uses.

The ramdisk is a second boot module in the same `PKGARCH1` archive format as the init package,
assembled from the source volume directory. The kernel copies it into a `MemoryObject` and hands that
object plus the channels to the service.

The read is zero-copy in the sense that matters: the service copies the file into a fresh
`MemoryObject` and **attenuates the handle to exactly the rights the request may have** before
transferring it - so the client receives memory it can read and nothing more, rather than a copy over
the channel.

The service refuses anything beyond read and map on a read-only volume, which is the first place the
volume's own policy and the capability's rights had to agree.
