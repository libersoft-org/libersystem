# M0127 - Userspace source and system-volume layout cleanup

Status: DONE (2026-07-25).

A mechanical ownership and layout migration, deliberately containing no source-level API refactor.
`src/user/` had grown from a few peer crates into runtimes, services, drivers, applications and
atomized libraries while still exposing every crate root in one flat list; the factory system volume
had the same debt, with `app.wasm`, text files and every fixture loose in its root.

*Condensed 2026-08-08. The step-by-step migration plan is gone - the tree is its own record. What
follows is the layout it settled on and the rules that keep it that way.*

## Source layout: five roles

All 73 crates live under `src/user/{runtime,services,drivers,apps,libs}/`. A repository check fails
if a Cargo crate sits directly under `src/user/`, if an old path survives, or if two physical paths
claim the same logical artifact.

Libraries are classified by **owning domain**, not by convenience: `libs/audio/`, `libs/image/`,
`libs/compression/`, `libs/protocol/`, `libs/clients/`, `libs/input/`, `libs/terminal/`, `libs/ipc/`,
`libs/display/`. The same categories are mirrored under `vol://system/lib/`, so `libs/audio/mp3/`
stages as `lib/audio/mp3.lslib`.

**A physical directory is not an identity.** Cargo package names, prefix-free `.lslib` SONAMEs,
`DT_NEEDED`, manifest logical owners and generated protocol identities are all unchanged by where a
crate sits. A new leaf declares exactly one category; moving a leaf between categories changes no
runtime ABI and no dependency edge.

Build outputs are all under the repository-root `.build/`: Cargo under `.build/cargo/<owner>/`,
boot and QEMU state under `.build/boot/`, staged images under `.build/image/<target>/`.

## Volume layout, and the Unix hierarchy that was deliberately not imported

`vol://system` root contains only `hello.txt`, `motd.txt` and the declared directories:

| directory | holds |
|---|---|
| `bin/` | user-invoked `.lsexe` tools. A suite with private files owns a subdirectory (`bin/lico/…`) |
| `libexec/` | volume-loaded services and internal helpers users do not invoke; one owning a state file gets a subdirectory (`libexec/config_service/{config_service.lsexe,config.tree}`) |
| `lib/` | canonical `.lslib` shared libraries, in their categories |
| `drivers/` | non-bootstrap driver executables |
| `components/` | non-native Wasm/component payloads |
| `log/` | only the machine-wide structured journal, owned by LogService |
| `audio/`, `wallpapers/` | the factory demonstration files |

**There is deliberately no `etc/`, `var/` or `share/`.** Configuration and non-system logs belong to
the program that owns them and live beside its binary; the machine-wide journal is the one exception.
The manifest maps a logical command name to its exact path, so an application subdirectory never
leaks into the command spelling.

## The manifest is the single source of truth

The positional line protocol was replaced by a typed manifest that declares every destination: 48
command ELFs below `bin/`, 20 internal ELFs below `libexec/`, six drivers, every library category,
the SDK payload at `components/liber_component/app.wasm`, and exactly four factory files.

It rejects undeclared source files, duplicate destinations, role/path drift, root pollution and a
missing SDK payload. Kernel package assembly, the shared-image builder and the standalone
`check-volume-package` audit all read the same destination set, so none of them can disagree.
ProcessService resolves named programs through a generated table from that manifest.

## Two namespaces removed rather than maintained

- The `order/` namespace and generated `.order` sidecars are gone: the provider load order is
  embedded in each executable's own bounded identity record instead of living in a parallel tree.
- The `id/` namespace is gone for the same reason - the record travels with the artifact it
  describes.

Two parallel namespaces that must agree are two chances to disagree; both were removed rather than
gated.
