# P02M0186 - A spool and stream service

Status: COMPLETE (2026-09-24). Every item below is done.

Applications receive a job capability rather than a raw printer endpoint. The service owns job
admission, bounded staging, serialization, status and lifetime. P02M0099 owns USB printer binding,
bulk transfers, class requests and transport recovery. This milestone establishes their contract
and proves the service independently of that deferred driver.

Initially accept already-rendered PostScript. Rendering, discovery UI, vendor maintenance,
persistent spooling and physical-page accounting remain outside scope. This is the service
destination authorized on 2026-09-21.

## P02M0186 - Public job contract

- [x] Add `src/idl/spool.lsidl`, package `liber:spool@1`, with bounded device enumeration/status,
  job creation and a separate job channel. `create(device, language, length)` reserves the declared
  bytes and returns a job capability supporting `write`, `submit`, `status` and `cancel`. Device
  identity includes the complete catalogue binding/provider generation. No operation exposes a
  catalogue, backend, reset or raw endpoint. Status remains available after submission.
- [x] Implement `writing -> queued -> active -> transferred | failed | cancelled` in a pure
  `service-logic` module. Only explicit `submit` makes bytes eligible for transmission, and it
  succeeds only when staged length equals declared length. Repeated submit returns the existing
  state without enqueueing/sending again. Writes after submission are invalid. Refuse zero-length
  jobs and lengths above the advertised maximum before admission.
- [x] Use bounded RAM staging: 4 MB maximum per job, 16 MB reserved job bytes globally, 16 live
  job records, 2 records per granted client, 16 clients and 8 devices. Reserve the full declared
  size at creation with fallible allocation; pressure returns `exhausted` before admitting the job.
  Bound bookkeeping separately and allow one 4096-byte backend frame per active device. Terminal
  jobs release byte reservations immediately; retain their small, still-charged status record
  until the job capability closes. Retire detached terminal records immediately.
- [x] Define application backpressure as bounded admission, separately from device readiness.
  Each public write contains at most 4096 bytes and accepts the whole frame into reserved staging,
  returning that count. It never waits for an unsubmitted job to print. Exceeding declared length
  accepts none of the frame and fails the job with a typed size-limit cause; reject oversized wire
  frames before dispatch. There is no partial public append or staging-cap `again`. Backend writes
  may accept a prefix: advance by exactly the acknowledged count and retain the suffix. Backend
  `again` accepts zero and waits for its outstanding buffer to drain; readiness or bounded timed
  status retry drives progress. Removal/timeout may end that wait. Use a 30-second no-progress
  deadline reset only by accepted bytes, and a 10-minute lifetime measured from submission through
  queued/active states. Stalled devices
  must not block other devices, clients or supervisor heartbeats.
- [x] Channel closure never submits. Closing a writing job aborts and refunds it; closing a
  submitted job detaches the observer while committed work continues within its bounds/deadlines.
  Explicit cancel removes a queued job; active cancellation stops transmission and records the
  acknowledged count and possible partial output. The quota owner is the fresh grant context:
  closing its root cannot release charges for still-live job channels. Process exit closes its
  endpoints; transferred job authority follows the surviving capability, not a numeric PID.
  Service restart loses the ephemeral queue and closes old job capabilities. Missing final status
  means unknown outcome, never success or authorization to replay automatically.

## P02M0186 - Evidence and the private backend

- [x] Separate job state, transport delivery and device observations. Decode standard port bits
  into paper-empty, selected/not-selected and generic-error, with unavailable observations explicit.
  Benign bits do not prove physical readiness. Cover-open and jam are optional details only when
  an identified backend supplies evidence; otherwise report unsupported/unknown detail.
  `transferred` means all bytes were acknowledged by the backend, not a finished physical page.
  Terminal failure/cancellation carries cause, confirmed accepted bytes and whether additional
  delivery is uncertain. Unplug remains a distinct cause after partial delivery. Never replay to
  a replacement generation. This evidence boundary follows
  [USB Printer Class 1.1, sections 3.3 and 4.2](https://www.usb.org/sites/default/files/usbprint11a021811.pdf).
- [x] Use a declared language enum, initially accepting only `postscript`; other formats return
  `unsupported` before admission/transmission. Backend capabilities come from a length-checked
  IEEE 1284 device ID capped at 4096 bytes. Recognize exact case-insensitive `CMD`/`COMMAND SET`
  tokens `POSTSCRIPT`, `POSTSCRIPT2` and `POSTSCRIPT3`; bounded unrecognized tokens are metadata,
  not supported languages. Missing/malformed/ambiguous capability evidence returns `unsupported`.
  There is no raw-language bypass or content sniffing. The client supplies the complete rendered
  document, including language document boundaries. No parser/renderer or language-code sanitizer
  is introduced here.
- [x] Define a private `printer-backend` interface with versioned attach, bounded capabilities,
  port observations, `write` with accepted count, and service-owned reset/recovery. Cap frames at
  4096 bytes and outstanding writes at one per device. Validate every accepted count against the
  offered prefix; timeout after submission reports delivery uncertainty instead of presumed zero.
  There are no arbitrary USB control requests. Admit one service consumer per provider and one
  active job per device, ordered by submission. Different devices progress independently.
- [x] Add a `printer` provider kind consistently in `device.lsidl`, `driver-protocol`, manifest
  kinds and DeviceManager conversions, allocating an unused value alongside the other new kinds.
  Use catalogue `subscribe/open` and live withdrawal, pinning operations to full provider identity
  and attachment generation. Withdrawal fails writing/queued jobs and ends active work with unplug
  and partial-delivery evidence. Reset invalidates the attachment and all jobs, never replaying a
  prefix. Failed recovery leaves the device unavailable. Successful reattachment restores transport
  eligibility only; it does not claim that reset undid paper output or restored language state.
