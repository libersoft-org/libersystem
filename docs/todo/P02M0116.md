# P02M0116 - What P02M0114 left in the disk probe, and three gaps it opened itself

Status: COMPLETE. Three rounds of outside audit (the third, fourth and fifth on this filesystem
work), all verified claim by claim against the code. **Every finding in all three rounds held** -
nothing was hallucinated across any of them.

*Condensed 2026-08-08: each finding is stated once with its resolution, instead of once in the audit
section and again in a "what was done" section.*

## The recurring lesson

Three of the third round's ten findings were **regressions P02M0114 introduced**, not residue it failed
to clear - and each was a consequence of a fix that was itself correct. A change that improves one
path has to be followed into every path that shares its assumptions, and none of the three had a
test that would notice.

## The disk probe

**`RawDisk` meant "LBA 1 does not begin with EFI PART", which is not the same as "blank"** - and
`mount_or_format` treated it as licence to format the whole device from sector zero. That formatted:
an ordinary MBR-partitioned disk, a hybrid MBR, a GPT whose first eight bytes are damaged while its
protective MBR and backup are intact, a superfloppy carrying FAT or ext4 at LBA 0, and any disk of
foreign data with no GPT signature. P02M0114 had fixed the answer for a GPT that *is* recognised and
left the negative case exactly as dangerous.

**The GPT that was parsed was believed without being verified.** No header CRC, no entry-array CRC,
no `header_size`, no LBA relations, no comparison against real capacity, no overlap check, no
checked arithmetic. An entry with the LiberFS GUID, `first = 1`, `last = 100000` passed everything -
and the mount then targeted LBA 1, the GPT header itself, found no superblock, and formatted on top
of the partition table that named the partition.

**`Blank` was still "I recognised nothing", which is the same mistake one level in.** The fourth
round's clearest case is a raw whole-device ext4: its superblock begins at byte 1024 with its magic
at offset 0x38, so the probe decided *before the sector the filesystem starts in*. Same for btrfs,
ZFS, LUKS, and data in no filesystem at all. Adding signatures one at a time is not a fix; there is
no complete list.

**`read_gpt` did not know which sector it was parsing.** It took the bytes and nothing else, so
`current_lba` - what the header states about itself - was never compared with where it actually came
from. A correctly-checksummed header physically at LBA 1 could claim `current_lba = 65000`, pass
every relation, and let a LiberFS entry legitimately start at LBA 1.

### What the probe is now

`src/fs/partition` is a crate answering one question about a disk, reading through a `Sectors` trait
- so the same code serves a virtio-blk disk behind a block service and a map of sectors on the host,
which is what makes tens of tests affordable where six integration cases would have been the ceiling.

- **`Blank` requires positive evidence**: LBA 0 and 1, the ext4 superblock region at 1 KiB, the swap
  signature near 4 KiB, the ISO9660/UDF descriptors at 32 KiB, the btrfs superblock at 64 KiB and the
  ZFS labels at 256 and 512 KiB - all read, all zero. Anything else unrecognised is `UnknownData`,
  refused by name. A sector the medium does not have is nothing to object to; a device that reported
  a capacity and then refused a sector inside it is `Io`, because this scan is what licenses a format
  and a partial read may not stand in for the part that failed.
- **The header is tied to the medium**: `read_gpt` takes the LBA it reads and the LBA the other copy
  must live at, and requires agreement - primary at LBA 1 naming the last sector, backup at the last
  sector naming LBA 1. Without those four relations a header can declare its own position.
- **The verified primary is checked against the backup.** An unreadable or damaged backup leaves the
  primary standing, which is what a backup being a backup means; only a backup that verifies and
  *disagrees* stops the write.
- **The whole table must be consistent**, not just the candidate entry: every used entry inside the
  usable range and no two overlapping. A tool that only reads a table may trust it; this one's answer
  authorises a write.
- **`HybridMbrAndGpt` is its own answer.** A real hybrid was decided entirely by its GPT with the MBR
  entries discarded - two tables describing one disk disagree by construction.
- **Allocations are fallible and `NoMemory` is its own answer**, for the same reason
  `MountError::NoMemory` is: "your partition table is damaged" sends an operator to look at a disk
  that is perfectly fine. An I/O failure while reading the entry array is `Io`, not `CorruptGpt`.

Recorded as direction rather than built: **auto-formatting a whole device should need an opt-in.** A
GPT entry carrying the LiberFS GUID is an explicit statement by whoever partitioned the disk; a raw
whole device is not, and the service currently infers permission from the absence of evidence.

## The three regressions P02M0114 opened

- **An unknown-type inode's blocks were reserved and never released.** The mark walk was taught to
  treat an unknown type byte as file-shaped, which is right; `drop_deleted_inode` was not, and an
  unknown type is neither `TYPE_FILE` nor a directory with a `dir_root`, so removing it dropped
  nothing. Before the fix nothing was reserved, so nothing needed releasing - the improvement created
  the leak. The correction is the same rule the parser already uses: file-shaped unless it is a
  directory.
- **The iterative directory walk reversed the order it documents.** Replacing recursion with a LIFO
  stack made leaf *groups* come out right-to-left. No test caught it because every directory test fit
  in a single leaf, where LIFO and FIFO are the same thing.
- **A refused allocation in the structural pass was silent.** `check_dir_structure` returned early
  when memory was short, so `fsck` reported a clean structural result for directories it never looked
  at. A report that cannot distinguish "checked and sound" from "not checked" is worse than one that
  admits the difference. Related: a `try_zeroed` failure in `derive_free` surfaced as `NoSpace` and
  the mount folded it into `Io`, telling the operator the disk did not answer when the problem was
  memory.

## Residue and later LiberFS findings

- `load_spill` still clamped an impossible record count where `Extent::parse` had been fixed to keep
  what is on the medium. A count larger than fits in a block is `Corrupt`, not something to trim.
- **The directory checker knew one rule about names and the path API knew eight.** A record read off
  the medium named `..`, or `a/b`, or carrying a control character, passed an `fsck` that a path API
  could never have produced. One `validate_name_segment` is used by both now.
- A null child pointer inside an internal node was accepted as ordinary. It is right for an empty
  root and wrong for a child slot: every key routed there resolves to nothing while `fsck` reports
  the tree clean because the counts add up.
- **The shared visited map could hide a bad CRC in a second snapshot's link.** The skip happened
  before the block was verified against the CRC recorded in *the link that reached it*, so snapshot
  B's bad link was never checked and `fsck` said nothing.
- **The unknown inode type is only safe in one direction.** Treating it as file-shaped is right for a
  flipped byte on a file; the overlay field makes the other direction possible, where an inode that
  *was* a directory arrives with `spill` holding the old `dir_root` and `walk_chain` reads a
  directory node as a chain block. Both readings are protected now, with the directory reading
  speculative - its own scratch map, strictness off, findings never reported as damage, because one
  of the two readings is nonsense by construction.
- **The strict rules only ran when someone asked.** `check_structure` runs on `fsck` and never on a
  writable mount, so a checksum-consistent damaged leaf is a structure `fsck` calls impossible and a
  writable mount will happily insert into.
- The label check stopped at the first NUL. A field like `system\0\xff\xffgarbage` is not something
  any writer produces, so requiring zero padding costs nothing and refuses an image provably not ours.

## Three flaky tests, all the same shape

Worth naming as a habit to watch for: each asserted **a number belonging to the whole machine**
rather than the property it was written for, and each cost a three-architecture sweep before it was
recognised as noise.

- `the_frame_pool_grows_past_the_boot_table_and_refuses_a_double_free` read the global `free_count()`
  before and after its own operations on an eight-core kernel with a live scheduler. Fixed by
  asserting properties instead: "every page came back and re-coalesced" became "a contiguous span of
  the same width allocates again", and "a double free adds nothing" became a **refusal counter**
  incremented where the allocator refuses.
- `the_allocator_refuses_a_frame_it_never_handed_out` had the identical flaw and had simply not been
  unlucky yet.
- `a_remote_spawn_wakes_a_halted_core_without_waiting_for_the_tick` asserted that *every* one of five
  cross-core trips came in under 4 ms - a wall-clock bound on an emulated guest sharing a host with a
  56-worker fuzz run. It takes the **best** of five now, which keeps the discrimination rather than
  widening the bound: with the IPI removed the best of five measures 10 ms against a 4 ms bound, a
  factor of 2500, so no amount of host noise can blur the two.

## What the rounds did not say

Nothing was reproduced at runtime; every round was static and so was each verification. The fourth
auditor could not run the tests and said so, treating this repository's test results as a claim
rather than its own measurement. That is the correct posture, and the three regressions above are a
fair reminder that **a green suite bounds what was tested, not what is true**.
