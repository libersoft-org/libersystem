# P02M0086 - aarch64 (ARM64) kernel + loader port

Status: COMPLETE. The kernel runs on ARM64 under `qemu-system-aarch64 -machine virt`, filling in the
P02M0085 architecture contract with the ARMv8-A mechanisms, plus the aarch64 UEFI loader variant.

*Condensed 2026-08-08 to the mechanisms and what the port proved.*

| area | how it is done here |
|---|---|
| MMU | VMSAv8-64 tables, 4 kB granule, TTBR0/TTBR1 user/kernel split |
| Exceptions | `VBAR_EL1` vector table, `ESR_EL1`/`FAR_EL1` decode, the same resumable/terminate/halt fault split as the other targets |
| Interrupts | GIC v2 or v3 for distribution and EOI, with per-device vector acquire |
| SMP | secondary cores via the PSCI `CPU_ON` firmware call - no real-mode trampoline |
| Platform | PL011 UART, ECAM PCI, device-tree parsing for what the firmware does not report |
| Loader | the aarch64 variant over the shared core: per-arch page tables, PSCI-based bring-up |

**What the port established** is the thing worth keeping: the kernel is one portable implementation
with roughly one architecture backend swapped, not a port in the sense of a fork. It boots the full
userspace chain to the interactive shell - 23 services including StorageService five times over for
system, media, ISO, UDF and USB - and runs the suite green.

The last visible difference from x86_64, an early kernel-drawn framebuffer before userspace takes the
display, was closed here too.
