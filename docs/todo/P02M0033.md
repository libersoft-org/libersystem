# P02M0033 - Hardware inventory commands (lsblk / lspci / lscpu / ...)

Status: COMPLETE.

A Linux-style hardware inventory: PCI, block devices, CPUs, IRQs, memory. The interesting part is not
the tools - it is that **each one needed the kernel to stop throwing information away**.

*Condensed 2026-08-08.*

| tool | what the kernel had to start keeping |
|---|---|
| `lspci` | the full boot bus scan - every present function with vendor, device and class triple, not only the virtio and xHCI ones a driver binds. `SYS_PCI_INFO`. |
| `lscpu` | each core's LAPIC id, which was print-and-forget at SMP report-in. `SYS_CPU_INFO`. |
| `free` | a total usable frame count fixed at init, plus the heap summing its free list on demand. `SYS_MEMORY_STATS`. |
| `lsmem` | the Limine memory map, whose response was one-shot and discarded. `SYS_MEMMAP_GET`. |
| `lsblk` | a capacity query in the block-service protocol, served by both block drivers. |

Every one of these is a **zero-capability binary**: the syscalls are free because the information is
not authority. `dev` was renamed to `lsdev` outright rather than aliased, so there is one name.

The pattern is worth remembering: information the kernel prints during boot and drops is information
no tool can ever show, and each of these was a one-line retention plus a read-only syscall.
