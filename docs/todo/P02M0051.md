# P02M0051 - LiberFS: hostile-disk robustness, second sweep (the consumers P02M0050 missed)

Status: COMPLETE. The fifth full source pass (2026-07-03) confirmed P02M0050's bounds hold and found the
same disease in the places the first sweep did not reach.

*Condensed 2026-08-08.*

- **`load_spill` took `count` from a chain block unclamped.** Clamped both to what fits in a block
  and to what the inode header still expects, so a forged chain can neither run past the block nor
  graft records the map never had.
- **`read_file` trusted `inode.size` as an allocation directive**, so a hostile size demanded that
  much memory. Gated with a saturating multiply, and the snapshot and restore paths ride the same
  gate.
- **The namespace walks had no cycle or alias guard.** Both carry a visited set. The test forges a
  cycle through the crate's own insert machinery, so it is a structure the code can really produce.
- **The recursive tree walkers overflowed the stack on a degenerate tree.** `TREE_DEPTH_MAX` is 64
  and every walker carries the budget.
- **Extent arithmetic overflowed on hostile values.** `end()` saturates, and a helper carries every
  physical-block computation through the same saturating path.
