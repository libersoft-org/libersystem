# P02M0170 - Verification evidence belongs to one revision and one immutable test artifact

Status: PLANNED. VERIFICATION INTEGRITY FOLLOW-UP. NOT A COVERAGE REDUCTION.

## Goal

Close the remaining evidence-integrity gap after P02M0167 and make a release run produce one
machine-readable dossier proving which immutable revision, toolchain, profiles, checks and artifacts
were actually exercised.

This milestone does not rebuild the selector. Ordinary scoped verification already consults the
shadow/trust store, candidate activation is already bound to the model hash, and `--release` already
ignores selection. Those are prerequisites to preserve. The unresolved defect is that two
same-architecture selections can still rebuild the shared Cargo test executable after the build
lock is released, so a private ISO can be assembled from the wrong shared kernel. The release path
also prints progress but does not leave one complete, fail-closed report for the release revision.

## Work

- [ ] **M1 - the locked build publishes an immutable per-run executable.** Under the existing
  same-architecture build lock, compile the requested `TEST_SELECTION`/`TEST_TAGS` without running
  it, obtain the exact produced test executable from Cargo's machine-readable output, copy or publish
  it to a run-unique immutable path, and build the run's medium from that staged executable before
  releasing the lock. The subsequent guest launch consumes only those staged paths and never asks
  Cargo to resolve or rebuild the shared target. Preserve the existing suite arguments, result-log
  identity, timeout/stall handling and exit status when invoking the QEMU runner directly.

- [ ] **M2 - concurrency proves identity, not merely absence of a compiler crash.** Run two suites
  for the same architecture concurrently with disjoint selections/tags. Each result must name and
  execute exactly its own catalog keys and artifact digest, while both guests overlap in time. A
  mutation which removes staging or lets the second shared build replace the first must make the
  gate fail. Keep the already content-addressed read-only fixtures and run-unique writable paths;
  this item closes only the accepted selection-specific executable remainder from P02M0167.

- [ ] **M3 - preserve the existing strict scoped-verification contract with direct regressions.**
  Pin that an ordinary scoped run is `TRUSTED` only when current-model shadow evidence covers its
  change class and targets; otherwise it exits distinctly as `SHADOW` unless the caller explicitly
  chooses `--allow-shadow`. Pin that a frozen candidate cannot activate against different canonical
  inputs or evidence from another model. If the current implementation satisfies these tests, no
  selector rewrite is performed.

- [ ] **M4 - one immutable release run emits one complete dossier.** Run from a clean detached
  worktree or an equivalent source snapshot and bind the report to the commit, complete source
  digest, Rust/tool versions, QEMU/firmware identities, build configuration and trust profile. The
  report contains stable check/profile IDs, outcomes, durations and result-log/artifact digests for
  every release-required ID in the canonical catalog at that revision, rather than a second manual
  list which can go stale. That catalog must cover: the host suites and checks; complete x86_64,
  AArch64 and RISC-V QEMU suites; authenticated/Secure Boot; enforcing and explicit degraded DMA
  profiles; filesystem corruption/mutation checks; and the development build and boot. A required
  ID/class which is absent, skipped, unparsable, or represented only by a stale log makes the release
  run fail. Existing `check.sh` gates may supply the evidence, but their presence in a large umbrella
  command is not inferred from a zero exit code.

- [ ] **M5 - the report is fail-closed and reproducible.** Host fixtures delete one required
  profile result, substitute a log from another commit/artifact, change the tree while a run is in
  progress, and corrupt the report. Each is refused. Re-rendering a completed dossier from the same
  recorded result set is byte-for-byte deterministic apart from a clearly separated invocation
  timestamp.

## Dependencies

- P02M0118 owns strict verification levels, shadow comparison, full sweep and release entry points.
- P02M0156 owns fail-closed gate execution.
- P02M0167 owns planning, candidate trust, run identity and fixture isolation; this milestone owns
  only its explicitly accepted immutable-executable remainder and release evidence aggregation.

## Definition of done

- Concurrent same-architecture selections cannot compile, package or boot one another's kernel.
- The ordinary scoped path retains its current trust/shadow behavior.
- A release has one report tied to one immutable revision and artifact set, and the report proves
  every named release profile ran successfully rather than merely recording an umbrella exit code.

## What this milestone refuses

- Git-host branch protection, required-status configuration, release publishing or key custody.
- Running the full release matrix for every ordinary source edit.
- New selector heuristics, lower trust thresholds, or a second shadow/candidate model.
