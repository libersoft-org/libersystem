# P02M0036 - Kernel bounds from the runtime (retire the last magic numbers)

Status: COMPLETE.

The principle: **where the runtime can tell us the real bound, no constant stands in for it.** Three
kernel constants, each on a sensitive path.

*Condensed 2026-08-08.*

**`MAX_CPUS` is gone entirely, including the BSP's slot.** Boot analysis showed nothing touches the
per-CPU tables before SMP init - the first GS-base write is at its top, the timer ISR is gated off
the scheduler, and the syscall stubs reach per-CPU state only through GS at runtime - so all three
tables could be heap-allocated at the machine's exact core count with no static fallback. The
"more cores than MAX_CPUS stay parked" warning went with it.

**Machines past 255 cores are reported rather than mis-served.** MSI's message address encodes an
8-bit destination, so such cores cannot receive device interrupts until x2APIC addressing lands. The
boot log says so, and the MSI-X acquire no longer truncates the LAPIC id with an `as u8`: an id that
does not fit steers the vector to the first core with an addressable id, and only a machine with no
such core is refused.

**`MAX_WAIT_ANY` binds to the caller's Domain handle budget** instead of a magic 4096 - a wait set
cannot name more handles than its domain holds, since every entry has to resolve in the handle table
anyway.

**`MAX_WRITE` binds to the transferred object's real size.** `ObjectInfo` gained a `size` field the
kernel fills for memory-backed objects, so StorageService validates a claimed write length against
what was actually transferred rather than against a 16 MB guess.
