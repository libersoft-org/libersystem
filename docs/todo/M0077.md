# M0077 - LiberFS: post-audit sweep (the re-review's findings)

Status: COMPLETE. A second full read of the crate after M0073-M0076 (2026-07-02, ~5500 lines). The
core re-verified clean; these are the edges.

*Condensed 2026-08-08.*

**`fsck` could verify from RAM instead of from the disk** - it never cleared the caches, so a
corruption present on the medium and absent from memory passed. All four caches drop at the top of
`fsck` now. The test is the interesting part: a device whose reads of one block corrupt *on switch*,
so the cached and the on-disk answers genuinely differ.

- **`reserve_run` silently truncated `len as u32`**, so a single write past 16 TB would drift the
  accounting from the reservation. Clamped before the claim.
- **`decompress_extent` trusted `ext.clen` off the disk** in a slice bound. Bounded with `.min()`, as
  defence in depth over the CRC.
- **`fsck` verified pinned snapshot generations' file data but not their directory trees.** Extended,
  so a snapshot generation's directory damage surfaces.
- **The overwrite path copied the old block before overwriting it.** It allocates fresh and records
  the committed block dropped - no copy. `cow_data` had no other caller and is gone.
- The module documentation still described the old compression. Corrected to LZ4 block format,
  per-volume switch in the superblock, off by default, new whole-file writes only.
