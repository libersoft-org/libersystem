# P02M0169 - Three bounded correctness debts: prepared launches, LSIDL rights and scheduler truth

Status: PLANNED. CORRECTNESS/HARDENING FOLLOW-UP. NOT A NEW SUBSYSTEM.

## Goal

Close three small findings which are real in the current tree but do not justify three independent
architecture projects:

1. a governed `kill` launch must receive the `Session` capability it already declares, and every
   failed prepared launch must be cancelled rather than merely losing the caller's task handle;
2. an LSIDL `@rights` annotation must either generate an enforceable dispatch guard or be rejected
   by the schema validator; and
3. the scheduler's contract-bearing comments must describe the preemptive, wake-migrating scheduler
   that is implemented now.

The three items are independent. They share this milestone only because each is a bounded correction
to an already implemented mechanism.

## What is there now

- ServiceManager already sends a SessionService client to PermissionManager, and PermissionManager
  already receives it, stores it in `Clients.session`, and can return it from
  `Clients::for_capability`. The live defect is narrower: `Capability::Session` is deliberately
  absent from `VOCABULARY`, while the `kill` manifest requests it and `kill` waits for `SESSION`.
- ProcessService already implements `cancel` for a prepared launch. The pipeline path uses it on
  several failures, but `launch_under_manifest`, the single-tool path, the selected-file path, and
  some group-refusal paths still close `started.task` without cancelling the prepared process held
  by ProcessService. Closing the broker's handle is not cancellation.
- Generated dispatch already calls `handle_carries` for a direct `handle<T>` parameter and checks
  both minimum rights and a declared kernel object type. The validator checks right names only.
  A nested or aliased shape which code generation does not recognize can therefore carry
  `@rights` in the ABI while the dispatch silently skips the guard. An annotated method whose result
  cannot express `denied` likewise falls through to an unguarded service call.
- `sched/mod.rs` still opens by calling the scheduler cooperative and non-migrating. Timer preemption
  is implemented, and a wake deliberately enqueues on the waker's core, so both statements are
  false. Some local references to cooperative test-driving remain accurate and are not to be
  mechanically replaced.

## Work

- [ ] **M1 - `Session` joins the grant transaction.** Add `Capability::Session` to the one ordered
  grant vocabulary, keep the existing SessionService client wiring, and remove comments which still
  claim PermissionManager has no such client. A missing SessionService client is a typed failed
  grant; it must not start `kill` without the authority it requested.

- [ ] **M2 - every launch has one rollback owner until commit.** Audit all four PermissionManager
  launch shapes (`launch_under_manifest`, one tool, a pipeline, and one selected file). After
  `launch_prepared` succeeds and before `release`/`release_group` commits, every error path cancels
  the koid through ProcessService and closes the local/bootstrap handles. `Ok(false)` from a group
  release is a pre-commit refusal: cancel every still-prepared member and preserve the promise that
  no stage ran. `Err` is different: ProcessService has removed the prepared tokens and may have
  started a prefix of the group. Retain enough ownership to `SIG_KILL` every member, wait for
  confirmed termination, remove/reap every ProcessService record and Domain, and report a commit
  fault; do not relabel that partial-commit recovery as an atomic refusal.

  `run_tool_under_manifest` currently calls the already-live `launch_bounded` for `imgconv`, so a
  later grant failure cannot be restored to "the tool never ran" with `cancel` or `SIG_KILL`. Extend
  the existing prepared request with that per-launch Domain bound, or add the one owner-scoped
  prepared-bounded operation, and commit it only after the same complete grant transaction as every
  other tool. Cancellation must synchronously remove its ProcessService record and Domain. Prefer
  one small guard/helper over hand-copied early-return sequences; do not otherwise redesign launch
  semantics.

- [ ] **M3 - the launch regression observes effects, not comments.** A positive fixture launches
  the real governed `kill`, proves that it receives the Session client, signals a controlled job and
  completes. Fault injection at each pre-commit handoff/grant, on the bounded prepared path, at group
  refusal and during a group release proves that no prepared or live process, Domain charge,
  bootstrap handle, frame, or ProcessService record remains above its baseline. The refusal oracle
  additionally proves no stage ran; the injected partial-commit fault instead proves every possibly
  started stage was terminated and reaped and the fault was reported honestly. Cover a pipeline
  group and the selected-file path as well as the ordinary and bounded single-tool paths, because
  those are separate implementations today.

- [ ] **M4 - LSIDL refuses an unenforceable `@rights` promise.** Put one classification of an
  enforceable rights-bearing parameter behind both validation and generation. For this version the
  accepted shape is the exact handle shape for which dispatch emits `handle_carries`; options,
  lists, results, records, and aliases which do not resolve to that exact shape are rejected rather
  than recursively authorized. Also reject an annotated method whose result cannot return the
  schema's `denied` case. Compile-fail fixtures cover every rejected shape and the missing-denied
  case; a positive generated-dispatch test and mutation prove that a bare handle still checks rights
  and object type before calling the service. Update `docs/LSIDL.md` and its conformance checklist in
  the same change: the current annotation table explicitly says runtime enforcement is not generated,
  and the language contract may not remain weaker or contradictory after this behavior changes.

- [ ] **M5 - scheduler prose states the implemented contract.** Correct the module header and the
  other contract-bearing comments in `sched/mod.rs` which still globally describe cooperative or
  non-migrating operation. State the actual boundary: timer-preemptive per-CPU run queues, explicit
  remote placement/wake IPIs, and wake-side migration onto the waker's core. Preserve accurate local
  descriptions of cooperative test harnesses. This item changes no scheduling policy, balancing,
  affinity, or TLB behavior.

## Definition of done

- `kill` receives `SESSION` and completes through the governed production launch path.
- No failed prepared or bounded launch leaves a live process, ProcessService record or resource
  charge; a pre-commit group refusal starts no stage, while a partial-commit fault is recovered and
  reported without making that stronger claim.
- Every accepted `@rights` annotation is guarded in generated dispatch; every unsupported shape or
  result contract is rejected before code generation, and the LSIDL specification states the same
  accepted shapes and enforcement behavior.
- The scheduler's top-level documentation no longer contradicts preemption or wake-side migration.

## What this milestone refuses

- A new SessionService, permission model or general launch redesign. One owner-scoped prepared-
  bounded operation is allowed only to remove the current live-before-grants exception; group-fault
  cleanup may add only the narrow synchronous reap needed to close records it already owns.
- Recursive authorization semantics for containers of handles; rejecting an unsupported promise is
  the smaller and safer correction.
- Scheduler load balancing, affinity, topology work, or a change to the 64-CPU admission policy.
