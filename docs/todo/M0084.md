# M0084 - LiberFS: dangling directory entries (report them, list around them, remove them)

Status: COMPLETE. The eighth full source pass (2026-07-03) found one uncovered class: **a directory
entry pointing at an inode that does not exist.**

A legitimate copy-on-write writer never produces one - the entry and the inode commit atomically -
but a hostile or corrupt volume can.

*Condensed 2026-08-08.*

**`fsck` died on it.** The per-item catches covered corruption and I/O but not the "no such inode"
error, so one dangling entry - or a hostile superblock naming a nonexistent root - killed the whole
report mid-walk. A dangling entry *is* structural damage: count it, name its path, keep walking.

**And it poisoned its directory.** The listing stat'ed every entry, so one bad entry failed the whole
listing; remove read the inode before deleting, so the entry could not be removed; write and rename
over the name failed the same way. **The operator's only remedy was a reformat.**

The repair path is the pair: listings skip entries whose inode cannot be read, so the healthy rest
lists and `fsck` names the damage - and remove tolerates a missing inode, clearing the entry and
skipping the free, because there is nothing to free.

**`fsck` names it, `remove` clears it.** A filesystem that can detect damage it cannot repair has only
done half the job.
