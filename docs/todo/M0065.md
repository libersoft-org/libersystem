# M0065 - LiberFS sized by the disk (drop the fixed 32 MB pool)

Status: COMPLETE.

StorageService formatted and mounted over a hardcoded layout regardless of how big the disk was. With
the block protocol able to report capacity, the layout is derived from it: on the standard 128 MB
test disk a fresh volume formats 112 MB instead of a fixed 32.

*Condensed 2026-08-08.*

The start offset stays a fixed boot-layout mark, because the region below it belongs to the factory
archive; the fixed pool size remains only as the fallback for a disk that cannot report a capacity.

**An existing volume mounts at the size recorded in its superblock and is never silently grown** -
the free map would not match. A mismatch against the disk's real capacity is *reported* rather than
acted on, and online resize is left as future work.

That is the useful distinction: a filesystem may not quietly change its own geometry to match new
information about the medium, but it must say that the two disagree.
