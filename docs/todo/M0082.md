# M0082 - LiberFS: fsck must survive what M0081 taught the mount to survive

Status: COMPLETE. The sixth full source pass (2026-07-03) found both remaining bugs in one place:
**fsck's error handling was written for the world before the mount learned to degrade**, and two of
those new behaviours now killed the report - a direct contradiction of the contract that **fsck
reports damage and never dies on it**.

*Condensed 2026-08-08.*

**`fsck` died on free-map damage.** It opened by rederiving the free map, which since the previous
milestone returns corruption for a broken chain - so it failed on **exactly the volume the operator
most needs a report for**, the degraded read-only mount.

Worse when the damage arises at runtime: `fsck` found it, errored out, and **left the volume
writable**, so the next commit's rederivation could allocate from an incomplete map. It now counts
the damage, sets read-only with the same policy the mount uses, and keeps walking - and the degrade
is sticky until a remount confirms the repair.

The second bug is the same shape one level down: the per-item catches covered corruption but not I/O,
so a hostile out-of-pool pointer that fails its read killed the walk rather than being counted.
