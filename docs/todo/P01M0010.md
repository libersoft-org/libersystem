# P01M0010 - Core services: Process, Device, Config

Status: COMPLETE.

Three more core services speaking generated `liber:system` bindings over IPC, each a standing
userspace process that ServiceManager brings up in the boot chain.

*Condensed 2026-08-08.*

- **ProcessService** - process lifecycle (create, start, exit, info) as a typed service over the
  kernel syscalls.
- **DeviceService** - typed device enumeration and info on top of DeviceManager.
- **ConfigService** - a typed `ConfigNode` tree with an IDL schema. **No textual `/etc`**: the
  configuration is a typed tree, so reading it is not parsing.

## `ps` reported every process the system had ever started

Found later. ProcessService recorded launches and nothing ever removed one, because the service held
no handle to a launched process and so could not tell that one had ended.

It keeps a READ duplicate now - which needed no new kernel work, since `SYS_PROCESS_STATS_GET`
already answered - and reaps on both `record` and `list`, so the record is bounded by the number of
live processes rather than by how long the system has been up.
