# M0018 - Blocking `wait` primitive

Status: COMPLETE.

The IPC model's central claim - **the only place that blocks is `wait`** - needed the primitive to
exist. Before it, servers polled with a would-block error and a yield.

*Condensed 2026-08-08. (M0105 later replaced the global registry with per-object buckets and a
claim-based wake; the shape below is what it replaced.)*

A `Blocked` thread state plus a wait registry. Blocking parks the thread in the registry - the strong
reference keeps it alive off every run queue - and reschedules with a disposition that saves the
stack without requeueing or zombie-ing it, so the thread resumes from exactly that point.

The waitable objects wake their own registry entries: a channel send wakes the peer as readable, a
channel's drop wakes the peer **so a blocked receiver observes peer-close rather than hanging**, an
event signal wakes its waiters, and a deadline wakes through the scheduler's deadline check.

`SYS_WAIT` re-checks readiness in a condition-variable loop, so an early or spurious wake simply
re-blocks rather than returning a lie.

One deferral recorded at the time: the CLI's serial read still busy-spun, because a real wait there
needs a UART receive interrupt. That landed with M0105.
