# M0019 - Preemptive scheduling

Status: COMPLETE. The LAPIC periodic timer (100 Hz) preempts ring-0 threads.

*Condensed 2026-08-08. (Ring 3 stayed cooperative until M0106, which is where the reason is written
down.)*

**The foundation is an interrupt-safe `SpinLock`**: it reads the interrupt flag and disables
interrupts before acquiring, and the guard restores the prior state on drop - so a lock holder can
never be preempted and an interrupt handler can never deadlock against a lock it interrupted. Nested
locks restore correctly, only the outermost re-enabling.

The timer has a dedicated preemptive IDT stub rather than the generic count-and-dispatch path. It
signals **EOI before any switch**, so the LAPIC keeps delivering while the thread is descheduled, and
reschedules only when it interrupted ring-0 thread code.

The preemptive switch reuses the cooperative one: the interrupt prologue saves the caller-saved
registers and the return frame on the thread's own kernel stack, and the switch saves the
callee-saved set. **There is no FPU or SSE state to save** - the kernel is built soft-float, verified
by there being zero XMM instructions in the binary.

A one-tick quantum, and a no-op when the core is idle or the thread is alone, so a sole thread keeps
running.
