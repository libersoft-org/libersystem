# P02M0005 - TimeService: wall-clock time (RTC + NTP)

Status: COMPLETE. Phase 1 had deferred wall-clock time because it needs an RTC or NTP, neither
available headless; the network stack made NTP possible.

*Condensed 2026-08-08.*

**Wall-clock time is userspace policy, never a kernel concern.** The kernel gained exactly one raw
mechanism, `SYS_CLOCK_RTC`: it reads the CMOS clock, takes a **stable snapshot** - waiting out an
in-progress update and re-reading until two passes agree - decodes BCD or 12-hour as the status
register dictates, and returns Unix seconds. Everything above that is a service.

TimeService seeds its offset from the RTC at start, so there is an immediate network-free UTC, then
disciplines it over SNTP as a best-effort background step: **boot never blocks on the network**, and
a DNS, route or reply failure leaves the RTC value standing.

`UTC = monotonic clock + offset`, and **setting the offset is a capability-gated service operation** -
there is no global "root sets the clock". Only the NTP client and the RTC source hold the write
right.

The timestamp is a typed object, and ISO-8601, epoch and human forms are renderings of it rather than
three separate values.
