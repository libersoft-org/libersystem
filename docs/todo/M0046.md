# M0046 - MSI-X interrupt routing (per-device vectors)

Status: COMPLETE. **Device interrupts are MSI-X only; the legacy INTx path is removed.**

The kernel routed device interrupts through the legacy PCI INTx line with no shared-line fan-out -
one driver per GSI - so a device sharing a GSI with another could not take its own interrupt.

*Condensed 2026-08-08.*

The bus scan parses the MSI-X capability (table size, BIR and offset into a table physical address).
The kernel reserves an edge-triggered vector band (48-63) with per-vector IDT stubs and a dispatch
that signals the bound `Interrupt` and issues EOI **with no mask/unmask dance** - MSI-X is
edge-triggered, not a shared level line, and treating it like one is the classic mistake.

`device_msix_acquire(index)` allocates a vector targeting the caller's CPU, maps the device's MSI-X
table page uncacheable, writes entry 0, enables MSI-X **and sets PCI Bus Master** - the MSI is a
memory write, so it needs bus mastering - and mints a bound `Interrupt`.

**A driver must never write its own MSI-X table**, which is why programming it is a kernel operation
behind a capability rather than something a driver does through its MMIO mapping.

With `virtio_input`, `virtio_net` and `virtio_snd` each on their own vector and `virtio_gpu` polling,
no driver was left on INTx - so the I/O APIC GSI routing, the old acquire syscall and the PCI
INTx-GSI fields were all removed rather than left as a second path. The I/O APIC is mapped and fully
masked and every device's INTx pin is disabled.

Deliberately one vector per device first; per-queue vectors are a later refinement.
