# P02M0001 - Event streams in the IDL toolchain (`stream<T>`)

Status: COMPLETE.

*Condensed 2026-08-08.*

A method returning `stream<T>` replies with a handle to a **freshly created sub-channel**; the
producer then sends elements framed with a sequence number, and the consumer drains them with `wait`
and receive - never by polling. **The channel closing is how the stream ends**, so there is no
terminal sentinel to get wrong and no way to miss the end.

Backpressure is not a mechanism this adds: it is the bounded channel that was already there.

The generator emits both halves, which is what P01M0008 had deferred - the client returns the typed
consumer channel and a reader, and the server's serve loop streams over the producer end.

`log.tail` is the first real producer, drained by the shell as a live stream. It could not be
generated at all before this landed.
