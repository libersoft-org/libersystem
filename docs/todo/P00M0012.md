# P00M0012 - Process and per-process address space

Status: COMPLETE. *Condensed 2026-08-08.*

A `Process` owns its address space, its handle table and its Domain; a thread holds a reference to its
process and **delegates those three, so the syscall layer did not change** when the handle table moved
off the thread.

Each address space builds private page tables with an empty user half, **sharing the kernel higher
half by copying the top-level entries** - which is the arrangement every later architecture repeated,
and the one P02M0115 later found could go stale when a kernel-half entry is added after a space exists.

The scheduler reloads CR3 on every switch and restores the kernel space when a core goes idle.

The test is the property rather than the mechanism: two processes map the same virtual address to
different frames and each reader sees only its own, and a handle installed in one is invisible to the
other.
