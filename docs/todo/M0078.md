# M0078 - LiberFS: OS- and architecture-agnostic (portability hardening)

Status: COMPLETE. The format was already endian-explicit and OS-neutral by construction; this removed
the last architecture assumption and wrote down what a foreign implementation needs.

*Condensed 2026-08-08.*

- **The 32-bit `usize` traps are gone.** File sizes and logical block indexes ride u64 end to end,
  with `usize` only where a memory-resident slice is indexed - so a 32-bit build never silently
  truncates a file past 4 GB.
- **Golden tests pin the byte layout**, so the fixed-offset little-endian format is asserted on every
  architecture the tests run on: every superblock field at its documented offset, the self-CRC rule,
  the record layouts, and the CRC32C test vector pinning the checksum definition itself.
- **The formal field-level specification lives in `docs/LIBERFS.md`** - encoding rules, every
  structure's offset table, the checksum and codec definitions with a vector, the commit protocol and
  the reachability rule behind the free map. The golden tests reference it, and a layout change must
  bump a feature bit and update it.
- **The semantics a foreign driver must honour are written down too**, which is the half a format
  table does not cover: byte-exact case-sensitive UTF-8 names with no normalisation, no links,
  UTC-seconds timestamps with a synthesized atime, synthesized mount-wide permissions with the owner
  tag opaque, read-only snapshot mounts, the copy-on-write and flush commit protocol, and the
  corrupt-chain degradation rule.
- **A GPT partition type GUID** (`4C424653-0001-4000-8000-4C6962657246`, "LBFS"/"LiberF") so a disk
  partitioned by any system carries a findable LiberFS volume.

Deliberately out of scope and recorded as such: foreign-architecture CI, a standalone crate build,
FUSE or WinFsp reference drivers, host mkfs and fsck tools.
