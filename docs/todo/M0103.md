# M0103 - LiberFS: second-pass findings (the raw-length gate gap)

Status: COMPLETE. The second full source pass (2026-07-04) went deep on the B+tree core, the
allocator and the codec - all clean - and found one real gap in the previous milestone's own gate.

*Condensed 2026-08-08.*

**The out-of-pool gate checked the stored span while the raw read path serves logical offsets.** A
forged raw extent claiming a one-block store and a thousand-block length, starting near the pool's
end, **passed the gate and read past the pool** - and a forged checksum block vouched for the foreign
bytes, so another partition's data surfaced as file content.

A raw run is gated by the larger of its length and its stored span now; a compressed run keeps the
stored-span gate, because its length is a logical span rather than addresses. The test is built so
that **every address field is in the pool and every CRC matches - only the length lies.**

Second: the mark walks pushed children before marking them, testing at pop. A hostile node fanning
~341 links at one unmarked block pushed ~341 duplicates, so the work list could transiently reach
O(links × pool) - gigabytes on a large hostile volume. Test-and-set at push means a block enters the
list once.
