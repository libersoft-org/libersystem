# M0105 - Kernel wake path: per-object wait queues, cross-core wake IPIs, and the serial RX interrupt

Status: COMPLETE.

A review found the remaining latency and scalability debt all on one path: **how a blocked thread
gets woken.** One global waiter list scanned under one lock, no way to nudge a halted core, and a
serial port that was only ever polled - together quantizing every interactive event to the 10 ms tick.

*Condensed 2026-08-08.*

**The wait registry split in two.** Object waits live in 64 koid-keyed buckets, so waking an object
locks and scans only that bucket. Timed waits additionally register in a separate list, which is the
only thing the deadline scan ever touches - so the no-deadline service waits that dominate the system
cost the timer path nothing.

**Wakes are claim-based.** A waker wins its thread with a Blocked→Ready compare-exchange *before*
enqueueing, so a `wait_any` waiter with one entry per object is enqueued exactly once no matter how
many of its objects fire together on different cores; the woken thread sweeps its own leftover
entries as it resumes.

That protocol forced the block path to become a proper parked handoff - the blocker zeroes its saved
stack pointer, marks itself Blocked and registers with interrupts masked through the switch, and the
enqueue spins out the context switch's first store before making the thread runnable. **This retired
a latent race the old registry tolerated**: a waker could previously see a Blocked thread whose stack
was not yet parked.

**A cross-core enqueue sends a wake IPI** (an EOI-only handler - the delivery itself is the message)
after waiting out the ICR delivery-status bit, so a halted core picks the thread up immediately
instead of on its next tick. Plain same-core wakes stay as they were.

The UART receive interrupt replaced the last polled input source.

The framing worth keeping: **the only blocking point is `wait`, so the wake path *is* the system's
latency.** And the global waiter list was the last single-core-shaped structure in a kernel that had
been SMP-aware since phase 0.
