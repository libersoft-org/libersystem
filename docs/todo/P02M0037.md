# P02M0037 - Runtime-tunable policies (constants become ConfigService keys)

Status: COMPLETE.

Six bounded-by-nature values - caches and rings that must stay bounded - had their bound picked by
the compiler. **The bound is the operator's policy**, so it belongs in the typed config tree.

*Condensed 2026-08-08.*

The keys: console scrollback and history, the journal depth, the ARP cache size, and the supervisor's
restart budget and watchdog ticks - each seeded with the constant it replaced. One correction fell
out of doing it: the journal's seeded value had been a stale demo number of 32 against a real depth
of 4096.

**The plumbing was the actual work**, and it is the part worth remembering: the owning services did
not hold ConfigService clients, and each needed a different route.

- NetworkService receives a supervisor-minted client as a bootstrap message.
- **LogService starts before ConfigService**, so its client is delivered late - the supervisor mints
  and sends it the moment ConfigService reports in, and LogService's serve loop had to stand on its
  bootstrap channel as well to catch it.
- ConsoleService mints its own from a factory it already held.

Console keys are read **at every VT creation**, so a change applies to the next VT with no console
restart. Those reads ride a bounded-wait transport, because a supervisor that wired the factory to a
mute endpoint - which a test scenario does - must never hang the console waiting for an answer that
is not coming.
