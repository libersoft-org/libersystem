# M0113 - Wasm: indirect calls and tables

Status: COMPLETE.

The interpreter trapped on `call_indirect` - **the first gap a real toolchain-built component hits**,
because any Rust trait object, function pointer or vtable compiles to one.

*Condensed 2026-08-08.*

The parser reads the table and element sections in the forms an LLVM toolchain actually emits, and
the interpreter builds the instance's function table sized to the larger of the declared minimum and
the highest element write, with unfilled entries null.

`call_indirect` pops the table index, traps on an out-of-range index or a null entry, **type-checks
the callee's actual signature against the immediate's expected one**, and only then dispatches. The
type check at call time is the spec semantics and it is the part that cannot be skipped: a table is
`funcref`, so the static type says nothing about what is in the slot.

## The engine decision, recorded

The from-scratch interpreter stays plan A for this phase: small, auditable, host-tested, and it fits
a `no_std` ring-3 environment. The AOT/JIT question is deliberately deferred to be settled **next to
the packaging work and gated on a measurement of a real component workload**, in this order of
preference: the interpreter suffices, a simple baseline compiler, a ported engine.

Likewise the full Component Model binary format and literal `wasi:*` worlds wait for a concrete
third-party interop need - the first-party world and SDK cover what exists, and WIT can be emitted
from the IDL generator when it is wanted.
