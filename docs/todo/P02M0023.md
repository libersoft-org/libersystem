# P02M0023 - LiberFS: 64-bit addressing, large files/volumes, and long names

Status: COMPLETE. *Condensed 2026-08-08.*

u32 block pointers capped volumes near 16 TB, double-indirect mapping capped a file near 1 GB, and
names were 28 bytes - all far too small for real storage.

- **Block pointers and file sizes widened to u64**, taking volumes into exabytes.
- **The file cap lifted**, folded into what became the extent map.
- **Names to 255 bytes**, decoupling the directory entry from a fixed 32-byte slot.
- **A portable-name policy at the filesystem boundary**: the cross-platform-unsafe set is rejected on
  top of `/` and NUL, **so a file created here moves cleanly to FAT or NTFS media**. That is a
  deliberate constraint on our own filesystem for the sake of the ones it will meet.
- **Opaque per-inode room for a future owner or ACL tag** - stored, never enforced. Authorisation
  stays in the service and the capability layer; the filesystem carries the bytes and no opinion.
