# P02M0042 - Contiguous DMA and full-size I/O (queues, sectors, jumbo)

Status: COMPLETE. The throughput milestone: everything had been sized by "one 4 kB DMA page" - rings
capped at 16 descriptors, block I/O moving one sector per request.

*Condensed 2026-08-08.*

**The kernel change underneath all of it: the frame allocator was rewritten from a LIFO free list to
a range table** - a sorted fixed array of (base, pages) runs seeded from the memory map, coalescing
on free. A free list cannot answer "give me sixteen physically contiguous pages" at all, so every
item below was blocked on it.

*(That fixed array is also what P02M0077 later had to bound, and what [P02M0120](P02M0120.md) exists to
replace: a run that does not fit is currently not tracked.)*

On top of it: virtio rings negotiate the device-reported queue size instead of assuming 16;
virtio-blk moves a whole span per request; xHCI mass storage gets a multi-page transfer buffer;
virtio-net does jumbo frames end to end; TCP gains window scaling, because a 16-bit window caps
throughput on any link with real latency; and StorageService issues extent-sized reads instead of
per-sector ones.

Measured before and after with a large `cat` and a bulk TCP transfer - the milestone is a throughput
claim, so it had to end in numbers rather than in a description.
