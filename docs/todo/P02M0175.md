# P02M0175 - Dual-stack transports, DNS and NetworkService

Status: PLANNED AFTER P02M0174. FUTURE-TRACK NETWORKING. NOT A PHASE-2 COMPLETION GATE.

## Goal

Carry P02M0174's IPv6 addresses through UDP, TCP, DNS, the public NetworkService contract and the
network tools, producing one coherent IPv4/IPv6 dual-stack appliance rather than a private L3 feature
which applications cannot name.

TLS is not part of this milestone. It authenticates and protects application transports and should
be designed after the address/socket contract is correct, not hidden inside an IPv6 rollout.

## Work

- [ ] **M1 - the IDL represents either address without ambiguity.** Add an exact 16-octet IPv6
  wire value as a fixed positional record (matching the current four-octet IPv4 record), not
  `list<u8>` plus `@bound(16)`, which permits shorter values. Add a closed `ip-address` variant and a
  distinct interface-qualified/scoped address form, then migrate endpoint, neighbor, route, DNS-
  server, interface, ping, traceroute and socket-information records to the appropriate form. Every
  stored or transmitted link-local value, including RDNSS, carries its interface; scope is rejected
  where nonsensical. Network info can report the bounded set of IPv4 and IPv6 addresses, routers and
  DNS servers instead of forcing one value into IPv4 fields. Because the current protocol generation
  is not frozen as a third-party ABI, make one reviewed compatibility-manifest update and migrate all
  first-party callers atomically rather than maintaining two indefinite parallel APIs.

- [ ] **M2 - UDP and TCP use the address family in every invariant.** Implement IPv6 pseudo-header
  checksums (mandatory for UDP), route/neighbor lookup, source-address selection and PMTU refusal.
  Connection/listener keys include family and full local/remote addresses so equal port numbers or
  low address words cannot alias IPv4 and IPv6 state. Define explicit IPv4-only, IPv6-only and
  dual-stack wildcard-listen semantics; an IPv4-mapped IPv6 address is not silently treated as an
  IPv4 capability. Demultiplex validated ICMPv6 Destination Unreachable, Time Exceeded, Parameter
  Problem and Packet Too Big quotations by family and the full quoted transport tuple to only the
  originating UDP, TCP or probe operation; an error may not terminate a different flow. TCP derives
  effective MSS from interface/path MTU, advertises it, and after a validated Packet Too Big
  resegments/retransmits outstanding data within the smaller MSS rather than leaving an established
  connection stalled. Preserve current backpressure, retransmission, close and resource accounting.

- [ ] **M3 - DNS returns bounded typed answers.** Query and validate A and AAAA records, including
  bounded name-compression/CNAME traversal, and return a bounded ordered list of typed addresses
  rather than one IPv4 address. Any link-local result carries its interface provenance in M1's
  scoped form, or is rejected when the resolver cannot determine that provenance; it may not escape
  as a bare `ip-address`. State the deterministic preference/fallback policy used by first-party
  callers and preserve distinct timeout, malformed, no-record and transport errors. An IPv6-only
  boot can use interface-qualified RDNSS from P02M0174; dual-stack boots retain the IPv4 DNS path.

- [ ] **M4 - NetworkService and clients migrate together.** Update connect/fetch, listen/accept,
  ping, probe/traceroute, sockets, info, resolution and SNTP call paths. Migrate `ip`, `ss`, `ping`,
  `traceroute`, `nslookup`, `nc`, `tcp`, `httpd` and every other current consumer selected by the
  generated protocol change. Define one canonical textual IPv6 form, bracketed `[address]:port` and
  URL authority parsing, plus one unambiguous interface-zone syntax for scoped link-local values;
  parsers/renderers round-trip and reject ambiguous IPv4-style splitting. `arp` remains explicitly
  IPv4; IPv6 neighbors are shown through the common interface view or a clearly named ND view.
  Configuration and service readiness are per family: SLAAC/DAD/RA processing runs independently of
  DHCPv4, and an IPv6-only profile can bring NetworkService online without a DHCPv4 lease or static-
  v4 fallback. Later family configuration changes are observable without restarting unrelated
  sockets. A deprecated source is not chosen for a new connection; when an address/route becomes
  invalid, affected UDP/TCP operations receive a defined error or close/reselect according to their
  existing state instead of continuing with an address the L3 layer no longer owns. Permission
  manifests do not gain raw NIC access.

- [ ] **M5 - dual-stack behavior is tested as a matrix.** Host fixtures cover UDP/TCP checksum
  vectors, address-family demultiplexing, same-port v4/v6 listeners, source selection, PMTU, AAAA/A
  answers, CNAME/answer bounds, textual/scoped-address round trips and deterministic fallback. QEMU
  gates use an explicit reviewed global-unicast /64; the IPv6-only row also disables IPv4 rather than
  accepting an incidental DHCPv4 path. Provide one deterministic unprivileged IPv6-capable Ethernet
  peer fixture through QEMU's socket netdev (including RA/ND, DNS and TCP/UDP peers) for the inbound
  oracle: Slirp's IPv4 `hostfwd` is not evidence that an SLAAC-only guest is reachable over IPv6.
  Exercise IPv6-only and dual-stack AAAA lookup, outbound and inbound TCP, UDP/DNS, `ping -6` (or the
  equivalent typed-address invocation), traceroute errors and a failed preferred-family connection
  followed by the declared fallback. Hostile fixtures quote a second live flow when delivering each
  ICMPv6 transport error and prove it remains untouched. A reduced-MTU path proves TCP MSS/
  resegmentation rather than only completing the handshake. Existing DHCPv4, IPv4 DNS, TCP and tools
  remain green in the same release matrix.

## Dependencies

- P02M0004 owns UDP/TCP/DNS and capability-scoped NetworkService.
- P02M0080 owns elastic service pools and their capacity reporting.
- P02M0174 supplies validated IPv6 addresses, routes, neighbors and PMTU state.

## Definition of done

- First-party applications can resolve, connect, listen, inspect and diagnose IPv4 and IPv6 through
  one typed capability-scoped API.
- IPv4-only, IPv6-only and dual-stack QEMU profiles have positive traffic oracles and hostile parser
  coverage, with bounded resources and no family aliasing.
- IPv4 behavior remains available; IPv6 support is not represented as TLS or general Internet
  hardening.

## What this milestone refuses

- TLS/HTTPS, certificate validation, QUIC, IPsec, VPN, firewall/NAT and advanced congestion control.
- DHCPv6 or privacy addresses unless P02M0174's SLAAC/RDNSS QEMU profile proves insufficient and a
  separate reviewed requirement is opened.
- POSIX raw sockets or ambient packet authority for tools.
