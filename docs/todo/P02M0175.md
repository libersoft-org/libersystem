# P02M0175 - Dual-stack transports, DNS and NetworkService

Status: PLANNED AFTER P02M0174. FUTURE-TRACK NETWORKING. NOT A PHASE-2 COMPLETION GATE.

## Goal

Carry P02M0174's IPv6 addresses through UDP, TCP, DNS, the public NetworkService contract and the
network tools, producing one coherent IPv4/IPv6 dual-stack appliance rather than a private L3 feature
which applications cannot name.

TLS is not part of this milestone. It authenticates and protects application transports and should
be designed after the address/socket contract is correct, not hidden inside an IPv6 rollout.

**The UDP deliverable is decided here rather than left to implementation.** UDP in this milestone
means the named INTERNAL operations - DHCP, DNS and SNTP - plus their IPv6 equivalents and their
test peers. There is NO public datagram bind/send/receive API. Adding one would be a second unplanned
public contract on top of a transmit-side TCP implementation this milestone already has to build,
and the tools this milestone migrates do not need it. If an application ever needs datagrams, it is
its own reviewed requirement with scoped endpoints, conflict rules and queue budgets.

## What is there now, and what it forces

- There is NO transmit-side TCP. `TcpConn` holds sequence counters and a receive buffer; it stores
  no unacknowledged bytes, no peer MSS and no send window. `tcp_build_data` advances `snd_nxt` past
  a one-shot frame and retains nothing, and `socket.send` truncates the caller's buffer to one
  segment, transmits once, closes the buffer and reports success. Only SYN has a retransmission
  loop. So "resegment and retransmit outstanding data after a PTB" cannot be implemented as an
  addition - there is no outstanding data to resegment, and loss is currently unrecoverable.
- DNS is uncorrelated. Any UDP datagram whose SOURCE port is 53 is handed to the parser; the
  destination port, the server address, the UDP length and checksum are unchecked, and the parser
  ignores the transaction ID, QR/opcode/rcode, the question section, the answer owner and CNAME
  chain, returning the first A record. `resolve` collapses every failure to `NotFound`.
- An inbound SYN allocates a TCB BEFORE any socket channel exists. `tcp_alloc` reuses a free slot or
  unconditionally pushes a new one - the pool has no cap - and every fresh TCB allocates 65,535
  receive bytes, growing to 262,140 when the peer offers window scaling. P02M0080's claim that the
  domain handle budget is the true ceiling does not hold for this path, because a half-open TCB
  consumes no handle.
- The public contract is IPv4-shaped and unbounded: `endpoint` is an `ipv4-addr` and a port,
  `net-info` carries one address and one gateway with an unbounded neighbour list, `listen` takes a
  bare `u16`, and `network.lsidl` contains no `@bound` at all - so the schema advertises requests
  larger than the service's 1024-byte request and 4096-byte reply buffers can receive.
- Boot blocks on DHCPv4 before entering the serve loop and then installs a hard-coded IPv4 fallback.
  The loop schedules only the lease deadline, and the synchronous helpers discard unrelated events.
  An IPv6-only profile would still wait for DHCPv4 and silently acquire v4 state.
- `service-logic` is the host-testable boundary; the `services` binary links `rt` and cannot be
  host-tested. Every pure decision added here goes there.

## Work

- [ ] **M1 - the IDL represents either address without ambiguity, with stated fields and bounds.**
  Enumerate the exact records, variants and operation signatures BEFORE implementation; a list of
  record names is not a wire contract and two reasonable implementers will produce incompatible ones.

  Add an exact 16-octet IPv6 wire value as a fixed positional record (matching the current
  four-octet IPv4 record), not `list<u8>` plus `@bound(16)`, which permits shorter values. Add a
  closed `ip-address` variant and a distinct interface-qualified/scoped address form. Define:

  - a stable INTERFACE IDENTITY with a generation, so a scoped value cannot silently refer to a
    replaced interface, and the valid and invalid scope combinations for each address class;
  - ADDRESS STATE (tentative, preferred, deprecated, invalid) with prefix and lifetimes;
  - ROUTE, ROUTER and DNS-SERVER entries as their own records, plural, replacing the single gateway
    and DNS fields;
  - a LISTENER BIND MODE - IPv4-only, IPv6-only, dual-stack wildcard - and a local scoped endpoint,
    with the conflict and reuse rules for two binds on the same port. `listen(port)` cannot express
    any of the three cases M3 implements and M9 tests; and
  - LOCAL AND REMOTE endpoints on accepted and live sockets, so `ss` can report what a socket
    actually is.

  Assign an explicit `@bound(n)` to EVERY variable-length occurrence the migration touches - MAC
  bytes, neighbour and address and router and DNS lists, names, TCP request strings, socket lists,
  fetch bodies and chunks - and derive the maximum request and reply sizes from those bounds.
  Reconcile them with the service's framing buffers: the wire may not advertise a request the
  service cannot receive. Define per-client and per-flow aggregate budgets, typed overflow versus
  deterministic truncation with an explicit truncation signal where truncation is allowed, and
  fallible allocation. Test exact-bound and over-bound encodings and the rollback and accounting on
  refusal.

  Migrate endpoint, neighbour, route, DNS-server, interface, ping, traceroute and socket-information
  records to the appropriate form. Every stored or transmitted link-local value, including RDNSS,
  carries its interface; scope is rejected where nonsensical. Because the current protocol generation
  is not frozen as a third-party ABI, make one reviewed compatibility-manifest update and migrate all
  first-party callers atomically rather than maintaining two indefinite parallel APIs, and add
  encode/decode/layout and cross-caller migration fixtures.

- [ ] **M2 - TCP acquires a bounded transmit side.** This is new implementation, not a family
  parameter added to existing code, and everything else in this milestone that mentions
  retransmission depends on it:

  - an owned per-connection queue of UNACKNOWLEDGED bytes, with a hard per-flow and aggregate byte
    budget;
  - peer MSS from the SYN, an effective MSS derived from interface and path MTU, and a tracked send
    window;
  - segmentation of a caller's buffer across several segments, and partial-write backpressure with
    a defined contract for whether `send` reports bytes ACCEPTED or bytes acknowledged - the current
    silent truncation to one segment is a data-loss bug reported as success;
  - ACK retirement with wraparound handling, an RTO for data and FIN, and a retry limit that closes
    the connection rather than retrying forever; and
  - resegmentation and retransmission of outstanding data within a smaller MSS after a validated
    Packet Too Big.

  Test partial ACK, loss, sequence wraparound, PTB resegmentation, close with data in flight, and
  budget refusal.

- [ ] **M3 - UDP and TCP use the address family in every invariant.** Implement IPv6 pseudo-header
  checksums (mandatory for UDP), route/neighbour lookup and PMTU refusal. Connection and listener
  keys include family and full local/remote addresses so equal port numbers or low address words
  cannot alias IPv4 and IPv6 state. Implement M1's three wildcard-listen modes; an IPv4-mapped IPv6
  address is not silently treated as an IPv4 capability. Demultiplex validated ICMPv6 Destination
  Unreachable, Time Exceeded, Parameter Problem and Packet Too Big quotations by family and the full
  quoted transport tuple to only the originating UDP, TCP or probe operation; an error may not
  terminate a different flow. Preserve current backpressure, close and resource accounting.

- [ ] **M4 - inbound TCP state is charged before it is published.** Define and enforce hard budgets
  the handle ceiling does not provide: a half-open (SYN-received) limit, an established-but-
  unaccepted backlog limit, a total TCB cap, and aggregate receive and transmit byte budgets across
  all connections. Add SYN-ACK retransmission with expiry, an accept-backlog policy, and an
  admission or eviction rule when a budget is reached. Charge the allocation BEFORE the state is
  published, and report capacity and drops through the existing capacity operation. Test SYN floods
  and completed-but-unaccepted backlog floods across both families and prove the heap stays within
  the declared budget. Correct P02M0080's "handle budget is the only ceiling" statement for this
  path in the same change, because it is currently the reason nobody looked.

- [ ] **M5 - source and destination selection follow a pinned algorithm.** "IPv6 first" is not an
  algorithm and will not survive multiple prefixes, deprecated addresses or a candidate with no
  route. Pin the applicable RFC 6724 profile for both default source-address selection and
  destination-address ordering, including the policy table, the tie-breaks this appliance uses, and
  any RFC 8028 route/interface update it adopts. Define candidate filtering, scoped-zone handling,
  explicit caller overrides, failure and fallback TIMING, and behaviour after an address or route is
  invalidated. Never choose a deprecated source for a new connection. Test mixed A/AAAA answers,
  multiple prefixes and routers, deprecated and tentative addresses, link-local scope, and a
  candidate with no usable route.

- [ ] **M6 - DNS is correlated, validated and bounded.** Validate UDP framing, length and checksum,
  and correlate a response by family, the scoped server it was sent to, the local and destination
  ports, the transaction ID, the normalized qname, the qtype and the qclass - today any datagram
  with source port 53 is accepted, so a spoofed or cross-query answer is indistinguishable from the
  real one. Validate QR, opcode, rcode and the section counts; validate the answer owner and the
  CNAME chain; bound name-compression traversal and reject compression loops; respect TTLs.

  Return a bounded ordered list of typed addresses rather than one IPv4 address. Any link-local
  result carries its interface provenance in M1's scoped form, or is rejected when the resolver
  cannot determine it; it may not escape as a bare `ip-address`. Preserve distinct timeout,
  malformed, no-record and transport errors instead of collapsing them.

  On a truncated response, retry over DNS/TCP with two-byte length framing, as RFC 7766 section 5
  requires of a general-purpose stub resolver - AAAA and CNAME sets are exactly the answers that
  overflow. This depends on M2 and is ordered after it. An IPv6-only boot can use interface-qualified
  RDNSS from P02M0174; dual-stack boots retain the IPv4 DNS path. Test spoofed answers, cross-query
  answers, compression loops and the TCP retry.

- [ ] **M7 - the service becomes event-driven and per-family.** Start serving IMMEDIATELY rather than
  blocking on DHCPv4, with explicit per-family enable/profile configuration and stated readiness
  criteria for each. Consume P02M0174's frozen L3 notification and ingress/egress contract - do not
  extend it here. Drive one aggregate deadline scheduler covering DHCP, ND, DAD, RA, PMTU and TCP
  timers, and a bounded durable event/pending-operation store keyed by flow, so no deadline is
  starved and no invalidation is lost while an RPC is blocked. An IPv6-only profile brings the
  service online with no DHCPv4 lease and no static-v4 fallback. Later family configuration changes
  are observable without restarting unrelated sockets; when an address or route becomes invalid,
  affected operations receive a defined error or close/reselect according to their existing state
  instead of continuing with an address the L3 layer no longer owns. Extract the pure decisions into
  `service-logic` and use the same core in QEMU.

- [ ] **M8 - NetworkService and clients migrate together.** Update connect/fetch, listen/accept,
  ping, probe/traceroute, sockets, info, resolution and SNTP call paths. Migrate `ip`, `ss`, `ping`,
  `traceroute`, `nslookup`, `nc`, `tcp`, `httpd` and every other current consumer selected by the
  generated protocol change. `arp` remains explicitly IPv4; IPv6 neighbours are shown through the
  common interface view or a clearly named ND view. Permission manifests do not gain raw NIC access.

  Textual forms are THREE separate grammars, not one parser decision:

  - RFC 5952 canonical rendering for display;
  - a bounded RFC 4007 `%zone` UI convention for input, mapped to M1's stable interface identity.
    A zone identifier is local UI scope: it is not part of an origin and is never transmitted; and
  - bracketed `[address]:port` and RFC 3986 URL authority WITHOUT a zone. A scoped URL authority is
    rejected. RFC 6874's zone-in-URI extension is deprecated and is not implemented; following its
    `%25` advice would produce non-standard URLs, origin ambiguity and leakage of local interface
    names.

  Parsers and renderers round-trip within each grammar and reject ambiguous IPv4-style splitting.

- [ ] **M9 - dual-stack behavior is tested as a matrix.** Host fixtures over `service-logic` cover
  UDP/TCP checksum vectors, address-family demultiplexing, same-port v4/v6 listeners in all three
  bind modes, RFC 6724 selection cases, PMTU and resegmentation, AAAA/A answers, DNS correlation and
  spoof rejection, CNAME and answer bounds, exact-bound and over-bound encodings, the three textual
  grammars and their round trips, and deterministic fallback.

  QEMU gates use an explicit reviewed global-unicast /64 and EXTEND P02M0174's socket-netdev peer
  fixture with DNS, UDP and TCP peers; the IPv6-only row also disables IPv4 rather than accepting an
  incidental DHCPv4 path. Exercise IPv6-only and dual-stack AAAA lookup, outbound and inbound TCP,
  UDP/DNS, `ping -6` (or the equivalent typed-address invocation), traceroute errors, a truncated
  DNS answer retried over TCP, and a failed preferred-family connection followed by the declared
  fallback. Hostile fixtures quote a second live flow when delivering each ICMPv6 transport error and
  prove it remains untouched, and flood the listener with SYNs and unaccepted connections in both
  families to prove M4's budgets hold. A reduced-MTU path proves TCP MSS and resegmentation of real
  outstanding data rather than only completing the handshake. Existing DHCPv4, IPv4 DNS, TCP and
  tools remain green in the same release matrix.

## Dependencies

- P02M0004 owns UDP/TCP/DNS and capability-scoped NetworkService.
- P02M0080 owns elastic service pools and their capacity reporting; M4 corrects its ceiling claim
  for inbound TCBs.
- P02M0174 supplies validated IPv6 addresses, routes, neighbours and PMTU state, the frozen L3
  notification contract M7 consumes, and the socket-netdev peer fixture M9 extends.

## Definition of done

- First-party applications can resolve, connect, listen, inspect and diagnose IPv4 and IPv6 through
  one typed capability-scoped API whose records, bind modes and bounds are stated in the schema.
- TCP owns its outstanding data: loss and a reduced path MTU are recovered rather than silently
  dropped, and `send` reports what it actually accepted.
- DNS answers are correlated and validated, distinct errors survive, and a truncated answer is
  retried over TCP.
- Inbound TCP state is charged against declared budgets before publication, and a SYN or backlog
  flood in either family cannot grow the service heap past them.
- IPv4-only, IPv6-only and dual-stack QEMU profiles have positive traffic oracles and hostile parser
  coverage against a controllable peer, with bounded resources and no family aliasing.
- IPv4 behavior remains available; IPv6 support is not represented as TLS or general Internet
  hardening.

## What this milestone refuses

- TLS/HTTPS, certificate validation, QUIC, IPsec, VPN, firewall/NAT and advanced congestion control.
  M2 builds reliable delivery, not a congestion-control implementation beyond what a bounded
  appliance needs.
- A public datagram socket API. UDP here is the named internal DHCP, DNS and SNTP operations.
- DHCPv6 or privacy addresses unless P02M0174's SLAAC/RDNSS QEMU profile proves insufficient and a
  separate reviewed requirement is opened.
- Zone identifiers in URLs or in any transmitted authority.
- POSIX raw sockets or ambient packet authority for tools.
