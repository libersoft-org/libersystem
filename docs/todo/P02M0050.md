# P02M0050 - LiberFS: hostile-disk robustness (sanity bounds on all on-disk values)

Status: COMPLETE. The fourth full source pass (2026-07-03) found one systematic hole the earlier
tracks only grazed.

**CRC32C protects against bit flips, not against an author.** A checksum-consistent structure written
deliberately passes every integrity check the filesystem has, so every number read off the medium
needs a sanity bound of its own.

*Condensed 2026-08-08.*

- **`mount_at` trusted `sb.num_blocks`.** A checksummed superblock could claim a pool larger than the
  device. Both bounds are in: the parse rejects a pool at or below the fixed layout, and the mount
  probe-reads the last claimed block before sizing anything.
- **The raw generation walks panicked on a corrupt node header.** Two clamped accessors sit next to
  `node_count` now - one bounded by the record width, one by the separator region - and the walks use
  them.
- **The raw walks had no cycle guard.** `walk_chain` carries a step counter capped at the pool size,
  and the mark walks skip already-marked blocks - marked meaning walked, which also stops re-walking.
- **The CRC-verified paths trusted `node_count` too**, so an attacker-authored volume that verifies
  could still overrun. Every consumer in the transaction, directory and `fsck` code rides the clamped
  accessors.
- **`lz_decompress` trusted the stream's own length header.** It takes a ceiling from the caller now,
  and both copy loops stop at it.
