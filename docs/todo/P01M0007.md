# P01M0007 - virtio drivers (headless): blk, net, console

Status: COMPLETE. Three drivers, each an isolated userspace process driving its device over
virtqueues and surviving a crash-and-restart cycle.

*Condensed 2026-08-08.*

The shared transport gained the split-virtqueue data path: fill a descriptor chain, publish it in the
available ring **with the right memory fences**, notify the device, and poll the used ring. The
transport was refactored into negotiate, per-queue setup and driver-ok, so each driver sets up only
the queues it needs.

Each driver proves itself at start rather than claiming to be up: the block driver writes a pattern
to a sector and reads it back, the network driver reads the MAC from device config and transmits a
broadcast frame, and the console driver writes a banner that lands on the host's console. **A driver
that reports online without having touched its device is reporting that it loaded.**

The network *stack* was explicitly phase 2; this is the driver only.
