# M0051 - LiberFS: block checksums (integrity)

Status: COMPLETE. Landed independently of copy-on-write, which it does not need.

*Condensed 2026-08-08.*

The filesystem trusted the block device, so a flipped bit - bit rot, a flaky controller, a bad cable -
came back as silent corruption.

**The checksum is stored in the block's parent metadata, never inside the block itself**: the inode
for data blocks, the superblock and table headers for metadata. A checksum stored inside the thing it
protects cannot detect a wholesale replacement of that thing.

Every read recomputes and compares, and a mismatch is **its own error variant** rather than corrupt
bytes with a success status. `fsck` walks all blocks and reports the failures.

Recorded at the time: this is detection. **Self-healing needs redundancy**, which the format does not
have.
