# P02M0010 - ResourceManager policy service

Status: COMPLETE (2026-06-27).

The kernel has enforced resource accounting since phase 0 - memory, handles, threads, IPC queue
bytes, DMA. This added the userspace **policy** layer that sets and adjusts those budgets per Domain:
mechanism in the kernel, policy in a service, the same split as PermissionManager.

*Condensed 2026-08-08.*

The IDL declares the model: a `resource-type` enum, a usage record and the operations to set, adjust
and read a budget. A component over its budget gets `RESOURCE_EXHAUSTED`, which was already a
first-class kernel error rather than something invented here. Under pressure the policy asks services
to reclaim before anything is killed.

## Per-launch Domains had to become reportable

Found 2026-07-30, while P02M0104 was giving each governed launch a Domain of its own: **ResourceManager
can only report the Domains it was given**, so a Domain created per launch was invisible - isolation
enforced and nothing able to observe it.

The fix hands over no handle. ProcessService already keeps a record per live process; it keeps the
per-launch Domain handle there and answers an `accounting` op with the live counters of every Domain
it holds, named after the program. Sending the Domain itself would make the receiver its last holder
and keep it alive past the process it accounts - which is exactly the lifetime the per-launch change
had just fixed.
