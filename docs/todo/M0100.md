# M0100 - UDF: second-pass findings (the shared-buffer corruption)

Status: COMPLETE. The second full source pass (2026-07-04) found **the most serious defect of the
whole filesystem series** - and the first pass missed it because the test images use embedded files
only.

*Condensed 2026-08-08.*

**`read_icb` used one buffer for the File Entry and for the extent data reads.** The inner loop
overwrote the buffer with the first extent's content, and the next iteration of the descriptor scan
then parsed **file data as though it were the File Entry**. Any file with two or more extents -
fragmented media, or a file near the extent-length ceiling - read back a silently corrupt tail
steered by its own first extent's bytes. The earlier gates kept it bounded; the content was simply
wrong.

The data reads land in their own buffer now, and the File Entry stays intact for the whole scan.

The lesson is about the fixtures rather than the code: **a test corpus where every file fits one
extent cannot see a multi-extent bug**, and the first audit pass had read the same function without
noticing.

Smaller: the root ICB is gated at mount rather than at first read, matching its sibling; the
descriptor tag's own recorded block address is cross-checked, so a descriptor copied to the wrong
block no longer passes on its checksum alone; and the single-partition assumption is recorded in the
module documentation rather than left implicit.
