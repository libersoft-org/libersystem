# M0121 - Application graphics, raw input, and PCM audio (the app-platform layer)

Status: DONE (2026-07-14).

Applications were prisoners of the text console: the framebuffer belonged to ConsoleService and there
was no way for a program to draw, read raw keys or play sound.

*Condensed 2026-08-08.*

**The display contract is compositor-shaped from day one**, even though there is one scanout today.
DisplayService owns the physical scanout and serves *process-bound logical surfaces* with synchronous
damage presents. A program never touches the hardware, so the day a compositor exists nothing above
it changes.

The pieces that make that safe rather than merely possible:

- **Fullscreen handoff with a guaranteed return.** The foreground VT hands the display over and gets
  it back on release, on crash, or on Ctrl+Alt+Esc - which SIG_KILLs the bound process. A handoff
  with no guaranteed return is a way to lose the machine to a hung program.
- **First-frame isolation**, so a new surface cannot show whatever was in the buffer before it.
- **Resize events** and measured presentation counters.
- **Raw stateful key input** and **PCM audio playback**, each extending its existing interface rather
  than adding a parallel one.
- Three capabilities join the vocabulary: `display`, `input-keys`, `audio-stream`. A program that
  does not name them cannot reach any of it.

Presentation performance was measured rather than assumed - the nearest-neighbour scaler in the
present path was the thing to watch.
