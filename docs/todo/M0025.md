# M0025 - IDL/WIT toolchain and generators

Status: COMPLETE. The decision this milestone exists to record: **the system IDL is our own, LSIDL** -
and it was decided from a real trial rather than in advance.

*Condensed 2026-08-08.*

Five or six real interfaces were written in WIT first - storage volumes, process, log, a channel with
handle passing, an event stream with backpressure. Five sticking points came out of it:

1. wire-level capability and handle transfer,
2. zero-copy shared buffers,
3. backpressured streams,
4. a stable channel ABI, where WIT has the WASM canonical ABI,
5. `wit-bindgen` targeting WASM components rather than our channel IPC.

Those are the same reasons Fuchsia built FIDL. LSIDL keeps WIT-inspired types - records, enums,
variants, flags, results, lists, tuples, options - and adds first-class `handle`, `buffer` and stream
types. The specification is `docs/LSIDL.md`.

The generators emit the binary layout, a Rust client, a CLI formatter, JSON and CBOR, documentation
and compatibility tests from one source, so **the same call renders as binary, CLI or JSON without
anyone maintaining three renderers**.

The generated client provides a synchronous-looking `call(req) -> resp` over the non-blocking channel
- internally send, wait, receive, with a correlation id and a reply handle - and one-way event
streams are read through `wait`, never polled.
