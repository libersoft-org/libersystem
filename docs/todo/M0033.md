# M0033 - NetworkService, UDP/TCP, and the net tools as standalone programs

Status: COMPLETE. With frames flowing from M0032, this built the transport layer, the service that
exposes it, and turned the network CLI into real programs.

*Condensed 2026-08-08.*

**The seam everything else was built on** came first: the L2/L3 stack moved out of the driver into a
NetworkService of its own. Sockets are handed out as capabilities and received data arrives as an
event `stream<T>` rather than through polling.

On top of that: UDP over the IPv4 layer with ports and checksums; off-link routing through the
gateway for addresses outside the local subnet; a minimal TCP state machine with handshake, in-order
data with ack and retransmit, and ordered teardown; a DNS resolver returning a typed `Ipv4Addr`; and
a DHCP client so the box can take a dynamic address.

**The net tools became separate binaries** - `ping`, `arp`, `ip` and the rest in their own crate -
rather than shell built-ins. That is the Unix small-tools split, and it needed one mechanism the
shell did not have: a foreground program-execution primitive. Adding it here is why every later tool
could be a program instead of a branch inside the shell.

The IDL toolchain gained the `buffer` zero-copy codec, the deferred first-class type, because a
socket API that copies every payload twice is not a socket API.
