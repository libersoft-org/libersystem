# M0137 - Build layering: compile, then package

Status: COMPLETE. Green on all three architectures.

The build worked, and that was the problem: it worked **only** when driven through `just`. Nothing in
the tree stated that the kernel crate must not be built alone, or that an application could not be
built without the shared-library step - so both were possible and neither said anything was wrong.

*Condensed 2026-08-08.*

- **The manifest describes the whole system**, including a `[[boot_artifacts]]` section naming the
  boot chain. `mkimage.sh` reads it instead of carrying its own hard-coded artifact list, so the two
  cannot disagree about what a bootable image contains.
- **The kernel is independent of userspace on every architecture**, not only on x86_64 where it
  happened to be true.
- **Init-package assembly moved out of `kernel/build.rs`** into a standalone step, and packaging
  became a phase that **compiles nothing**. A phase that both compiles and packages cannot be
  reasoned about: any failure could be either.
- **A dynamically linked program that starts without one of its providers names the missing one**
  rather than failing in whatever way a null jump happens to fail.
