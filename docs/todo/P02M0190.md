# P02M0190 - TPM 2.0 for applications: a provider, a typed API and a demonstration tool

Status: OPEN. It closes when every item below is done.

THE OWNER'S DECISION (2026-09-25), IN HIS OWN TERMS: who consumes the TPM does not matter; what matters is
that the resource EXISTS in LiberSystem and is ready for third-party developers to use - shown by a small
tool that demonstrates it working. That replaces the position P02M0099 had taken, which was to wait for a
consuming service (measured boot, key storage) before exposing anything.

WHAT EXISTS. Everything under the binding is in, from P02M0099: `src/tpm` carries discovery from the ACPI
`TPM2` table, the FIFO/TIS and CRB transports over a `Registers` trait, bounded marshaling with every
response header validated, and the typed operations - Startup, SelfTest, GetRandom, PCR_Read and PCR_Extend
on the SHA-256 bank, a secret sealed to a PCR policy and unsealed, and a quote by a restricted ECDSA P-256
key. `host.tpm` holds it against models and against `swtpm` - the TCG reference implementation - with the
quote's signature verified by OpenSSL; the kernel's hardware suite drives it through QEMU's `tpm-crb` and
`tpm-tis` front-ends over `swtpm`.

WHAT IS MISSING IS EVERYTHING ABOVE THE LIBRARY, and one prerequisite below it.
  - NO DRIVER PROCESS CAN BIND THE TPM. It is not a PCI function: firmware describes it by a static ACPI
    table at a fixed address, and this system has no identity for a firmware-described device - no name,
    no claim, no MMIO capability for one. That is the firmware-node device identity, put to the owner as
    its own question on 2026-09-25. ONLY ITS FIRST STEP IS NEEDED HERE: devices from static tables, with
    no AML interpreter. This milestone REQUIRES that step and does not build it.
  - NO CONTRACT: nothing an application can call.
  - NO TOOL: nothing a person can run to see it work.

## P02M0190 - The provider

- [ ] A TPM driver process, restartable like every driver here, bound through the static-table identity:
  it maps the CRB or FIFO region the `TPM2` table names, runs `src/tpm` over it, and is the ONE owner of
  the device - commands are serialized in the driver, because a TPM executes one at a time and a second
  caller interleaving a session would corrupt the first. It starts the TPM when firmware left that to the
  OS and runs the self-test once.
- [ ] A typed contract, `liber:tpm@1`, carrying exactly the library's operations and nothing raw: random
  bytes (bounded per call), PCR read, PCR extend (the debug PCR 16 and the application range the policy
  names - never the firmware's), seal to a PCR policy and unseal, and a quote over a caller's nonce with
  the attestation and the public key returned for verification elsewhere. No command passthrough: a raw
  TPM command interface is an authority over every session and every hierarchy, and it is exactly what a
  third-party API must not be.
- [ ] THE AUTHORITY IS SPLIT BY WHAT IT CAN HURT, and PermissionManager grants each part separately:
  `tpm` (random, PCR read, quote - observation) and `tpm-measure` (PCR extend, which changes what every
  later quote and unseal answers) and `tpm-seal` (seal and unseal). Appended to the capability vocabulary,
  never inserted, so no capability's number moves.
- [ ] A client library in the shared-library set, so a third-party program links the contract the way the
  system's own tools do, and the contract's generated documentation says what each call costs and refuses.

## P02M0190 - The demonstration tool

- [ ] `tpm`, a small text tool: `tpm info` (the interface, the manufacturer, the firmware version),
  `tpm random N`, `tpm pcr N`, `tpm extend N TEXT`, `tpm seal TEXT FILE`, `tpm unseal FILE` and
  `tpm quote NONCE FILE`. It prints what the TPM answered and nothing it computed itself, so what a person
  reads is the device's answer.
- [ ] A cold development scenario gate, `qemu-tpm-tool`, with `swtpm` behind QEMU's CRB front-end: the tool's
  random bytes differ between two calls; `extend` then `pcr` shows the SHA-256 chain the GATE computes on the
  host from the text it typed; `seal` then `unseal` returns the text; an `extend` of the policy PCR makes the
  next `unseal` refuse; and the quote file's signature verifies with OpenSSL on the host against the public
  key in it. The same scenario on `tpm-tis` in a second run.

## P02M0190 - Verification

- [ ] Host tests for the contract's bounds and the driver's serialization; the three cross-builds; the
  dynamic report refreshed for the new library and tool.
- [ ] Runtime on x86_64 with both front-ends; aarch64's `tpm-tis-device` on the `virt` machine once the
  device-tree half of the identity exists; riscv64 has no TPM model in this QEMU and says so rather than
  passing.
- [ ] `docs/` gains a page for third-party developers: what the contract offers, which grant each call
  needs, and what this TPM is NOT - not a key store with backup, not a measured-boot chain until firmware
  measures the loader.

EXCLUDES: measured boot of this system's own loader and kernel (it needs firmware and loader work of its
own); localities above 0, whose PCRs belong to firmware; RSA keys; HMAC and parameter-encryption sessions;
any vendor security processor outside TPM 2.0.
