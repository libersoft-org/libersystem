# M0054 - LiberFS: extents and sparse files

Status: COMPLETE. *Condensed 2026-08-08.*

A pointer-per-block map made a 1 GB file roughly 256 000 pointers - heavy metadata, and it forced
every block to physically exist.

An extent stores a contiguous run as one start-and-length record, so a large contiguous file needs a
handful of records instead of hundreds of thousands of pointers. **Sparse files then come for free:
an unwritten region is simply a gap in the map, read back as zeros**, so a logically huge but mostly
empty file - a VM image, a preallocated database - costs only what was written.

The per-block checksums carry over the new layout, and `fsck` validates the runs and the free map
derived from them.
