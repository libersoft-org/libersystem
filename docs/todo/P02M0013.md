# P02M0013 - A simple persistent native filesystem

Status: COMPLETE. The first writable on-disk filesystem behind the existing Volume API - the service
and its typed interface unchanged, only the backend gaining writes.

*Condensed 2026-08-08. This is where LiberFS began; the copy-on-write, checksum and snapshot
machinery came in the later track.*

A host-testable crate with zero dependencies and a `BlockDevice` trait, so the same code runs against
an in-memory device under `cargo test` and against virtio-blk in the system. That decision is why
LiberFS has ever had a fast test suite at all.

The first layout was deliberately simple: 4 kB blocks, a superblock, a free bitmap, a fixed inode
table, a flat root directory and direct block pointers per inode. Enough integrity through ordered
writes that a crash mid-write does not corrupt the volume, and files created from the shell survive a
reboot.

The framing at the time is worth keeping: **the direction was fixed, not the feature set.** Multiple
filesystem backends behind one Volume API was the layering claim, and this milestone was the second
backend that proved it.
