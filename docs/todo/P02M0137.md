# P02M0137 - Remove redundant dynamic-report work from warm builds

Status: TOOLING. NOT A PHASE-2 COMPLETION GATE.

## Goal

Make a warm shared-library build pay only for work whose inputs changed.

The build cache already reports hits and no rebuilds, but the successful-build cleanup path invokes
the dynamic-report inventory check. That supposedly cheap check currently runs the full ELF report
generator through a recursive self-test before it dispatches the requested mode. The fix is to make
inventory genuinely name-only, make a full check perform one ELF sweep, and propagate failures
without weakening the report gate.

Do not add an ELF cache, benchmark platform, guest work, planner work or execution-history service in
this milestone. A content-addressed metric cache is a separate follow-up only if the explicit full
report gate remains materially slow after the duplicate sweep is removed.

## Verified diagnosis

The current call path is:

1. `build.sh` invokes `src/tools/build-shared.sh` for each requested architecture.
2. A successful non-targeted shared build reaches `report_build_summary` through its `EXIT` trap.
3. The trap calls `check_dynamic_report_inventory`.
4. That helper runs `src/tools/check-dynamic-report.sh --check-inventory`.
5. The checker loads common state and runs `self_test` before parsing the mode.
6. `self_test` recursively invokes public `--check`, which generates all three reports and scans the
   ELF graph before the outer process reaches the cheap inventory branch.

On the current graph there are 74 dynamic tools for each of three targets and 64 providers for each
target. A statically counted full sweep launches 2,352 `llvm-readelf` processes. Therefore the warm
x86_64 path hides one sweep, `--arch all` hides three sweeps, and public `--check` and `--write` each
perform two sweeps today.

The same path contains directly related correctness problems:

- the recursive self-test accepts any nonzero child status as proof that its mutation was detected;
- it mutates only `docs/DYNAMIC_EXECUTABLES.tsv`, not the wave and image reports;
- production environment variables can suppress the self-test or redirect the authoritative report;
- some `llvm-readelf` statuses are lost inside process substitutions;
- `build-shared.sh` currently turns every inventory failure into a warning and can print `status=0`
  even when the inventory stage should fail;
- targets and logical waves are repeated in several loops, while the success message says 15 waves
  although the report contains six logical waves and 18 target-wave rows.

## Scope

This milestone owns only:

- mode dispatch and dependencies in `src/tools/check-dynamic-report.sh`;
- its three tracked report files and a small disposable-fixture regression test;
- failure propagation and summary reporting in `src/tools/build-shared.sh`;
- the public dynamic-report gates and directly affected documentation;
- before/after timing of these exact paths.

It explicitly does not own permission coverage, shared kernel-test fixtures, QEMU or guest events,
planner selection, cost models, execution history, StateStore, calibration, protected evidence,
campaign infrastructure or broad documentation cleanup.

## Exit contract

The checker and its caller use this small closed contract:

| Status | Meaning                                                                         |
| -----: | ------------------------------------------------------------------------------- |
|    `0` | The requested check matched or the write completed.                             |
|    `1` | Tool, manifest, parser, I/O or other internal failure.                          |
|    `2` | Invalid mode or surplus arguments.                                              |
|    `3` | Name-only inventory differs from the tracked detailed report and needs refresh. |
|    `4` | A full generated report differs from its tracked report.                        |

Only status `3` is a nonfatal post-build warning. A negative mutation probe succeeds only when it
receives status `4` and the expected report-specific diagnostic.

## Work

- [ ] **M1.1 - Capture a lightweight baseline for the exact affected paths.**
  - Record the commit, OS and kernel, CPU and memory, Bash, compiler, `llvm-readelf` and manifest
    generator versions.
  - Prepare all target graphs once with `./build.sh --arch all --part libs`.
  - Run one warm-up and retain five raw timed samples for:
    - public `--check-inventory`;
    - a pre-change diagnostic run with only the recursive self-test suppressed;
    - `./check.sh --gate dynamic-report`;
    - warm `./build.sh --arch x86_64 --part libs`.
  - Retain command, stdout, stderr, status and build summary under an ignored
    `.build/benchmarks/dynamic-report/` directory.
  - These logs diagnose this milestone only. They are not a reusable evidence framework.

- [ ] **M1.2 - Dispatch and validate the mode before expensive setup.**
  - Zero arguments mean `--check`; otherwise require exactly one of `--check`,
    `--check-inventory` or `--write`.
  - Reject unknown modes and surplus arguments with status `2` before loading the manifest, sourcing
    `lib.sh`, locating `llvm-readelf`, creating temporary files or reading tracked reports.
  - Remove `DYNAMIC_REPORT_SELF_TEST` and `DYNAMIC_REPORT_OVERRIDE` from the production interface.
    Tests pass fixture paths only to private functions or a dedicated test entry point.
  - A spy fixture proves that usage errors perform zero manifest, temporary-file and ELF work.

- [ ] **M1.3 - Make inventory a real name-only path.**
  - Inventory reads only the manifest tool names, `TOOL_WAVES` keys and the x86_64 tool-name column
    from `docs/DYNAMIC_EXECUTABLES.tsv`.
  - It does not require `llvm-readelf`, inspect artifacts, generate reports or run mutation probes.
  - A missing detailed report or a name mismatch returns status `3`; malformed manifest data,
    manifest-versus-wave inconsistency and parser failure return status `1`.
  - On the current manifest, success reports 74 checked tools and makes zero `llvm-readelf` calls.

- [ ] **M1.4 - Generate each full candidate set once and test comparison without recursion.**
  - Separate candidate generation, format validation and authoritative comparison into internal
    functions.
  - `--check` generates one candidate triplet, validates it, compares it once, and only after a match
    runs three cheap negative probes against copies of those candidate files.
  - Each probe mutates a different report and must receive status `4` plus its expected diagnostic.
  - `--write` performs one generation and no negative probe.
  - Cache immutable per-artifact header metrics inside that single generation when multiple report
    aggregations consume them; do not add a persistent cross-run cache.

- [ ] **M1.5 - Fail closed on subprocess and parser errors.**
  - Capture and check the status of every `llvm-readelf` invocation, including writable and immutable
    segment metrics and provider exports that currently run in process substitutions.
  - Never publish a partial or defaulted metric after a child failure.
  - A shim that prints plausible partial output and exits nonzero must produce status `1` before any
    comparison or write for every repaired consumer.
  - A malformed real-artifact fixture proves that the relevant parser path was actually reached.

- [ ] **M1.6 - Propagate inventory status and print a truthful build summary.**
  - Run inventory only after a successful non-targeted shared build.
  - Treat status `3` as a warning; propagate status `1`, `2`, signals and unknown statuses as fatal.
  - Preserve an earlier build failure and do not let cleanup replace it.
  - Print `inventory_status=not-run|match|refresh-required|fatal`, a diagnostic inventory duration,
    and a final `status=` equal to the process exit status.
  - Targeted shared builds, kernel-only builds and failed shared builds do not run inventory.

- [ ] **M1.7 - Add bounded regression fixtures and safe fixed-triplet publication.**
  - Add `src/tools/check-dynamic-report-regressions.sh` and expose it as the
    `dynamic-report-regressions` gate.
  - Run all mode, status, mutation, subprocess and build-summary cases in a disposable fixture root.
    Hash the three tracked TSV files and `lib.sh` before and after the matrix.
  - Test `--write` against a temporary output root, never through a production environment override
    and never against the tracked reports.
  - Keep report publication local to this fixed triplet: one writer lock, same-filesystem staging,
    validation before publication, and a small recoverable pending marker or old/new snapshot around
    the three renames. Readers take the matching read lock or reject an in-progress publication.
  - Inject failure at each rename in a disposable checkout and prove that readers see either the old
    complete triplet or the new complete triplet. Do not introduce a general transaction store.

- [ ] **M1.8 - Derive cardinalities once and correct only affected documentation.**
  - Define targets and logical waves once and derive loops, row counts and messages from those
    collections.
  - Current expected values are 74 tools per target, six logical waves, 18 target-wave rows, and file
    line counts 224, 20 and 5 for detailed, wave and image reports.
  - Update the dynamic-report sections in `docs/DYNAMIC_LINKING.md`, `docs/DEBUG.md` and
    `docs/PERF.md`. Remove the nonexistent `just dynamic-report-check` command and stale five-wave or
    48-tool claims.
  - Document `./check.sh --gate dynamic-report` as the public check and
    `(cd src && just dynamic-report-update)` as the writer. State that the check reads built artifacts;
    it does not rebuild them.

- [ ] **M1.9 - Close with functional regression and direct warm-path measurements.**
  - Structural spies prove: invalid usage performs no setup; inventory performs zero report
    generations and zero ELF reads; `--check` and `--write` each perform exactly one generation.
  - Warm x86_64 performs one cheap inventory and no hidden report generation or ELF read in the
    report stage. `--arch all` performs three cheap inventories and no hidden generation.
  - Targeted and kernel-only builds perform zero inventories.
  - The median inventory stage and warm-build report stage are each at most two seconds on the
    baseline host.
  - The median full dynamic-report gate is at most 65% of its pre-change median, with the same built
    inputs and tracked report bytes.
  - All regression gates pass, the tracked report hashes are unchanged unless an intentional report
    update was part of the change, and the working tree contains no temporary report artifacts.
  - If the explicit full gate is still a material bottleneck, record a separate cache proposal with
    fresh profiling data. Do not add it here.

- All nine tasks above are complete.
- The recursive public self-invocation and both production test-bypass environment variables are
  gone.
- Inventory is name-only and full check/write perform one generation each.
- The exit contract is covered at both checker and build-wrapper boundaries.
- The fixed three-report publication is recoverable without a general persistence framework.
- The directly affected documentation matches the actual public commands and cardinalities.
- Before/after raw samples and summaries are retained in the ignored benchmark directory.
- These commands pass from the repository root:

```sh
bash -n \
  src/tools/check-dynamic-report.sh \
  src/tools/check-dynamic-report-regressions.sh \
  src/tools/build-shared.sh \
  build.sh check.sh
./check.sh --gate dynamic-report-regressions
./build.sh --arch all --part libs
./check.sh --gate dynamic-report,dynamic-report-regressions
git diff --check
./verify.sh
```

Do not use the writer command as a validation command. It intentionally changes tracked reports.
