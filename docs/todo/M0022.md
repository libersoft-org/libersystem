# M0022 - LogService (structured logging)

Status: COMPLETE. **The journald model, not syslog:** records are structured data, never lines of
text.

*Condensed 2026-08-08.*

The canonical `LogRecord { ts, severity, source, fields }` lives in the shared `abi` crate, so
emitters, the service and the kernel agree on it byte for byte. **The compact little-endian binary
encoding IS the object**; text, JSON and CBOR are three renderings derived from it, all `no_std` and
heap-free into a caller buffer.

That ordering is the point. A system whose canonical form is text has already lost the fields.

LogService keeps a bounded journal of canonical record bytes and serves emit and query, with the
query taking a format and a minimum severity. ServiceManager holds a client and emits a lifecycle
record as each service comes up.

Recorded at the time: the journal is a fixed ring - eviction policy and persistence came later - and
the timestamp is the monotonic tick, because calendar time needs an RTC and a TimeService.
