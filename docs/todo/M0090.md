# M0090 - FAT: third-pass findings (the cluster range gate and the leftovers)

Status: COMPLETE. A third full source pass over the FAT implementation, after M0086-M0089.

*Condensed 2026-08-08.*

**The one that mattered: cluster values off the medium were never range-checked.** A `first_cluster`
read from a directory entry became a table offset and then a sector address without anything
verifying it was inside the heap. `next_cluster`, `set_fat_entry`, the chain walk and `last_cluster`
all refuse an out-of-range value as `Invalid` now, before it can be turned into an address.

The rest, each a small hole with a clear shape:

- **An exFAT directory could not grow** - there was no grow path at all. `Dir` now carries its parent's
  handle fields and entry-set byte range, so the exFAT path grows the way the classic one does.
- **Windows-illegal characters passed into long names.** Refused as `Invalid` beside the existing
  dot-and-space gate, for both families.
- **Degenerate boot-sector pointers still mounted** - FAT32 `root_cluster < 2` among them. All four
  refused at mount, each forged separately in the test.
- **A mid-allocation I/O failure leaked clusters.** Both allocators unwind the slots already written,
  and exFAT writes the FAT before the bitmap so a failure leaves the bitmap untouched.
- **Timestamps were zeroed** - an invalid DOS pair. `set_clock` plus a DOS encoder clamped to
  1980-2107, so an unset clock still produces a legal value.
