# P02M0081 - Filesystem stack unification and performance

Status: COMPLETE.

Four filesystem crates had grown four slightly different `BlockDevice` traits and error enums, and
the storage service routed volumes through a hand-written enum with a match arm per backend.

*Condensed 2026-08-08.*

- **One `fscore` crate** (`src/fs/core`, `no_std`, no dependencies) holds the single `BlockDevice`
  trait and the single `FsError`. The trait is block-size agnostic, so a backend is not forced to
  pretend its blocks are 512 bytes.
- **Storage routes through a `FileSystem` trait** rather than an enum: read, list, capacity and
  status are the universal operations, and the mutation and snapshot operations default to the
  read-only answer. Adding a backend stops meaning editing a match in the service.
- **A decompressed-extent LRU** of 8 runs replaced LiberFS's single-slot cache, keyed by each run's
  first stored block.
- The incremental free map this milestone asked for had already been delivered by P02M0044.

The general point: four copies of a trait are four chances for a backend to be subtly different in a
way only one caller notices.
