# P02M0093 - Shared system libraries (dynamic linking)

Status: DONE (2026-07-14) **as the loader/provider pilot**. The broad executable rollout the original
wording implied did not land here; P02M0096a owns and hard-gates it after the full `/bin` conversion.

*Condensed 2026-08-08.*

**The compatibility model was decided first and written down**, in `docs/DYNAMIC_LINKING.md`, before
anything was built. That ordering is the point: a dynamic linking scheme whose compatibility rule is
discovered afterwards has already shipped incompatible artifacts.

The constraint that shaped everything: **the bare targets support neither Rust `dylib` nor
`cdylib`**. So the pinned builder emits full-graph PIC rlibs and links deterministic ELF shared
objects from them, rather than relying on a Rust-level dynamic library that does not exist for these
targets.

The library set is atomized - one library, one concern, with real dependency edges between them
rather than a single bag of shared code.
