# P02M0136 - Text foundation: shaping, fallback and layout

Status: FUTURE TRACK. DEPENDS ON P02M0103b (`render2d`'s glyph-run seam). NOT A PHASE-2 COMPLETION
GATE.

Created 2026-08-15 alongside `P02M0103`'s seventh pass. `render2d` draws a `GlyphRun` - glyphs that
are already chosen, already shaped and already positioned - and that seam is deliberate: a rasteriser
has no business knowing what a script is, and a shaping engine has no business knowing what a
coverage mask is. But the seam only divides the work; it does not do half of it. Without this
milestone LiberSystem can draw text it is handed and cannot produce text from a string, which is not
a platform ordinary applications can be written on.

The division of labour, stated once so neither milestone drifts into the other:

    P02M0136                                    P02M0103b / P02M0103c
    font files, character to glyph,             glyph outlines to coverage,
    script shaping, fallback, BiDi,             masks, colour glyphs, bitmap
    line breaking, positioning                  strikes, transforms, caching
                            \                  /
                             ->  GlyphRun  <-

Everything below is about producing a correct `GlyphRun`. Nothing below rasterises anything.

That division has one consequence worth stating, because getting it wrong makes the two milestones
wait for each other. `P02M0103` proves the RASTERISATION half against PRE-DECODED FIXTURES - a glyph
outline, a bitmap strike, a colour glyph - and deliberately does not open a font file, because
opening one needs the parser below and the parser below needs `render2d` to draw with. **The first
real font file this system reads is read here**, and the end-to-end proof - font file to shaped run
to pixels - is this milestone's, against the renderer `P02M0103` already delivered. Neither side
writes a throwaway parser.

- [ ] Parse OpenType and TrueType fonts with every length, offset and index checked before use, and
  treat a font file as HOSTILE INPUT throughout - a font is untrusted content that arrives from a
  document, a download or a package, and font parsers are a classic memory-safety target. Required
  tables: `cmap`, `glyf`/`loca`, `CFF`/`CFF2`, `head`, `hhea`, `hmtx`, `maxp`, `name`, `OS/2`,
  `post`, `GSUB`, `GPOS`, `GDEF`, `kern`, plus `COLR`/`CPAL` and `sbix`/`CBDT`/`CBLC` for colour and
  bitmap glyphs and `fvar`/`gvar`/`avar` for variable fonts. Every parser is fuzzed and every
  malformed table is a typed refusal rather than a panic or a wild index.

- [ ] Implement Unicode segmentation over a versioned, generated character-property table rather than
  hand-written ranges: grapheme cluster, word and line-break boundaries, plus the character classes
  shaping needs. State the Unicode version the tables are generated from and regenerate rather than
  patch.

- [ ] Implement the bidirectional algorithm - paragraph level detection, embedding levels, isolates,
  overrides, mirroring and reordering into visual runs. Half a BiDi implementation is worse than none,
  because it renders Arabic and Hebrew text that looks plausible and is wrong.

- [ ] Implement complex-script shaping over `GSUB`/`GPOS`: feature selection, script and language
  systems, ligatures, contextual and chaining substitution, marks and mark attachment, cursive
  attachment, kerning and the Indic, Arabic, Hebrew, Thai and Khmer shapers those scripts need. Latin
  alone is the case that makes a design look finished and proves nothing.

- [ ] Implement font fallback as a policy with a stated order rather than an accident of enumeration:
  a per-script and per-language preference list, a last-resort face, and deterministic selection so
  the same string with the same installed faces always produces the same run. Fallback that depends
  on directory order is a rendering difference between two machines.

- [ ] Support variable fonts: named instances and arbitrary axis coordinates, with the resulting
  outlines and metrics correct at any coordinate rather than only at the named instances.

- [ ] Produce the `GlyphRun` `render2d` consumes: face, size, variation coordinates, glyph indices,
  offsets in fractional units, cluster mapping back to the source string, direction, and the flags
  that tell the rasteriser which glyph kind each entry is. The cluster mapping is not optional - it
  is what a caret, a selection, a hit test and an accessibility tree are built from.

- [ ] Implement line layout above shaping: measurement, line breaking with the Unicode algorithm,
  justification, tabs, alignment, direction-aware line composition, ellipsis and truncation, and
  the caret and selection geometry that follows from the cluster mapping.

- [ ] Bound everything and account it: a font cache and a shaping cache with stated eviction, bounded
  per-run glyph counts, bounded fallback depth, and every allocation charged to the calling Domain.
  A document that asks for a pathological run meets a typed refusal rather than an allocation.

- [ ] Host tests over a pinned corpus with expected glyph indices and positions per case: Latin with
  ligatures and kerning, Arabic in all four joining forms, Hebrew with marks, Devanagari reordering,
  Thai without spaces, Khmer stacking, mixed-direction paragraphs, emoji sequences including ZWJ and
  skin-tone modifiers, and variable-font instances. Fuzz every parser and the shaper itself; prove no
  panic, no unbounded allocation and no out-of-bounds read on any malformed font.

- Done when: a string in any of the tested scripts becomes a correct `GlyphRun` that `render2d`
  renders, line layout produces caret and selection geometry, fallback is deterministic, the corpus
  tests pass on all three architectures, and every parser survives fuzzing.
- Explicitly deferred: a full text-editing widget, rich-text markup parsing, hyphenation dictionaries,
  vertical writing modes, and font hinting - each a separately approved milestone.
- Concept: P02M0103 (the graphics platform and the `GlyphRun` seam), P02M0097 (where font packages
  live), P02M0093/P02M0096a (shared providers and package identity).
