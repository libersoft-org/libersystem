# P02M0136 - Text foundation: shaping, fallback and layout

Status: FUTURE TRACK. NOT A PHASE-2 COMPLETION GATE.

DEPENDS ON `P02M0103b` for the frozen `GlyphRun` and font-resource contract, and on `P02M0103c` for
the conforming `soft2d` renderer its end-to-end proof draws with. Corrected 2026-08-30 after the
2026-08-30 plan audit: the original status line named `P02M0103b` alone, and `P02M0103b` is the
backend-neutral PROFILE with backend-free host tests - it delivers no renderer, so the mandatory
"font file to pixels" gate had nothing to run against. The two dependencies are different in kind and
are now named separately:

- the SHAPING and LIBRARY work depends on a resolved `P02M0103b` `GlyphRun` and font-resource
  contract, and may start as soon as that contract is frozen;
- the INTEGRATION and Done gate depends on `P02M0103c`'s conforming renderer.

THE `DrawList` PRECONDITION IS NOW MET, and it is recorded here because it was the reason this
milestone could not start. `P02M0103b` carried two mandatory `DrawList` contracts - an immutable
in-process replayable list in one item and a transportable cross-process format in another - and the
font resource is carried by whichever wins, since its lifetime, its transport and whether a raw
reference may appear in a list all differ between them. Implementing the shared seam against the
loser would have meant replacing it. `P02M0103` DECIDED IT on 2026-08-30: Profile 1's `DrawList` is
immutable, versioned, cacheable and replayable IN-PROCESS, carrying a typed resource TABLE - not
inline references - with cross-process transport becoming the named `render2d-wire` extension.
So the font resource is a TYPED HANDLE INTO A PROCESS-LOCAL RESOURCE TABLE, and the contract frozen
by the first item below is written against that and nothing else.

Created 2026-08-15 alongside `P02M0103`'s seventh pass. `render2d` draws a `GlyphRun` - glyphs that
are already chosen, already shaped and already positioned - and that seam is deliberate: a rasteriser
has no business knowing what a script is, and a shaping engine has no business knowing what a
coverage mask is. But the seam only divides the work; it does not do half of it. Without this
milestone LiberSystem can draw text it is handed and cannot produce text from a string, which is not
a platform ordinary applications can be written on.

The division of labour, stated once so neither milestone drifts into the other:

    P02M0136                                    P02M0103b / P02M0103c
    font files, character to glyph,             glyph outlines to coverage,
    script shaping, fallback, BiDi,             masks, colour glyphs, bitmap
    line breaking, positioning                  strikes, transforms, caching
                            \                  /
                             ->  GlyphRun  <-

Everything below is about producing a correct `GlyphRun`. Nothing below rasterises anything.

That division has one consequence worth stating, because getting it wrong makes the two milestones
wait for each other. `P02M0103` proves the RASTERISATION half against PRE-DECODED FIXTURES - a glyph
outline, a bitmap strike, a colour glyph - and deliberately does not open a font file, because
opening one needs the parser below and the parser below needs `render2d` to draw with. **The first
real font file this system reads is read here**, and the end-to-end proof - font file to shaped run
to pixels - is this milestone's, against the renderer `P02M0103c` delivered. Neither side writes a
throwaway parser.

## The seam is not yet a contract, and it is this milestone's first item

The audit's sharpest finding: neither milestone says how a glyph ID becomes geometry. This side
produces glyph indices; that side must rasterise outlines, masks, bitmap strikes and `COLR` paint
graphs - and nothing owns the validated font bytes, the decoded glyph data, the lookup, the lifetime
or the identity between them. A glyph index and a kind flag cannot be drawn.

Two further consequences fall out of the same hole. `P02M0103`'s glyph cache is keyed by face, size,
transform and subpixel phase - which omits the variation coordinates this milestone promises, and the
palette and strike selection colour and bitmap glyphs need, so two different instances of one face
collide in that cache and render stale pixels. And fallback produces runs over SEVERAL faces while
this milestone's `GlyphRun` carries a singular `face`, so the output of the fallback item cannot be
expressed in the type the seam item defines.

- [ ] **Freeze ONE shared font-resource contract before either side implements against it.** Owned
  jointly with `P02M0103b` and written once. It states:
  a content-derived face identity plus face index, so two loads of the same bytes are one face and a
  changed file is a different one; ownership of the immutable validated backing, and the rule that no
  decoded structure holds a raw reference into bytes that can move; bounded access to decoded
  resources - outline, grayscale/subpixel mask source, bitmap strike, `COLR` v0 layers and v1 paint
  graph - as explicit resource forms rather than a category; lifetime, generation and invalidation,
  so a replaced face invalidates what was derived from it; and whether a layout result is a sequence
  of face-, script- and direction-homogeneous `GlyphRun`s or one run carrying per-glyph face
  references. THE FIRST IS THE ANSWER unless a measurement says otherwise, because it is the one that
  matches both fallback's output and `render2d`'s per-run paint and cache key.
  `P02M0103`'s glyph cache key is corrected in the same change to face IDENTITY AND GENERATION,
  glyph, size, variation coordinates, transform, subpixel phase, glyph kind, and strike and palette
  where they apply.

- [ ] Parse OpenType and TrueType fonts with every length, offset and index checked before use, and
  treat a font file as HOSTILE INPUT throughout - a font is untrusted content that arrives from a
  document, a download or a package, and font parsers are a classic memory-safety target. The tables
  are the ones the published profile below names. Every parser is fuzzed and every malformed table is
  a typed refusal rather than a panic or a wild index.

- [ ] **Publish a CLOSED OpenType profile, and refuse what is outside it.** "Parse `CFF`/`CFF2`" and
  "correct at any coordinate" cannot both be met by a table list: producing outlines from `CFF`/`CFF2`
  needs a bounded Type 2 / CFF2 charstring interpreter with subroutines, variation-store selection
  and `blend`; and correct METRICS at a non-default coordinate needs `HVAR` for horizontal advances -
  which is also what varies CFF2 advances - and `MVAR` for the font-wide metrics line layout reads.
  Neither appeared in the table list while both were promised by the requirement above it.
  The profile is a document with a version, and it states: the exact table versions supported;
  `GSUB`/`GPOS` lookup types and flags, including `FeatureVariations` and device/variation
  adjustments; the `COLR` v0/v1 and variable-paint subset; the bitmap formats
  (`sbix`/`CBDT`/`CBLC`); the variation mechanisms (`fvar`, `gvar`, `avar`, `HVAR`, `MVAR`, and CFF2
  variation behaviour); and the finite list of supported scripts and languages. Anything outside it
  is a typed `Unsupported` refusal, not undefined behaviour and not a silent wrong result.
  "Indic" is not a profile entry. Name the scripts.

- [ ] Implement Unicode segmentation over a versioned, generated character-property table rather than
  hand-written ranges: grapheme cluster, word and line-break boundaries, plus the character classes
  shaping needs. State the Unicode version the tables are generated from, pin the source data files
  by SHA-256, and regenerate rather than patch.

- [ ] Implement the bidirectional algorithm - paragraph level detection, embedding levels, isolates,
  overrides, mirroring and reordering. Half a BiDi implementation is worse than none, because it
  renders Arabic and Hebrew text that looks plausible and is wrong.

- [ ] Implement complex-script shaping over `GSUB`/`GPOS`: feature selection, script and language
  systems, ligatures, contextual and chaining substitution, marks and mark attachment, cursive
  attachment, kerning, and the shapers the profile's named scripts require. Latin alone is the case
  that makes a design look finished and proves nothing.

- [ ] **State the pipeline as ONE ordered sequence with typed intermediates, not as a list of
  algorithms.** The items above and below are stages, and their order is normative because plausible
  orders are wrong in ways that look right. In particular BiDi is NOT one paragraph-level reorder:
  UAX #9's reordering is applied PER LINE, after line boundaries are known, so a paragraph reordered
  once and then wrapped is wrong wherever it wraps. The order is:
  UTF-8 validation and canonical-equivalence policy; itemisation into grapheme, script and language
  runs; BiDi paragraph level and embedding-level resolution; face fallback, applied
  cluster-atomically; shaping per face-, script- and direction-homogeneous run; width measurement;
  line breaking; boundary-sensitive reshaping where a break changed a joining or contextual context;
  and finally per-line visual reordering and mirroring.
  Logical source spans and resolved BiDi levels are RETAINED through wrapping - they are the inputs
  the last stage needs. State Script and Script_Extensions handling, that language is an explicit
  input rather than ambient state, when reshaping is repeated, and the missing-glyph retry rule.
  Bind the behaviour to pinned versions of UAX #9 and UAX #29.

- [ ] Implement font fallback as a policy with a stated order rather than an accident of enumeration:
  a per-script and per-language preference list, a last-resort face, and deterministic selection so
  the same string with the same installed faces always produces the same runs. Fallback that depends
  on directory order is a rendering difference between two machines. Fallback operates on whole
  clusters and syllables; splitting a combining sequence, an Indic syllable, an Arabic joining
  context or an emoji ZWJ sequence across two faces is the defect this item exists to prevent.

- [ ] Support variable fonts: named instances and arbitrary axis coordinates, with outlines AND
  metrics correct at any coordinate rather than only at the named instances - which is what makes
  `HVAR` and `MVAR` profile entries rather than optional extras.

- [ ] **Produce the `GlyphRun` `render2d` consumes, with every unit and representation fixed.** Face
  resource and generation, size, variation coordinates, glyph indices, offsets and advances,
  direction, and the flags that tell the rasteriser which glyph kind each entry is. Fixed once, not
  per implementation: the source-span unit (UTF-8 byte offsets into the original string) and whether
  spans are stored in logical or visual order; the numeric representation of offsets, advances and
  origins, with its rounding and overflow behaviour; the glyph origin convention.
  The CLUSTER MAPPING is not optional and not a single index - it is what a caret, a selection, a hit
  test and an accessibility tree are built from, and one cluster-start integer cannot express a
  ligature caret, RTL affinity or a discontiguous BiDi selection. It carries: the source RANGE per
  cluster, intra-ligature caret positions, caret affinity, and the logical-to-visual mapping from
  which selection geometry is derived.

- [ ] Implement line layout above shaping: measurement, line breaking with the Unicode algorithm,
  justification, tabs, alignment, direction-aware line composition, ellipsis and truncation, and
  the caret and selection geometry that follows from the cluster mapping.

- [ ] **PREREQUISITE, NOT OWNED HERE: a font package role and a catalogue owner.** The plan cited
  `P02M0097` as "where font packages live" and it is not there: `P02M0097`'s final volume layout
  declares `bin/`, `libexec/`, `lib/`, `drivers/`, `components/`, `log/`, `audio/` and `wallpapers/`
  and deliberately no `share/`, and the manifest validator admits factory data only at `hello.txt`,
  `motd.txt`, `audio/test.mp3`, `wallpapers/*.webp` and `bin/lico/syntax/*.syntax`. The first real
  font cannot be staged, and deterministic fallback has no installed set to enumerate.
  A separately approved `P02M0097`-compatible addition must provide: the canonical font destination
  and its manifest role; the licensed, pinned last-resort face and the conformance corpus, staged the
  same way; a bounded catalogue owner with stable face identity and a deterministic tie-break order;
  the capability path by which an ordinary application reaches system faces - font bytes or a
  read-only MemoryObject, never an ambient directory scan; and the update and cache-invalidation
  rule.
  This milestone states whether parsing, catalogue and cache are IN-PROCESS or service-owned, and
  the two answers differ in accounting: in-process charges the caller's Domain automatically, while a
  service-owned cache is charged to the service and therefore needs stated per-client quotas.
  IN-PROCESS IS THE ANSWER unless the catalogue forces otherwise, because it is the one whose
  accounting the plan already promises.
  Script and language are explicit inputs - a BCP-47 value - and any SYSTEM DEFAULT depends on
  `P02M0105`, which does not exist yet. Until it does there is no default and the caller states the
  language; an implicit locale would be policy this architecture deliberately does not have.

- [ ] **Bound the recursive and multiplicative work, not only the caches, and make refusal typed.**
  Cache eviction, per-run glyph counts and fallback depth are three limits and none of them bounds
  the work a structurally VALID font can demand. Numeric limits are stated for: font, file and table
  bytes; composite-glyph depth and total point expansion, with cycle detection; CFF/CFF2 subroutine
  recursion depth and operand-stack size; `COLR` paint-graph depth and node count; contextual
  `GSUB`/`GPOS` traversal depth and output expansion; axis, region and feature counts; BiDi control
  nesting; repeated shaping and fallback attempts; and layout passes per line and per paragraph.
  Checked offsets prevent an out-of-bounds read; they do not prevent a valid font from exhausting
  time, stack or the caller's Domain.
  ALLOCATION IS FALLIBLE ON THIS PATH. Userspace infallible allocation exits the process when it
  fails, so "charged to the calling Domain" does not by itself produce the typed refusal this
  milestone promises: parser, cache and layout allocations use the fallible forms, cache insertion is
  transactional, and a refusal rolls back partial insertion and releases its charges. Deterministic
  work accounting makes the same input meet the same limit on every architecture.

- [ ] **Host gates.** Run the NORMATIVE Unicode conformance files for the pinned version -
  `GraphemeBreakTest`, `WordBreakTest`, `LineBreakTest`, `BidiTest`, `BidiCharacterTest` - pinned by
  SHA-256, not a representative sample. Over a pinned corpus with pinned font versions, file hashes
  and compatible notices, assert expected glyph indices and positions for: Latin with ligatures and
  kerning, Arabic in all four joining forms, Hebrew with marks, Devanagari reordering, Thai without
  spaces, Khmer stacking, mixed-direction paragraphs, emoji sequences including ZWJ and skin-tone
  modifiers, and variable-font instances at named and arbitrary coordinates including cases where
  metrics vary independently of outlines. Add negative cases for fallback determinism, cache
  invalidation across a face generation change, every numeric limit above, caret affinity and
  discontiguous selection. Fuzz every parser and the shaper: no panic, no unbounded allocation, no
  out-of-bounds read on any malformed font.

- [ ] **Guest gate.** A staged, governed text-and-render conformance executable runs in a booted
  guest on x86_64, aarch64 and riscv64: it loads a real font from its staged package, shapes and
  lays out the corpus, draws through `render2d`/`soft2d`, and compares against a canonical raster
  oracle within the tolerance `P02M0103s` fixes. "Host tests pass on all three architectures" has no
  executable meaning - this tree distinguishes host gates from code run in a booted target - and the
  three-architecture claim belongs to this gate. Both gates are wired into `verify.sh`, and a focused
  mutation of each new gate is watched to fail so the evidence is not vacuous.

- Done when: the shared font-resource contract is frozen and implemented on both sides; the published
  OpenType profile is met and everything outside it is a typed refusal; the pinned Unicode
  conformance files pass; a string in every profile-named script becomes a correct `GlyphRun` that
  `soft2d` renders to the canonical raster oracle in all three guests; line layout produces caret and
  selection geometry including ligature carets and discontiguous selection; fallback is deterministic
  and cluster-atomic; every stated limit is enforced with a typed refusal and released charges; and
  every parser survives fuzzing.
- Explicitly deferred: a full text-editing widget, rich-text markup parsing, hyphenation dictionaries,
  vertical writing modes, and font hinting - each a separately approved milestone.
- Required and NOT owned here: the `P02M0097`-compatible font package role and catalogue owner, and
  `P02M0105` for any system default language. (`P02M0103`'s `DrawList` decision was the third and is
  met as of 2026-08-30.)
- Concept: P02M0103 (the graphics platform and the `GlyphRun` seam), P02M0097 (the volume layout a
  font package role must extend), P02M0093/P02M0096a (shared providers and package identity).
