# P02M0182 - A capability-scoped smart-card service

Status: OPEN. It closes when every item below is done, and not before.

**WHY THE DRIVER MAY NOT BE THE SERVICE.** P02M0099's USB CCID item is explicit: the transport
parses class and slot capabilities, powers and negotiates card parameters and exchanges bounded
APDUs - and it must not contain PIN handling or authentication policy. Those are the parts that
decide who may use a card, and a decision that lives inside a process holding a USB claim is a
decision an attacker who reaches that process has already made.

**AND IT EXISTS BECAUSE THE OWNER SAID SO (2026-09-21)**, answering P02M0099's question about the
nine unowned destinations.

## The shape

- [ ] A typed `liber:smartcard@1` interface: readers, slots, card presence, ATR, and a bounded
  APDU exchange with an explicit timeout and an abort. Each reader is reached through a capability,
  so "this application may talk to this reader" is a fact the system can state.
- [ ] PIN VERIFICATION IS THE SERVICE'S AND THE PIN NEVER CROSSES A CLIENT BOUNDARY. A reader with
  a pinpad verifies on the reader; one without needs a trusted input path, which this milestone
  names as a dependency rather than inventing.
- [ ] Transaction scoping, so a client holding a card for a multi-step operation is not interleaved
  with another - and a bound on how long it may hold one, because a client that never releases is a
  reader nobody else can use.
- [ ] Insertion and removal as typed events with bounded queues, and a card removed mid-transaction
  reported as exactly that rather than as a failed APDU.
- [ ] Host tests over the decisions that are pure - ATR parsing, the T=0 and T=1 protocol state
  machines, malformed lengths and sequence identifiers - with deterministic mutations.
- [ ] A guest gate over an emulated reader, registered in the verification model in the same change.

## Definition of done

Done when a client holding a reader capability can wait for a card, read its ATR and exchange
bounded APDUs under a transaction with a timeout; when PIN handling is the service's and no client
path carries one; when the protocol state machines are host-tested against hostile input; and when
the guest gate and its model entry land with the code.

## What it unblocks

P02M0099's **USB CCID smart-card class**.
