# P02M0012 - The Liber component ABI + a Rust component SDK

Status: COMPLETE (2026-06-28) for what it built; RENAMED 2026-08-11 to what that is.

The title said "Full Component Model + WASI preview 2 + an SDK" and the thing built is a small,
capability-oriented core-Wasm ABI with a Rust SDK, running on this project's own interpreter. There
is no `.wit` file in this repository, no wit-bindgen, no canonical ABI and no component encoding.
The design is good; the name described a different one, and a name that describes a different thing
is how an audit - or a newcomer - is told a component exists which does not.

So this milestone is the Liber component ABI, and it is complete as that. The decision was
P02M0130's to make and it is made: **this is a Liber component ABI and a Liber Rust SDK.** WASI
Preview 2 remains a thing this system may want later, and if it is wanted it is its own milestone -
WIT definitions, versioned worlds, the canonical ABI, component encoding, generated bindings,
resources and handles, the standard WASI interfaces and the other two languages are all outstanding
work, none of which is hidden inside this one.

The history is worth keeping because it is the failure mode, not the mistake: the commit that opened
this milestone said "usable subset, Rust done, C and Go remaining", and the 2026-08-08 condensation
lost the qualifier. A summary that drops a qualifier turns a subset into the full thing, and nothing
downstream can tell.

P01M0011 had run a minimal Wasm component over an integer-subset interpreter with one host import.
This grew the host into an application runtime.

*Condensed 2026-08-08. Renamed 2026-08-11.*

- The Wasm runtime handles control flow, floats and the wider instruction set - enough to run a real
  toolchain-built component rather than a hand-shaped one.
- **The world maps onto the services that already exist**: `liber:vfs@1` onto StorageService,
  `liber:log@1` onto LogService. Nothing new is invented for Wasm; a component reaches the same
  services through the same capabilities a native program does. (The world is named and versioned as
  of P02M0130; it was three unversioned strings before that.)
- Components load from a `vol://` package and launch as ordinary governed processes.
- A Rust SDK builds a component against that world. C and Go are not done and are not claimed.

The test that matters is the last one: a component built by an external toolchain, loaded from
storage, with its imports wired to real services - and, since P02M0130, with the file it wrote read
back off the volume, because the earlier version of that test compared a copy taken before the write
and could not have failed.
