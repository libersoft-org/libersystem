# P02M0012 - Full Component Model + WASI preview 2 + an SDK

Status: COMPLETE (2026-06-28) FOR THE SUBSET IT ACTUALLY BUILT, and the title overstates it.
Corrected 2026-08-10: there is no `.wit` file in this repository, no wit-bindgen, no canonical ABI
and no component encoding. What exists is a capability-oriented core-Wasm ABI (`liber.read`,
`liber.write`, `liber.log`) with a Rust SDK, running on this project's own interpreter - a good
design under a name that describes a different one. The commit that opened this milestone said
"usable subset, Rust done, C and Go remaining"; the 2026-08-08 condensation lost the qualifier.
P02M0130 carries the decision: rename to what this is, or reopen for WASI Preview 2.

P01M0011 had run a minimal Wasm component over an integer-subset interpreter with one host import. This
grew the host into an application runtime.

*Condensed 2026-08-08.*

- The Wasm runtime handles control flow, floats and the wider instruction set - enough to run a real
  toolchain-built component rather than a hand-shaped one.
- **WASI preview 2 worlds map onto the services that already exist**: `wasi:filesystem` onto
  StorageService and so on. Nothing new is invented for Wasm; a component reaches the same services
  through the same capabilities a native program does.
- Components load from a `vol://` package and launch as ordinary governed processes.
- An SDK builds a component against the WIT worlds for Rust, C and Go.

The test that matters is the last one: a component built by an external toolchain, loaded from
storage, with its imports wired to real services.
