# P02M0183 - A typed modem service

Status: OPEN. It closes when every item below is done, and not before.

This owns the service prerequisite for P02M0099's USB CDC-MBIM item. ModemService owns SIM,
registration and context policy; NetworkService owns IP configuration and traffic. Subscriber
identity and management commands are separate authorities from data use. The owner requested
this destination on 2026-09-21.

Current NetworkService expects an Ethernet `MAC` greeting, runs DHCP, opens the first published
NIC and closes its catalogue subscription. A modem cannot use that path by publishing raw IP
bytes as Ethernet. The minimum raw-IP attachment and persistent network lifecycle below belong
here, not to an assumed prerequisite already implemented elsewhere.

## P02M0183a - Contracts, deployment and authority

- [x] Add `src/idl/modem.lsidl` (`liber:modem@1`) and a separate versioned
  `modem-device.lsidl` provider contract. Public records contain bounded device inventory,
  SIM presence/lock state, registration, operator, signal with validity, contexts and typed
  failures. Missing measurements are unknown. Scoped handles name provider publication identity,
  service incarnation, SIM generation and context generation; a reused session number is not
  the old context. Exclude subscriber identifiers from ordinary records.
- [x] Serve a new `modem_service` in the existing services crate. Add manifest source, program,
  service, protocol/client generation, build inputs and dependencies. ServiceManager supplies
  `SERVE`, private `ADMIN`, private network-attachment and `CATALOGUE` roles. Append positional
  roles and update every affected launcher and kernel harness. Public clients receive neither
  the catalogue nor provider connections.
- [x] Add a `modem` provider kind in device IDL, driver-protocol constants, system-manifest's
  closed mapping, DeviceManager's conversions and generated registries. Allocate an unused
  value at implementation alongside P02M0180-P02M0188, preserving existing values. Subscribe
  continuously, use per-consumer `open`, and handle withdrawal. `consumers = 1` bounds
  connections; it does not authorize an application.
- [x] Add separate security grants and PermissionManager policy: `modem-state` for
  non-identifying observations, `modem-data` for allowed context activation/deactivation,
  `modem-identity` for IMSI/ICCID/phone number, and `modem-manage` for PIN/PUK and supported
  management operations. Only PermissionManager receives the private admin factory and mints
  restricted endpoints from explicit policy. Identity/management are denied by default;
  connecting to the ordinary inventory endpoint cannot mint or exercise these authorities.
- [x] Bind grants to an authorized provider/SIM generation and data grants to allowed context/APN
  settings and an explicit permission to replace an existing uplink. No raw command escape hatch
  or network-admin handle reaches the data client. Close, admin revocation, client endpoint
  loss, SIM change, device withdrawal and service restart invalidate the scoped authority and
  tear down its contexts. New generations require a fresh grant. Never log credentials,
  submitted PIN/PUK or subscriber identifiers through ordinary state/diagnostics.
- [x] At grant minting bind the endpoint to a `WAIT | TRANSFER` observer of the exact
  prepared client task, reusing PermissionManager's `grant_for_task` launch path. ModemService
  observes owner death independently of channel closure and retires every grant/context owned
  by that task, even if a client duplicated or transferred its endpoint. The observer carries
  no task-management authority. Failed prepared launches revoke grants before cleanup completes.
- [x] Admit at most four modem providers, 32 client connections and one active modem context
  globally; expose the limits. Coordinate the finite catalogue client/subscription capacities
  with all manifest consumers, including P02M0180-P02M0188: the current eight-client capacity
  cannot host them all. Test capacity refusal and reclamation rather than removing bounds.

- [x] Reuse P02M0180's shared catalogue infrastructure stage: private
  `provider-catalogue-admin.open-consumer(kinds)`, held only by ServiceManager, mints this
  service's kind-scoped catalogue connection. DeviceManager checks the actual publication
  kind/generation on both subscribe and open. This depends on that infrastructure stage, not
  completion of Bluetooth functionality. Use its bounded 32-client/subscriber admission and
  combined manifest-budget check; do not duplicate its factory or rely on an unchecked filter.

## P02M0183b - Provider boundary and transaction lifetime

- [x] The private provider protocol carries version/limits, state queries/indications, PIN/PUK,
  activate/deactivate, returned IP configuration and session-tagged IP datagrams. It serves a
  deterministic emulated provider here and the MBIM class module later. The provider translates
  framing; ModemService owns policy and command authorization.
- [x] Stage pure MBIM control-fragment and session/NDP validation in the existing host-testable
  driver library, with module-local tests. The fixture and later MBIM driver use those routines;
  `cdc.rs`'s NCM signatures do not constitute MBIM support. Put service transactions/policy in
  runtime-free `service-logic` modules. USB descriptor binding, actual transfers, NTB transport
  and xHCI attachment remain P02M0099's driver work; no second USB parser lives in the service.
  **LANDED 2026-09-23.** `drivers::mbim` (8 module-local tests) parses and reassembles control fragments under
  negotiated limits, refuses out-of-order and conflicting duplicates, expires assemblies, and walks NTB16/NDP16
  tables with session membership, offset and cycle checks; the fixture carries every record through it.
  Transactions and policy are `service_logic::modem_commands`; the service parses no USB framing.
- [x] Correlate requests with provider connection generation and a non-reused transaction ID;
  validate operation and SIM/context generation on replies. Unsolicited indications update a
  versioned snapshot. A bounded watch coalesces to the newest snapshot with an explicit resync
  marker, never pretends to preserve all transitions. Late/duplicate replies cannot activate
  replacement contexts. Reset IDs only with a new connection generation.
- [x] Negotiate down from hard maxima: eight pending commands/device, one state-changing
  command/device, four fragment assemblies, 64 kB/message, 256 kB aggregate assemblies/device,
  256 fragments/message. Validate totals, overlap, conflicting duplicates, arithmetic overflow,
  session membership, NDP cycles and every transfer offset before copying/allocating. Assembly
  expiry is two seconds; local command deadlines are five seconds for queries/PIN/PUK and
  60 seconds for activation. They bound waiting, not hardware completion.
  **LANDED 2026-09-23.** `mbim::Limits::negotiate` (256 fragments, 64 kB, 256 kB, 4 assemblies, two-second
  expiry) and `modem_commands` (eight pending, one state change, five and sixty seconds), host-tested at and
  past each bound; ModemService clamps the provider's own limits down before using them.
- [x] At expiry/cancellation free pending capacity and return definite failure or
  `outcome-unknown` when a state change may have reached the device. Never replay PIN, PUK or
  activation automatically. Reconcile through fresh read-only queries before conflicting
  operations; unreconciled state remains unknown rather than retaining a pending slot forever.
- [x] Surface attempt counters as `known(n)` or `unknown`, with SIM/state generation and
  freshness. Query before an attempt and after completed/uncertain results when supported;
  unsupported counts remain unknown. Require explicit acknowledgement to attempt with unknown
  remaining count, serialize attempts, and clear submitted-secret buffers after bounded handling.
  **CORRECTED 2026-09-24:** the PIN/PUK command is encoded into a fixed buffer ModemService owns and zeroes
  after the send, not through the generated client, whose growing vector was freed with the secret in it.
- [x] Cap datagrams at negotiated MTU, maximum 4096 bytes, and 64 packets/256 kB per direction
  per active context. Transmit returns busy at capacity; receive overflow reports a drop count.
  Disconnect drops queued datagrams/assemblies and wakes waiters with a terminal reason.

## P02M0183c - Explicit NetworkService attachment and lifecycle

- [x] Add private versioned `network-link-admin` and raw-IP link interfaces beside network IDL.
  ServiceManager retains the admin root and supplies ModemService an attachment endpoint
  restricted to its contexts; PermissionManager supplies the data client's context authority.
  Ordinary `network` clients cannot reach either admin operation. Attachment includes provider,
  SIM and context generations, packet channel, family, address/prefix, optional gateway,
  at most two DNS servers and MTU. NetworkService validates and owns configuration and routing.
- [x] Support one IPv4 modem context and one selected uplink globally first. IPv6-only modem
  configuration returns typed unsupported; preserve existing Ethernet IPv6 support. Factor
  the existing `net.rs` IPv4 input/output into a raw-IP medium sharing ICMP/UDP/TCP/DNS logic
  with Ethernet. Keep Ethernet framing/ARP/DHCP in its medium; raw IP never waits for MAC,
  sends ARP, runs DHCP or uses the QEMU static fallback. Install modem configuration atomically
  and report the selected interface identity and effective MTU through existing network state.
- [x] Make NetworkService's catalogue subscription persistent and unify linked/unlinked serving.
  Track at most 16 Ethernet publications with generations; keep the current usable provider,
  otherwise choose the lowest stable live publication identity. Support late providers, active
  withdrawal, failed-channel teardown and replacement opening. A modem is explicitly installed,
  not an automatically selected Ethernet publication. This owns the missing destination lifecycle
  if no P02M0099 NIC slice has landed it first; reuse that implementation if one has.
- [x] Without replace-uplink authority, activation returns busy when another link is selected.
  With that explicit grant, it may replace the selected NIC. Reserve network admission before
  activating the modem, validate returned configuration and report success only after installation
  commits. Admission refusal leaves the current link intact. Post-activation installation failure
  performs bounded deactivation; uncertainty leaves the context unavailable pending reconciliation.
- [x] A committed switch invalidates old sockets/pending operations with typed link-changed,
  clears addresses/routes/DNS/traffic, and advances interface generation. Do not migrate TCP
  sessions. Deactivation, SIM/provider loss or owner/grant loss removes the context, restores
  the previous Ethernet publication if still live, otherwise selects the deterministic fallback
  or serves unlinked. A modem reconnect needs a fresh explicit activation. Old events cannot
  restore stale configuration. There is no multipath, routing daemon or automatic PIN policy.
