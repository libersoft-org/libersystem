# P02M0014 - virtio-gpu driver + runtime mode-set (the resize source for the local console)

Status: COMPLETE (2026-06-24).

P02M0006c had finished the terminal's resize **mechanism** - winsize, the resize event, the reflow - and
the local hardware console had no **source** of size changes: a fixed framebuffer never changes size.

*Condensed 2026-08-08.*

A userspace `virtio_gpu` driver over the existing transport owns the control queue, and the
framebuffer ConsoleService renders into becomes the virtio-gpu scanout resource. QEMU runs with
`-vga none -device virtio-vga`. The console now renders through a 2D scanout that can change size at
runtime, which is what makes the resize path reachable at all.

Resize events came from polling `GET_DISPLAY_INFO` here. *(P02M0074 later replaced the poll with the
device's configuration-change interrupt, and got the acknowledgement ordering right so a change
racing the handler is not lost.)*
