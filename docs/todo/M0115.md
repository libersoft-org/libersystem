# M0115 - Architecture abstraction layer (the HAL boundary)

Status: COMPLETE.

`arch/mod.rs` re-exported x86_64 directly and the portable kernel reached into x86-specific paths
throughout. Before a second architecture could compile, every arch-specific surface had to sit behind
one explicit contract.

*Condensed 2026-08-08.*

The contract is documented per subsystem in `arch/mod.rs`: boot hand-off and `BootInfo`, paging,
context, per-CPU state, interrupts, the local APIC and its timer, the fine clock, the I/O APIC,
serial, PCI, syscall entry, usermode entry, AP boot, RTC and randomness.

**The measurable property is that `grep target_arch` finds zero matches outside `arch/`.** The
portable kernel never names an architecture. One leak had to be chased down: `smp.rs` held a private
inline-assembly `read_cr3()`. The only remaining x86 inline assembly outside `arch/x86_64/` is in the
test module, which is never cross-built.

x86_64 stays the reference implementer, entirely untouched, and the other two were rewritten from
ten-line skeletons into full stub backends carrying every contract symbol with its exact signature -
so a cross-build links even though it cannot boot yet.

The shape mirrors the bootloader decision: one implementation per architecture behind a stable
boundary, rather than conditionals threaded through shared code.
