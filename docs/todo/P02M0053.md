# P02M0053 - LiberFS/storage: the seed-archive loop and snapshot-name encoding

Status: COMPLETE. The seventh full source pass (2026-07-03) found the crate clean and the remaining
hole in the one place the hostile-disk audits had not reached - **a duplicated parser**.

*Condensed 2026-08-08.*

**StorageService's boot-time seeding loop parsed the archive format a second time, before the
bounds-checked parser ever saw the bytes.** It read the entry count and each entry's offset and size
straight off the disk and **resized a Vec by them**, so a hostile disk carrying the archive magic and
a four-billion entry count claimed a ~170 GB table and the seeding path aborted the whole storage
service.

The circumstance is what makes it serious: **the seeding path runs exactly on a disk without a valid
LiberFS - the disk whose content is least trustworthy.**

The claim is now bounded by the seed region's fixed size rather than even by the disk: the filesystem
starts immediately past it, so no archive can extend further. Both the entry table and the last
blob's end are checked, and a claim beyond the region means "no archive" rather than an allocation.

**A duplicated parser is a duplicated vulnerability**, and this one had been written to be quick
rather than to be safe.
