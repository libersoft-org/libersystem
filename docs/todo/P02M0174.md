# P02M0174 - IPv6 at layer three: addressing, ICMPv6 and neighbour discovery

Status: FUTURE TRACK. NETWORKING FOUNDATION. NOT A PHASE-2 COMPLETION GATE.

## Goal

Add a bounded IPv6 host layer beside the existing IPv4 stack: canonical addresses, Ethernet IPv6,
strict packet parsing, ICMPv6, neighbour discovery, duplicate-address detection, router discovery and
SLAAC. IPv4 remains operational throughout.

This mirrors P02M0003's layer boundary. It does not yet change every public NetworkService operation
or add IPv6 TCP/DNS tooling; P02M0175 owns that transport/API migration after the L3 behavior is
proven.

**The conformance claim is stated up front, because the honest scope is narrower than "an IPv6
host".** RFC 8200 section 5 requires a node to accept a fragmented packet that reassembles to 1500
octets, and RFC 8504 section 5.1 requires nodes to receive and process Fragment headers. This
milestone implements ATOMIC fragments - a Fragment header with offset zero and M unset, which is a
complete packet and needs no reassembly state - because that is what real DNS resolvers emit and
refusing it discards valid traffic. It does NOT implement multi-fragment reassembly. The milestone
therefore delivers a bounded appliance IPv6 host with a NAMED conformance gap, and neither the goal
nor the Definition of done may describe it as a generally conforming one. Closing that gap is a
separate item with its own memory and timeout budget, and it is a blocker on any future claim of
general IPv6 interoperability.

## What is there now, and what it forces

- `Stack::Outcome` carries `reply_len` plus ONE `Event`, and the events are ephemeral scalars. The
  standing NetworkService loop bounds its wait only by the DHCP lease deadline, and the blocking
  ARP, ping, DNS and TCP helpers pump frames while discarding every event that is not the one they
  are waiting for. Nothing in that shape can carry concurrent DAD, RS retry, NUD probes and four
  independent expiry timers, so M6 is not optional decoration - the state machines have nowhere to
  live until it exists.
- The configured MTU is accepted down to 576, and frame buffers are allocated once at startup as
  `min(configured, link) + 14`. An IPv6 layer on a sub-1280 link is illegal, and an RA cannot be
  allowed to enlarge buffers that were sized at boot.
- The IPv4 parser deliberately trims the L3 packet to its IP total length, which is how Ethernet
  padding is handled correctly today. The IPv6 parser must do the same against Payload Length rather
  than treating any trailing bytes as an undeclared payload.
- The harness constructs only QEMU user-mode networking. There is no controllable Ethernet peer, so
  the hostile RA/ND/ICMPv6 oracles this milestone's own gate requires cannot be built from what
  exists. That fixture is therefore owned HERE and extended by P02M0175, not the other way round.
- `service-logic` exists precisely because the `services` binary links `rt` and cannot be host-
  tested. Every pure IPv6 state machine goes there; the binary keeps only the I/O.

## Work

- [ ] **M1 - IPv6 values are typed and scoped.** Introduce canonical 128-bit address, prefix and
  route types with checked construction and classification for unspecified, loopback, multicast,
  link-local and global addresses. A link-local address is never used without the interface/scope
  which gives it meaning. Derive the stable link-local interface identifier by one documented local
  policy; do not accidentally expose an unreviewed hardware identifier as a privacy claim.

- [ ] **M2 - Ethernet/IPv6 parsing is strict and bounded.** Support EtherType `0x86dd`, the fixed
  IPv6 header, payload-length and next-header validation, hop limit, multicast destination filtering
  and egress construction. SLICE THE L3 PACKET TO THE IPv6 PAYLOAD LENGTH before any extension-header
  walk, and treat the remaining outer Ethernet bytes as padding rather than as undeclared payload -
  the IPv4 path already trims to total length for this reason, and a rule that refuses "trailing
  payload" would reject valid short and empty IPv6 frames on a padded link.

  Walk extension headers under explicit byte/count limits and implement their unknown-option action
  bits; reject deprecated routing forms and malformed chains. A payload-length-zero packet carrying
  a Jumbo Payload option is refused unless a separately bounded jumbogram design is added; a
  genuinely empty payload stays valid. This milestone's MTU and buffer model does not support
  jumbograms.

  Fragment headers: do not originate fragments, and continue to reject fragmented ND as RFC 6980
  requires. Process an ATOMIC fragment - offset zero, M clear - as a complete packet: strip the
  header and continue the walk with its Next Header, with no reassembly context created. Refuse
  every non-atomic fragment with a typed result and count it, so the named conformance gap is
  observable rather than silent. Return a typed too-large result when an outgoing payload exceeds
  path MTU.

- [ ] **M3 - ICMPv6 is part of the host, not an optional ping codec.** Validate the IPv6
  pseudo-header checksum and implement echo request/reply plus the errors needed by this host:
  Destination Unreachable, Packet Too Big, Time Exceeded and Parameter Problem. Errors quote only a
  bounded portion of the triggering packet and are not generated in response to cases forbidden by
  ICMPv6 - a non-unique source, or another ICMPv6 error - and a multicast destination suppresses an
  error EXCEPT in the two cases the standard exempts.

  **THE MULTICAST EXCEPTIONS ARE STATED, BECAUSE A BLANKET RULE CONTRADICTS M2** (2026-08-30). M2
  requires the unknown-option action bits to be implemented, and those bits decide this: action `10`
  discards the packet and sends Parameter Problem Code 2 REGARDLESS of whether the destination was
  multicast, while action `11` does so only when it was not. A blanket "no error for a multicast
  destination" makes action `10` unimplementable and makes the two bits indistinguishable. Packet Too
  Big is the second exemption and is required for multicast destinations too, since a PMTU report is
  the whole mechanism by which a sender learns a path is narrower. M8 tests action `10` and action
  `11` against a multicast destination as separate cases with opposite expected outcomes, plus the
  Packet Too Big case.

  RATE-LIMIT ORIGINATED ERRORS, as RFC 4443 section 2.4 requires: a bounded aggregate token bucket
  with a configurable rate, deterministic drop accounting, and bounded log output. Without it a
  malformed-extension or unreachable-destination flood turns this guest into an unbounded ICMPv6
  error generator even though its parsing and cache allocation are bounded.

  Maintain a bounded path-MTU cache with a floor of 1280 and expiring entries. A Packet Too Big
  update is accepted only when its quotation matches a recent packet emitted by this host on that
  route and its advertised MTU lowers the current value; unmatched, stale, increasing and replayed
  quotations cannot poison the cache.

- [ ] **M4 - neighbour discovery replaces ARP for IPv6, with the full NUD machine.** Implement
  solicited-node multicast, Neighbor Solicitation/Advertisement and Router Solicitation/Advertisement.
  Implement ALL FIVE neighbour-cache states of RFC 4861 section 7.3.2 - `INCOMPLETE`, `REACHABLE`,
  `STALE`, `DELAY` and `PROBE` - with their transitions, timers, retry counts and backoff. `DELAY`
  and `PROBE` are what revalidate a stale neighbour with unicast probes and what retire a dead one;
  a cache that stops at `STALE` either never recovers a next hop or never gives it up, and RFC 8504
  section 5.4 requires host NUD.

  Validate hop limit 255, source-address rules, target legality and exact option lengths before
  learning anything. Cache entries, pending packets, retries and per-tick work are bounded;
  unsolicited/flooding ND cannot allocate or log without limit. Define what happens to packets
  queued against an entry that fails resolution or is evicted.

  Own multicast membership rather than assuming it: implement bounded MLDv2 reports on joining and
  leaving every SOLICITED-NODE group and any other reportable group, and a bounded response to a
  general or group-specific query.

  **NOT FOR ALL-NODES, AND WITH MLD'S OWN QUERY VALIDATION** (corrected 2026-08-30). A previous
  version required reports on joining and leaving `ff02::1`. That is prohibited: membership of the
  link-scope all-nodes group is permanent and no MLD message is ever sent for it - a host reporting
  it is announcing something it can never leave, and MLD has excluded that address since its first
  specification. Reports belong to the solicited-node groups and to any other group the host joins.

  A received MLD QUERY is validated on MLD's own terms, which are NOT ND's: a link-local source
  address, HOP LIMIT 1, and the Router Alert hop-by-hop option present. The adjacent hop-limit-255
  rule in this item is ND's and does not apply here, and applying it would discard every legitimate
  query. An invalid query is discarded silently and counted.

  **AND THE HOST'S OWN FIRST REPORT IS SOURCED FROM `::`, BECAUSE IT PRECEDES DAD** (added
  2026-08-31). The previous version specified the source rules for RECEIVED queries and left the
  source of the host's own reports unstated, which broke the ordering this item exists for: M5 runs
  DAD before the tentative link-local address becomes usable, so at the moment each solicited-node
  group is joined there IS no valid link-local source to send a report from. A listener that waits
  for one reports after DAD, the snooping switch has not been told to forward the group, and the DAD
  Neighbour Solicitation never reaches a duplicate - which is exactly the scenario cited above as the
  reason MLD is in this milestone at all. So:

    the initial report   is sent with the UNSPECIFIED source address `::`, before DAD, as RFC 9777
                           section 5.2.14 requires
    after DAD            once a valid link-local address exists, every joined group is reported again
                           from it, which the same section recommends and which is what leaves the
                           switch's state correct for the rest of the boot

  M8 gains both cases as its own: a pre-DAD report is observed sourced from `::`, and the post-DAD
  re-report is observed for every group already joined. A listener that sends its first report only
  after DAD fails the first; one that never re-reports fails the second.

  **AND MLD IS A TIMED PROTOCOL, WHICH THE PREVIOUS VERSION LEFT OUT** (added 2026-08-31). Reports on
  join and leave plus an answer to a query is not a listener: without the timers below, a
  source-specific query goes unanswered and ONE LOST JOIN REPORT defeats membership for good - on
  precisely the snooping link this whole item was added to support. The bounded listener state is:

    three query kinds     GENERAL (no address), MULTICAST-ADDRESS-SPECIFIC (an address, no sources)
                            and MULTICAST-ADDRESS-AND-SOURCE-SPECIFIC (an address and a source list).
                            Each is answered from different state, so a listener that handles only
                            the first two silently ignores the third
    delayed response      a response is not immediate: it is scheduled after a RANDOM delay bounded
                            by the query's own maximum-response value, which is what stops every
                            listener on a link answering one query at once
    pending state         TWO TIMER LEVELS, NOT ONE PRIORITY ORDER (corrected 2026-08-31). A
                            previous version said a General Query "supersedes" the per-address ones,
                            which is not the rule and is wrong in the case that matters: an
                            interface-level response scheduled LATER than a pending per-address one
                            would suppress it, and the address-specific answer the querier asked for
                            would arrive late or not at all. RFC 9777 section 6.2 keeps one INTERFACE
                            timer and one timer PER ADDRESS, and the rules are:
                              - a pending General response suppresses scheduling another response
                                only when it is scheduled SOONER than the newly selected delay;
                              - a General Query schedules on the interface timer and CANCELS any
                                previously pending General response - it does not touch the
                                per-address ones;
                              - an address-specific query for an address with no pending response
                                schedules one on that address's timer;
                              - a second query for an address that already has one is merged rather
                                than added, at the EARLIEST of the remaining time and the newly
                                selected delay: an address-specific query CLEARS the recorded source
                                list, and a source-specific query UNIONS its sources into it
    state-change retry    a report announcing a JOIN or a LEAVE is retransmitted [Robustness
                            Variable] times - a small constant, 2 by default - at intervals chosen
                            RANDOMLY within the unsolicited-report interval rather than on a fixed
                            period, because MLD is unacknowledged and its first packet is exactly the
                            one a congested or filtering link drops, and a whole link retransmitting
                            in step is the burst that drops it again (RFC 9777 section 6.1). A SECOND
                            state change for the same address while retransmissions are still pending
                            MERGES into the pending report and RESETS the counter rather than queuing
                            a second one - without which a join followed quickly by a leave can be
                            transmitted in either order

  All of it is bounded: a fixed number of groups, one pending record per group, and a retry count
  that is a small constant. This adds no public multicast API, no querier role and no routing - it is
  the listener half only, which is what a host that joins solicited-node groups owes.

  RFC 8504 section 5.11 requires MLDv2 for a node that joins multicast groups and names ND's
  solicited-node dependency explicitly. DAD and ND work on a permissive
  emulated link without it and fail behind an ordinary multicast-snooping switch, which is the kind
  of gap an emulated-only gate cannot see.

- [ ] **M5 - DAD and SLAAC have explicit lifetimes and survive a hostile RA.** Form a tentative
  link-local address, perform duplicate-address detection before use, process valid autonomous RA
  prefixes into a bounded set of tentative global addresses, and run DAD for every newly formed
  unicast address before it becomes usable.

  Validate Prefix Information options completely: the conventional IID-based SLAAC path forms an
  address only from a PIO with `A=1` and a /64 prefix, `L` is evaluated independently and only `L=1`
  installs the prefix as an on-link route, and other lengths are not silently truncated into an
  address. REQUIRE `PreferredLifetime <= ValidLifetime` and discard the option otherwise. Define one
  explicit representation for an infinite lifetime and how it transitions to and from a finite one.

  Implement the RFC 4862 section 5.5.3 two-hour rule for updating the valid lifetime of an existing
  autoconfigured address from an unauthenticated RA. The plan's own claim is that a hostile RA
  cannot install immortal state or invalid prefixes; without the two-hour rule a single forged
  short-lifetime PIO removes a working SLAAC address, which is the denial of service that rule
  exists to prevent and would make the completion claim false in the case it is written for.

  Maintain a BOUNDED DEFAULT-ROUTER LIST with at least two entries, per RFC 4861 section 6.3.4, not
  one global lifetime scalar: per-router lifetime, preference, NUD linkage, deterministic ORDERING
  and removal on expiry or zero lifetime. P02M0175's API expects routers plural, and one scalar makes
  an unrelated RA overwrite a working router.

  ORDERING, NOT SELECTION - and the word was wrong (corrected 2026-08-31). This said "deterministic
  selection", which hands M0174 the one decision M6's ownership boundary exists to place in M0175:
  with more than one router, CHOOSING the route and next hop is the policy question, and M6 states
  both that this milestone only enumerates candidates and that its egress never silently picks one
  for the caller. Two paragraphs of one file cannot own the same decision.
  So what this list owes is a total, stable ORDER - by preference, then by reachability state, then
  by a stated tie-break - which is what makes the enumeration M6 promises deterministic rather than
  arbitrary. Which entry a caller's traffic uses is M0175's.
  THE ONE EXCEPTION IS THIS MILESTONE'S OWN CONTROL TRAFFIC, and it is already written down: M6 says
  ND, DAD, RS, MLD and echo use a documented default choice, because they have no transport above
  them to ask. That default is the FIRST entry of this order, stated here so the two paragraphs name
  the same rule.

  Advertised MTU is accepted only within `[1280, effective link ceiling]` and NEVER enlarges the
  fixed frame buffers. Below 1280, IPv6 is refused on that link while IPv4 continues - per-family
  readiness, stated as such, rather than a whole-service failure.

  Expiry deprecates then removes state, clears/refuses pending L3 packets and publishes bounded
  address/route invalidation events for P02M0175's transport layer. Accept a bounded set of RDNSS
  servers for the later resolver, validate their option lifetime, withdraw on lifetime zero or
  overflow-safe expiry, and publish the DNS-configuration change.

- [ ] **M6 - the L3 layer has a timer, event and interface seam.** Nothing above can work inside the
  current one-ephemeral-event-per-frame model, so this item is a prerequisite of M3-M5 rather than a
  cleanup after them:

  - ONE aggregated next-deadline path that runs regardless of which RPC is active, computed over
    every DAD, RS, ND retry, NUD, prefix, address, router, RDNSS, PMTU and MLD timer - the MLD
    response delay and the state-change retransmission included, which an earlier version omitted
    while calling the list exhaustive - so a blocking `resolve` or `connect` cannot starve them;
  - a durable BOUNDED event queue (or a generation/bitset model) drained after every frame, so an
    RA arriving during a DNS wait is not discarded by the helper that was waiting for something
    else;
  - bounded pending-resolution queues with a defined outcome when they overflow or their entry
    fails; and
  - explicit L3 ingress/egress interfaces, whose OWNERSHIP BOUNDARY is frozen here because M0175
    claimed the same decisions (corrected 2026-08-30):

        M0174 owns the STATE and the MECHANISM   the address, prefix, route, router, neighbour and
                                                   PMTU tables; their validation, lifetimes and
                                                   invalidation; and the ability to ENUMERATE
                                                   candidates - the usable source addresses for a
                                                   given destination, the matching routes and their
                                                   routers, and the PMTU for a chosen route
        M0175 owns the POLICY                    which candidate to use. RFC 6724 source and
                                                   destination selection, the policy table and its
                                                   tie-breaks, caller overrides, and the fallback
                                                   order between families

    The seam is therefore a QUERY, not an answer: egress takes a destination and an OPTIONAL
    caller-chosen source, route and next hop, and either uses what it was given - validating that the
    address is still valid and the route still live - or returns the CANDIDATE SET for the caller to
    choose from. It never silently picks one on the caller's behalf. This milestone's own internal
    traffic (ND, DAD, RS, MLD, echo) uses a documented default choice, because those have no
    transport above them to ask.

    The division is not arbitrary: selection needs the destination and the caller's intent, which are
    transport facts M0174 has no consumer for, while the tables are L3 state M0175 must not duplicate.
    A layer that owned both would make this milestone's Definition of done depend on a policy nothing
    in it uses. M0175 consumes exactly this contract and adds no state to it.

  Extract the pure state machines into `service-logic`, which exists for this: the `services` binary
  links `rt` and cannot be host-tested, so a state machine written inside it can only be driven from
  a booted guest.

- [ ] **M7 - the controllable peer fixture is built here.** Provide one deterministic unprivileged
  IPv6-capable Ethernet peer through QEMU's socket netdev, with programmable RA/PIO/RDNSS emission,
  ND responses, ICMPv6 error and PTB injection, malformed-packet and flood generators, and an
  IPv4-coexistence path. The harness only constructs user-mode networking today, and Slirp cannot be
  a deterministic hostile L3 oracle, so M8's required cases are unbuildable without this. P02M0175
  EXTENDS this fixture with DNS, UDP and TCP peers; it does not create it.

- [ ] **M8 - packet fixtures and QEMU prove both positive and hostile paths.** Host tests over
  `service-logic` cover address classification, checksums, extension walking, payload-length slicing
  with Ethernet padding, atomic-fragment acceptance, non-atomic-fragment refusal, ICMP errors and
  their rate limit, DAD conflict, all five ND states and their timers, MLDv2 join and leave reports,
  the PRE-DAD report sourced from `::` and the post-DAD re-report of every joined group, all
  three query kinds including a SOURCE-SPECIFIC one, a second query arriving while a response is
  pending, and a LOST FIRST REPORT recovered by the
  state-change retransmission, RA validation including `PreferredLifetime > ValidLifetime`, the
  two-hour rule, multiple
  routers and their independent expiry, RDNSS withdrawal/expiry, jumbogram refusal, matched and
  unmatched PMTU quotations, RA MTU above the link ceiling and below 1280, and cache exhaustion.

  THE MLD TIMER CASES ARE NAMED INDIVIDUALLY, because a generic "superseding and merging" pair passes
  against the wrong deadline rule (added 2026-08-31). Four cases, each failing a different plausible
  implementation: a General Query arriving while a per-address response is pending EARLIER, proving
  the per-address response still goes out on time rather than being superseded; a General Query
  arriving while a General response is pending, proving the older one is cancelled and not duplicated;
  an address-specific query merging into a pending source-specific response, proving the recorded
  source list is CLEARED and the earlier of the two deadlines kept; and a source-specific query
  merging into another, proving the source lists are UNIONED. And two state-change cases: a burst that
  loses more than one report, proving the Robustness retransmissions still deliver it, and a JOIN
  followed by a LEAVE for the same address while retransmissions are pending, proving the pending
  report is merged and its counter reset rather than the two being transmitted out of order.

  A SUB-1280 EFFECTIVE LINK is its own fixture, because the Definition of done's per-family clause has
  no oracle without one (added 2026-08-30). A link whose EFFECTIVE MTU is 576 or 1279 - the
  configured knob and the driver's reported link MTU together, not an RA option - must leave IPv6
  refused, IPv4 working, and the frame buffers at their boot-time size. The low RA MTU option stays a
  separate REJECTION test: on a normal link that option is ignored, which exercises a different branch
  and proves nothing about per-family readiness.

  A named QEMU IPv6-L3 gate configures an explicit reviewed global-unicast /64 and DNS/router
  addresses rather than accepting QEMU user networking's deprecated default site-local prefix as a
  global-address oracle. The guest obtains link-local and SLAAC global addresses, resolves the router
  at L2, exchanges echo traffic and observes Packet Too Big, while malformed extension/ND/RA and
  flood fixtures are refused within fixed resource bounds - including a bounded count of emitted
  ICMPv6 errors under flood. The same boot retains its IPv4 address and ping path.

- P02M0003 owns Ethernet/IPv4/ARP/ICMP and the existing fragmentation refusal.

## Definition of done

- A QEMU appliance configures valid link-local and SLAAC addresses and exchanges ICMPv6 without
  regressing IPv4, against a controllable peer rather than an incidental Slirp behaviour.
- ND runs all five NUD states with multicast membership announced, and SLAAC applies the two-hour
  rule and a multi-entry router list, so a hostile RA cannot install immortal state, remove a
  working address, or overwrite an unrelated router.
- ND, RA, extension-header, PMTU and ICMPv6-error processing are fail-closed and bounded under
  hostile input, including a bound on errors this host originates - and the multicast suppression
  rule has its two stated exceptions rather than being blanket, so option action `10` is
  implementable.
- Multicast membership is announced for the solicited-node groups and NOT for all-nodes, and MLD
  queries are validated on MLD's own terms.
- IPv6 is refused, with IPv4 preserved, on a link whose EFFECTIVE MTU is below 1280 - proved by a
  fixture whose link is actually that narrow, not by the RA-option rejection test - and an RA can
  never enlarge the frame buffers.
- The L3 seam's ownership boundary is the one this file states: M0174 owns the tables and enumerates
  candidates, M0175 chooses among them. Neither file claims the other's half.
- No unscoped link-local address is presented as supported, and the named conformance gap is stated
  rather than implied: atomic fragments are processed, multi-fragment packets are refused and
  counted, and no document in this milestone calls the result a generally conforming IPv6 host.

## What this milestone refuses

- UDP/TCP/DNS/public NetworkService migration, which is P02M0175.
- DHCPv6, temporary/privacy addresses, router forwarding, firewall/NAT, IPsec, VPN or Wi-Fi policy.
- Multi-fragment reassembly. It is the named blocker on a general interoperability claim and is
  proposed separately with its own context, byte and timeout budget, overlap rejection and the
  mandatory 1500-octet reassembled size.
- MLD snooping, querier election or any multicast routing role. Bounded host membership only.
