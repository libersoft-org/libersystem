# P02M0020 - LiberFS: write semantics, metadata, and integrity

Status: COMPLETE. *Condensed 2026-08-08.*

LiberFS could only write whole files, kept no timestamps, could not rename, and leaked blocks on a
crash - its ordered-writes design assumed an `fsck` that did not exist yet.

- **Offset writes**: seek and write at an offset, append, and truncate to a length, so a log can be
  updated in place rather than rewritten.
- **Timestamps and typed metadata room** per inode, surfaced through the volume `stat`.
- **Atomic in-volume rename** - which is the in-volume half of the concept's transfer operation;
  across volumes it is copy, verify, publish, delete.
- **`fsck`** reclaiming blocks and inodes leaked by a crash mid-write, **which is what makes the
  ordered-writes guarantee complete** rather than aspirational.
