# M0075 - LiberFS: format and modernity

Status: COMPLETE. The on-disk-format debts, bundled so that one reformat carries all the layout
changes together.

*Condensed 2026-08-08 to the format decisions and the measurements.*

- **Superblock v2 carries a FEATURES flags word**, and parsing requires an **exact match** - so a
  volume from an older layout is rejected for reformat rather than mis-parsed. That is the whole
  point of the flags: a partial match is the dangerous outcome.
- **A free-space API**, which was a popcount away: `free_blocks()` plus a typed `volume.status`
  reporting label, total and free bytes, compression and read-only.
- **Directory records became variable-length** - hash, child, a length byte and the name, about 13
  bytes plus the name - sorted by (hash, name) and rewritten compactly on change. The fixed 267-byte
  record had meant 15 entries per 4 kB leaf; it is now roughly 250.
- **The codec is LZ4 block format**, dependency-free, replacing LZSS: token framing, 64 kB offsets,
  unbounded match lengths and the spec's end-margin rules, with every match candidate byte-verified.
- **Names must be valid UTF-8**, checked in `split_segments` on top of the portable-name policy.

## The CRC change, and why it is recorded

CRC32C was a byte-at-a-time software table. Slice-by-8 - eight compile-time tables, eight bytes per
round - turned the benchmark around:

| | before | after |
|---|---|---|
| 64 MB write | 1.72 s | 137 ms |
| 64 MB read | 204 ms | 67 ms |
| host suite | ~82 s | ~0.4 s |

The host suite falling from 82 seconds to under half a second is the part with lasting consequences:
a checksum that costs that much makes the tests too slow to run, which is how a filesystem ends up
with tests nobody waits for.
