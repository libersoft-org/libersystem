# P02M0055 - LiberFS: last nits (NUL in snapshot names, failure-count overflow)

Status: COMPLETE. The ninth full source pass (2026-07-03) found the core clean and two edges.

*Condensed 2026-08-08.*

**A snapshot name could contain a NUL.** NUL is valid UTF-8, so the name check passed it - but the
on-disk record is NUL-padded, so a remount truncated the name at the first one. Two distinct
snapshots could therefore both come back named the same thing, defeating the duplicate check they had
both passed, and deleting one would delete both.

The rule that came out of it: **a snapshot's identity must not change across a remount.** NUL is
refused as a bad name.

The `fsck` failure counter could overflow, since it sums per-extent damage over the whole pool and a
pathologically damaged volume can push the total past a u32 - a debug-build panic. Every accumulation
saturates now, and a saturated count reads as "beyond counting", which such a volume is.

Added while closing the track: **a standing fuzz guard**, so the hostile-disk bounds hold on every
future change by test rather than by review.
