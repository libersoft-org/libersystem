# P02M0078 - ABI versioning and boot image hygiene

Status: COMPLETE.

Syscall numbers and ABI structs were compile-time constants with no runtime check - fine while kernel
and userspace build from one tree, and **the worst possible failure mode** once a package path runs
binaries built elsewhere or earlier.

*Condensed 2026-08-08.*

The `abi` crate is stamped with a version and there is an appended check syscall - **appended,
because old numbers never move**, which is the contract this makes enforceable. The runtime's entry
issues that check as its **very first syscall**, before calling the program's main: the kernel
answers, and on a mismatch the runtime prints a clear line and exits.

So a binary built against a different revision is refused **before it runs against a renumbered call
or a grown struct**, rather than misbehaving in a way that looks like a bug in whatever it touched
first.

The rule the mechanism enforces: new calls append, old ones never renumber.
