# P02M0180 - A sandboxed Bluetooth service above HCI

Status: OPEN. It closes when every item below is done, and not before.

**WHY THIS IS A MILESTONE AND NOT PART OF THE DRIVER.** The USB Bluetooth HCI transport item in
P02M0099 stops at HCI on purpose: it carries bounded command, event, ACL and ISO packets over a
capability-scoped transport and knows nothing about what they mean. Everything above that line -
pairing, link keys, L2CAP, RFCOMM, the profiles, radio policy - is a large, historically
attack-prone body of parsing that must not run inside the process holding an xHCI endpoint. A
driver that grew it would put the whole of it behind a device claim.

**AND IT EXISTS BECAUSE THE OWNER SAID SO (2026-09-21).** The question P02M0099 put was whether this
system wants these features at all, because the search under that item found no milestone, no
architecture entry and no phase sentence naming a Bluetooth stack. The answer was that the drivers
are wanted, which makes the service under them wanted. This file is that service's owner.

**WHAT IT IS NOT.** It is not the transport, it is not a profile catalogue that grows a new
entry per device, and it is not a place for radio policy that belongs to a platform policy service.
The boundary is the one the driver item already drew and this file keeps: HCI packets in, typed
events and capability-scoped channels out.

## The shape

- [ ] A typed `liber:bluetooth@1` interface: controller enumeration, power state, the local
  address and features, and a bounded scan with typed results. Nothing in it returns a raw HCI
  packet to a client, because a client that can send one is a client that can do anything the
  controller can.
- [ ] Pairing and bonding with the key store as a separate capability. Link keys are long-lived
  secrets; the service holds them behind a capability a client never sees, and the key store is
  asked rather than read.
- [ ] L2CAP with bounded channels and per-connection queue limits, and the fragmentation and
  reassembly it needs, host-tested against malformed and hostile fragment sequences before a
  controller is involved.
- [ ] One profile, chosen because something real asks for it, and the rule that a profile with no
  consumer is a guess - the same rule the provider catalogue already states for `ProviderKind`.
- [ ] Its own domain and its own resource bounds, so a stack that is wedged or compromised takes
  nothing else with it. This is the whole argument for the milestone and it has to be a property
  the boot enforces rather than a paragraph here.
- [ ] Host tests over every decision that is a pure function of bytes - the HCI event decode, the
  L2CAP reassembly, the pairing state machine - with deterministic malformed mutations, on the same
  terms every other parser in this tree is held to.
- [ ] A guest gate proving the observable effect end to end, and registered in the verification
  model in the same change.

## Definition of done

Done when a client holding only the `liber:bluetooth@1` capability can enumerate a controller,
scan, pair and open one profile's channel; when every layer above HCI runs in a domain of its own
with bounds the boot sets; when the parsing decisions are host-tested against hostile input; and
when the guest gate and its verification-model entry are in the same change as the code.

## What it unblocks

P02M0099's **USB Bluetooth HCI transport**, which is written and waiting for a destination.
