# P02M0180 - A sandboxed Bluetooth service above HCI

Status: OPEN. It closes when every implementation and verification item below is done.

The service owns Bluetooth host protocols and policy enforcement above a bounded HCI transport.
The USB transport in P02M0099 is still unimplemented. Its class module will live inside the USB
controller process under the existing `usb_class.rs` execution model; this service runs in a
separate process and resource Domain. It receives no device claim, MMIO, DMA or USB endpoint
capability. Platform radio policy remains outside this service.

## P02M0180 - Scope and implementation order

- [ ] Deliver the transport wire, service, protected bond backend, real input consumer integration
  and an in-guest controller/peer fixture first. This is the prerequisite P02M0099 needs; service
  completion uses the fixture and does not claim USB transport coverage. The later USB item owns
  endpoint binding, transport recovery and its hardware/emulator gate against the same wire.
- [ ] The first profile is the HID-over-GATT boot mouse subset, consumed by the existing
  InputService/ConsoleService pointer path. Support one LE central connection per controller,
  static/public peer addresses and an encrypted bonded boot mouse. Support bounded ATT/GATT
  discovery, Protocol Mode selection and Boot Mouse Input Report notifications. Convert relative
  movement/buttons to the existing normalized pointer stream and prove an actual cursor/button
  change. Do not add RFCOMM, BR/EDR profiles, keyboards, arbitrary report maps, audio, ISO streams,
  privacy-address resolution or additional profiles in this slice; return typed unsupported
  results for unsupported modes rather than claiming full HOGP conformance.
- [ ] Require LE Secure Connections with a 128-bit key and a controller supporting the HCI P-256
  public-key/DHKey commands. Implement the host SMP state machine and AES-CMAC derivations in the
  host-testable leaf, using official vectors and independent expected values. Use healthy system
  randomness; refuse pairing if unavailable, and never use `random_insecure`. This mouse slice
  supports the Just Works association model, explicitly reported as encrypted but unauthenticated
  against active radio impersonation; no downgrade to legacy pairing. Operator authorization is
  required before pairing or enabling an input peer. Peer identity is not proven by its name.

The protocol references are the [Bluetooth HID-over-GATT profile](https://www.bluetooth.com/specifications/specs/hid-over-gatt-profile-1-0/)
and the [Bluetooth Security Manager specification](https://www.bluetooth.com/wp-content/uploads/Files/Specification/HTML/Core_v6.3/out/en/host/security-manager-specification.html).
Use specifications and independently authored implementations; do not import differently licensed
stack source. The restricted mouse subset and security label are deliberate product scope.

## P02M0180 - Provider and client contracts

- [ ] Add a typed internal HCI provider contract and a `bluetooth-hci` provider kind in
  `src/idl/device.lsidl`, corresponding registry/wire handling and generated bindings. Allocate
  unused enum values from the current combined vocabulary, never assume this is the only new kind.
  DeviceManager owns publication slot/generation and binding generation. A controller's USB child
  publication uses the controller binding lifetime plus its manager-assigned publication identity;
  no new independently claimed USB-interface identity is introduced.
- [ ] Own the shared catalogue infrastructure stage before Bluetooth protocol implementation:
  add private `provider-catalogue-admin.open-consumer(kinds)` to DeviceManager and hand its
  root only to ServiceManager over trusted bootstrap. `kinds` is a bounded subset of the closed
  ProviderKind vocabulary. Minted clients enforce that subset on both `subscribe` and `open`,
  checking the manager's actual publication kind and generation rather than a caller's claimed
  kind. They expose no minting operation. ServiceManager mints each service's manifest-authorized
  client and updates all production/test bootstrap callers. Migrate existing consumer factories
  too: no legacy unrestricted `open` path may remain reachable by ordinary inventory clients.
  Preserve their read-only inventory operations without granting new private transport kinds.
  This stage is reusable by P02M0181
  through P02M0187 without waiting for Bluetooth completion. Raise the finite catalogue client
  and subscription caps from eight to 32, check the combined manifest needs against that budget
  and test cross-kind denial, stale-generation denial and refusal at the cap.
- [ ] BluetoothService subscribes to that kind-scoped catalogue endpoint and connects by exact
  publication identity. Snapshot plus live withdrawal follows the existing catalogue convention.
  The bootstrap/manager authorizes this service as the HCI consumer; a registry consumer count is
  only a capacity check. Ordinary clients receive neither catalogue-connect authority nor the
  provider endpoint. Account for all new services when sizing the bounded catalogue client and
  subscriber tables, which currently admit only eight.
- [ ] The provider carries commands service-to-controller, events controller-to-service and ACL
  data both ways. Reserve a negotiated ISO packet kind for the separately owned transport, disabled
  in this service. Advertise supported kinds and packet/queue maxima before traffic. Hard packet
  ceilings including HCI headers are 258 bytes for commands, 257 for events, 1028 for ACL and
  4100 for ISO; honor smaller advertised/controller limits. Validate kind, direction and declared
  length before enqueueing. At most one HCI command is outstanding; obey returned command/ACL
  credits, bound incomplete ACL/L2CAP state, and never treat transport send as command completion.
- [ ] Provider control supports initialization/reset and reports reset, fault and removal. A reset
  advances the service's controller-session epoch and invalidates links, scans and profile handles;
  withdrawal invalidates the publication itself. Close outstanding requests with typed outcomes,
  discard late packets from old epochs, clear partial reassembly and release held buttons on loss.
  Reconnect to a replacement only through a fresh catalogue publication and reinitialization.
- [ ] Define `liber:bluetooth@1` read, operator and profile connection scopes. Read clients can
  enumerate controller identity/features/address/power and perform a scan with a caller deadline
  capped at ten seconds, at most 64 deduplicated results and explicit cancellation/completion.
  Read authority cannot power the controller, pair, forget a bond or activate an input profile.
  Operator requests are typed power-on/off, pair/cancel, forget and enable/disable a named peer;
  expose pairing progress and its security level, never raw HCI or keys. Pairing is capped at
  60 seconds and only one attempt is live per controller.
- [ ] ServiceManager grants the operator endpoint only to the explicit trusted operator component
  through PermissionManager's manifest grant path, following the existing device-policy pattern;
  no default operator grant. This is an administrative authorization, not a claim that Just Works
  authenticates the physical mouse. The operator selects a current scan identity. Power requests
  enforce the configured platform allow/deny setting and report refusal without inventing radio
  policy. The InputService receives only `open-mouse(peer)` authority over enabled peers and a
  typed bounded report channel. Closing it or disabling the peer removes that input source.
- [ ] Add the InputService bootstrap client and a bounded additional source slot through which it
  opens the enabled mouse channel, reconnects after service restart and forwards normalized input
  through its existing pointer/console path. Do not publish a pretend driver provider from the
  Bluetooth userspace service. Update every bootstrap caller, including kernel harness callers.

## P02M0180 - Bonds and containment

- [ ] Own a small `bluetooth_bond_store` service in this milestone. Its private capability supports
  lookup, atomic store/replace and delete by local controller identity plus peer address/type and
  key/security version. Store the LTK and only the metadata this restricted profile requires;
  reject mismatched controller/peer identities and unsupported record versions. Lookup may return
  key material only to BluetoothService so it can issue encryption commands. "Asked rather than
  read" means a typed confined operation, not a claim that HCI encryption works without a key.
- [ ] ServiceManager/StorageService mint a writable directory-scoped storage connection for the
  backend's manifest-owned `vol://system/state/bluetooth-bonds` directory and grant the private
  bond endpoint solely to BluetoothService. Ordinary clients receive neither capability. Use the
  existing `volume.open-writer` replacement session and acknowledged `writer.commit` on
  disk-backed LiberFS; `writer.flush` confirms staged bytes only, and remove-then-rename is not
  an atomic replacement. Cap records at 64 and the complete store at 64 kB. The backend survives
  service restart/reboot through this directory; a corrupt record is
  unavailable, never an implicit new peer. Do not claim protection from a trusted storage
  administrator or add a general-purpose key manager/encrypted-volume project.
- [ ] Pairing is reported as bonded only after durable commit. If storage is absent/full or a
  write fails, terminate the bonding attempt and erase temporary keys; do not silently downgrade
  to a transient bond. Reconnect retrieves the matching record and proves encryption before
  enabling input. Forget durably deletes it before reporting success and terminates the live link.
  Clear transient key buffers on completion/failure and exclude key bytes from logs and events.
- [ ] Extend the existing ProcessService bounded-launch mechanism with a finite resource-limits
  record and a prepared/release form usable by ServiceManager. Set every limit before releasing
  the process; reject invalid limits and fail startup if Domain creation or any limit assignment
  fails. No fallback to ordinary `launch(..., domain=0)`. ServiceManager selects the documented
  limits for these two manifest services; existing unrelated launches retain their behavior.
  Keep the Domain in ProcessService's existing accounting/cleanup record, and tear it down on
  failed launch or service stop before a replacement starts.
- [ ] Initial BluetoothService limits: 64 MB memory, 256 handles, 4 threads, 2 MB IPC queues,
  2 MB stacks and zero DMA. Bond backend: 16 MB memory, 64 handles, 2 threads, 256 kB IPC queues,
  1 MB stacks and zero DMA. Measure image/runtime baseline under these exact limits and tune
  finite values with recorded headroom if necessary, never replace them with unlimited values.
  No launcher or device privilege is granted to either service. Use existing resource counters;
  this does not add a CPU scheduling policy.
- [ ] Bound service tables to two controllers, one link each, 16 client connections, four
  L2CAP channels per link, 16 queued packets per link and 256 kB aggregate packet storage.
  L2CAP SDUs are at most 512 bytes with one incomplete SDU per channel and a one-second assembly
  deadline. Default ATT MTU 23 is sufficient for the mouse subset. Event-loop work is bounded
  per turn and waits use deadlines; refuse overload explicitly, with no allocation retry spin.
  On process death all ephemeral clients close. Restart rebuilds controllers from the catalogue,
  restores bonds through the backend and requires fresh profile channels; it never revives old
  client handles or button state.
- [ ] Add the service binaries, source/dependency paths, staging destinations, state declarations
  and roles to `src/user/services/manifest.toml`; add generated protocol/client exports, operator
  and read grant vocabulary in `src/idl/security.lsidl`, PermissionManager delivery and service
  resolution/restart handling. Update IDL generation inputs, manifest-derived bootstrap code and
  relevant source-hygiene allowances in the same implementation. No new root authority is ambient.

## P02M0180 - Verification and completion

- [ ] Put production HCI-event, ACL/L2CAP, ATT, SMP, HID-report and bond-record logic in a pure
  leaf without `rt`/`ipc-client`, following `service-logic`'s host-testing boundary. Keep tests in
  separate test modules. Test exact boundaries, hostile lengths, missing/duplicate/out-of-order
  fragments, exhausted credits, timer expiry, unsupported features, downgrade attempts, bad
  confirmations, identity mismatches and deterministic mutations of independent valid vectors.
- [ ] Add an in-guest test-only HCI controller/peer provider speaking the production wire. It
  emulates the selected LE boot mouse, command credits, secure pairing exchanges, encryption
  status and report notifications, including scripted bad fragments/reset/unplug. Cryptographic
  expected transcripts/keys are independent fixtures, not expectations generated by the code
  under test. Test fixtures are absent from shipping manifests and cannot be enabled by clients.
- [ ] Implement the standalone `bluetooth-service` guest gate with a manifest-complete x86_64
  test image and isolated persistent volume. An ordinary read client enumerates/scans but is
  denied operator verbs; an authorized operator pairs and enables the fixture; InputService and
  a live pointer client observe the specified movement and button changes. Restart the service
  and cold-reboot the same volume to prove bond reuse without re-pairing, then forget and prove
  it cannot be reused. Assert key/store-capability denial and stale-handle rejection.
- [ ] In the same gate, force transport loss while a report/scan is pending, exhaust a configured
  service resource using a test hook and terminate/restart the service. Read the actual Domain
  counters and assert finite limits/refunds; prove another running service still answers a typed
  request and pointer input from an unrelated source remains usable. A service-online marker or
  a returned-but-idle channel is not the oracle.
- [ ] Register the gate in `check.sh`, `src/tools/verify-model/src/catalog.rs`, guest-evidence
  profiles and `model/release-required.toml` as required by the existing exact-set checks. Declare
  test-image/volume producers and coverage for the Bluetooth/bond binaries, pure leaf, protocol,
  InputService, manifest and bounded-launch/bootstrap changes so each selects this proof. Run
  model validation, generation/source-hygiene checks, focused host tests, this x86_64 gate and
  cross-build AArch64/RISC-V. USB endpoint/stall/physical-radio coverage remains P02M0099's gate.

Done when the supported mouse path scans, pairs, durably bonds and supplies useful input through
capability-scoped channels; the separate Domains and aggregate bounds are enforced at boot; denial,
loss and restart behavior pass; and production host tests plus the registered guest gate land with
the implementation. The USB Bluetooth HCI transport is then unblocked, not already implemented.
