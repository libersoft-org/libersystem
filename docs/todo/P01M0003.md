# P01M0003 - Kernel additions: driver + spawn syscalls, queue/DMA accounting

Status: COMPLETE. The syscall surface grew from 24 to 33 calls.

This is the milestone that made **userspace drivers possible at all**: three syscalls materialise the
`Interrupt`, `DeviceMemory` and `DmaBuffer` objects, each capability-gated, so a driver is an
ordinary process holding ordinary capabilities.

*Condensed 2026-08-08.*

- `interrupt_bind` hands a device IRQ to a userspace driver, delivered as an event signal rather than
  as a callback - so a driver waits the same way everything else waits.
- `device_memory_map` maps an MMIO region into a driver's address space.
- `dma_buffer_create` allocates a DMA-safe buffer and its handle.
- `process_create`, `thread_create` and `thread_start` are exposed to userspace, capability-gated.
- `random_get` (the kernel CSPRNG) and `object_property_set`.
- **Resource accounting extended to `ipc_queue_bytes`**: a queued message is charged to the sender
  until it is received, so a slow reader cannot be used to make someone else's memory grow.
- **Kernel-side driver-crash cleanup**: a driver fault detaches its IRQ and disables what it owned.
  A userspace driver that can die must not leave the hardware armed.
