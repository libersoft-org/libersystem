# P02M0192 - Gamepads: an input vocabulary, the USB mapping and a gamepad test tool

Status: OPEN. It closes when every item below is done.

THE OWNER'S DECISION (2026-09-25): a new milestone that brings a TOOL into LiberSystem for testing gamepads,
in the text interface, showing which button is pressed on which gamepad. The tool is the consumer the
vocabulary lacked, so the rule that held the vocabulary back - no shape without a real consumer - is met by
this milestone rather than stepped around.

WHAT EXISTS. P02M0099's HID expansion item left the gamepad half open for exactly one reason. The device
side is done: the shared report-descriptor parser keeps the Generic Desktop game controls and the Button
page with their logical bounds, six fixtures hold that, and `usb-gadget.sh setup hid-gamepad` builds a real
USB gamepad in the harness - four axes (X, Y, Z, Rz, eight bits each) and sixteen buttons. What is missing
is a SHAPE: `liber:input@1` carries `pointer-event`, `key-event` and `contact-event`, and none of the three
is a set of axes with a button bitmap. A gamepad forced into any of them is the flattening the HID item
exists to prevent.

## P02M0192 - The vocabulary

- [ ] `liber:input@1` gains a gamepad: a record naming the device (a stable per-attachment identity and the
  provider's label), its axes (usage, logical minimum and maximum, the value), its buttons (a bitmap over
  button numbers, up to 32), and hat switches (eight directions or centred). Additive; the version stays 1.
- [ ] A gamepad stream on `input`: the devices present when it opens, then a state change per report, then
  an arrival or a departure as each happens - so a consumer knows WHICH gamepad pressed WHAT.
- [ ] FOCUS IS DECIDED HERE, NOT IN THE DRIVER. A graphical application receives gamepad input only while it
  holds display focus, on the same one-shot proof `subscribe-keys` and `subscribe-contacts` take, and on
  focus loss every held button is released to it before the stream closes - the rule the touch stream
  already has. A console program is granted the stream through its own capability, `input-gamepad`,
  appended to the vocabulary.

## P02M0192 - The mapping

- [ ] P02M0099's HID expansion maps a parsed gamepad collection onto the record - axes by usage, buttons by
  number, hats by their logical range - and publishes it to InputService as a gamepad provider; a report
  whose fields fall outside their declared logical bounds is refused, not clamped into a plausible value.
  That half of the HID item closes when this lands.

## P02M0192 - The tool

- [ ] `gamepad`, a text tool: a line per connected gamepad with its label, its pressed buttons by number
  and its axes as values within their range, redrawn in place as reports arrive; arrivals and departures
  shown as they happen; `q` or Ctrl+C leaves and restores the console.
- [ ] Two gamepads at once, because "which gamepad" is half of the question: the harness builds ONE USB
  device carrying TWO HID gamepad functions, and a helper process writes button and axis reports into each
  function's `/dev/hidgN` in a scripted order.
- [ ] A cold development scenario gate, `qemu-gamepad-tool`: the tool lists two gamepads; a button pressed on
  the second is shown on the second and not the first; releasing it clears it; an axis moved to its
  extremes shows the range's ends; and unplugging one removes its line while the other keeps working.

## P02M0192 - Verification

- [ ] Host tests of the mapping over the gadget's exact descriptor and hostile variants; the cross-builds;
  the dynamic report refreshed for the tool.

EXCLUDES: force feedback and rumble (an output report, and a separate authority); gamepads over Bluetooth
(P02M0180's HID profile would consume this vocabulary later, not define it); button remapping and
calibration profiles.
