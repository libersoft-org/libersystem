# M0145 - The kernel's lowest layers do not yet keep the promises the upper ones make

A fourth-party audit of the kernel, verified against the code at `7352135` on 2026-08-06. It
reports 37 findings across three severities. **Every finding checked against the source held.**
Nothing was hallucinated, and one claim was found to be UNDERSTATED rather than overstated.

The audit's own summary is the fair one: this is not a badly built kernel. Capability handles with
rights and generations, per-process address spaces, resource domains, explicit W^X, quotas,
rollbacks - the design is a real capability microkernel rather than a hobby monolith. What it does
not yet have is the transactional and synchronisation machinery that design REQUIRES once it runs
untrusted ring-3 code on more than one CPU. Several subsystems already assume both.

One correction to the audit, in its favour and against it in one place each:

- **Understated.** The `ET_EXEC` chain is worse than described. Verified end to end: `validate_segment`
  is passed `window = None` for `ET_EXEC`, `AddressSpace::try_map` passes straight to the mapper with
  no half check, the x86_64 syscall entry decides its origin from the SIGN of the return RIP
  (`test rcx, rcx` / `js`), and `user_buf_ok` returns `true` UNCONDITIONALLY when
  `!in_user_syscall()`. All four links exist today. That is a complete privilege-escalation path,
  not a hazard.
- **Overstated, slightly.** The audit says `user_buf_ok` does not confine a buffer to userspace. It
  does - `if end > USER_VA_END { return false }`. Its other three claims about that function are
  exact: no `USER` permission bit, no write permission, and a time-of-check window before the copy.

Ordered by the audit's own phases, which are the right ones.

## Phase 1 - closing the userspace/kernel boundary

Until these are done, untrusted ring-3 code is not isolated. Everything else on this list is a
correctness problem; these are a security boundary that is currently open.

- [ ] **An `ET_EXEC` image is not confined to userspace, and the syscall entry trusts an address
  sign.** `elf.rs` computes `window` as `(image_type == ET_DYN).then_some(...)`, so an `ET_EXEC`
  segment is checked for overlap and alignment and against nothing else. `try_map` does not bound
  the address either.

  The exploit chain is complete without any other bug: map an executable page in the higher half,
  jump to it, issue `SYSCALL`. The entry stub reads a negative return RIP, takes the kernel
  self-call path, leaves the user stack in place and sets `FROM_USER = 0` - after which every
  `user_buf_ok` in the kernel returns `true` for any address at all.

  Four things to fix, and they are independent defences: validate every segment against an explicit
  userspace range regardless of image type; bound `try_map_user` itself so no caller can ask for the
  kernel half; separate the kernel's own `syscall_dispatch` calls from the hardware `SYSCALL` entry
  so origin is never inferred from an address; and make `user_buf_ok` refuse rather than pass when
  it cannot establish the caller is ring-3.

- [ ] **User pointer access is not fault-safe and checks the wrong things.** `user_buf_ok` proves a
  page is translatable and nothing more: not that it carries `USER`, not that it is writable for a
  copy-out, and not that it is still mapped when the copy happens - another thread of the same
  process can unmap between the two. The copy is then a raw `copy_nonoverlapping` in ring 0, and a
  ring-0 fault is treated as a kernel bug and stops the machine.

  Wanted: real `copy_from_user` / `copy_to_user` / `read_user_value` / `write_user_value` that check
  U/S and R/W, hold the address space against concurrent unmap (or pin the pages), copy in bounded
  chunks, and have an architectural fault-recovery table so a fault returns an error instead of
  panicking.

- [ ] **The mapper overwrites a live leaf PTE without a word.** `try_map_page_in` writes the leaf
  with `entry.write_volatile(...)` unconditionally. Mapping over an existing mapping silently
  replaces it: the previous frame is leaked, a second load can overwrite the first, two concurrent
  stack faults can overwrite each other, and one loader's rollback can remove another's mapping.
  The hierarchy walk also does not everywhere distinguish a table pointer from a large-page leaf.

  Wanted: a typed `MapError` with `AlreadyMapped`, `HugePageConflict`, `InvalidAddress`,
  `PermissionConflict` and `OutOfMemory`, and intermediate table creation that is either
  transactional or hands the caller a token it can roll back.

- [ ] **A syscall can ask the kernel for an unbounded allocation.** `sys_channel_send_caps` does
  `alloc::vec![0u8; bytes_len as usize]` before the message is charged to any quota, and
  `MAX_MESSAGE_CAPS` exists while `MAX_MESSAGE_BYTES` does not. The same shape is in `read_bytes`,
  in the ELF load path, and in `wait_any`'s per-count vectors. These are infallible `vec!`
  allocations, so exhaustion is an allocation-error handler rather than an error return.

  Wanted: an explicit maximum for a message, an ELF image and a wait set; `try_reserve_exact`
  everywhere a length comes from userspace; and the quota charged BEFORE the payload is built, not
  after.

## Phase 2 - physical memory and SMP

- [ ] **There is no TLB shootdown.** Every architecture invalidates locally only - `invlpg`,
  `tlbi vae1`, `sfence.vma` - and nothing tracks which CPUs an address space is live on, sends an
  IPI, or waits for acknowledgement. A process with threads on two CPUs can have CPU A unmap a page
  and return the frame to the allocator while CPU B still holds the translation and keeps writing
  through it, into whatever the frame becomes next - including a page table.

  Wanted: a per-address-space active-CPU mask, a TLB generation, an IPI shootdown with ACKs, and
  leaf frames released only after the shootdown completes. Teardown can use ASID/PCID generations or
  epoch-based reclamation instead.

- [ ] **`kstack_ptr` is written both atomically and not.** It is an `AtomicU64` that the scheduler
  reads with `load(Acquire)`, while the context-switch assembly writes the same memory with a plain
  `mov [rdi], rsp` / `str x2, [x0]` / `sd`. That is a data race by the Rust memory model, and on
  AArch64 and RISC-V the plain store carries no release ordering - another CPU can observe a
  non-zero SP and start restoring a register frame that is not globally visible yet.

  Wanted: split the state - `saved_sp: UnsafeCell<u64>` plus a `park_complete: AtomicBool` released
  after the registers are stored, with the waker acquiring before it reads the SP.

- [ ] **Two last threads can both decide they are not the last.** `sched` counts other live threads
  from a `process.live_threads()` snapshot and calls `mark_exited()` when it sees none. Two threads
  exiting concurrently each see the other, neither marks the process exited, and the process stays
  formally alive forever: `wait` never returns, handles never close, peers never see `PeerClosed`,
  quotas stay held.

  Wanted: an atomic live-thread counter with `fetch_sub(1, AcqRel) == 1` deciding the finaliser, and
  thread creation raising it under the same lifecycle lock and refused once terminating.

- [ ] **The frame allocator can deadlock on the heap it feeds.** `FrameAllocator` holds
  `heap: Option<Vec<Run>>` under a global `SpinLock`, and inserting a freed run can grow that `Vec`.
  The global allocator's `alloc` calls `grow()`, and `grow()` calls `frame::allocate()` - so the
  frame lock is held across a path that takes the frame lock again. On one CPU that is a self
  deadlock on a spin lock; across two it is the classic AB-BA.

  The invariant is written down in `frame/mod.rs` and is not true: "the kernel heap never allocates
  frames at runtime (its window is mapped once at boot), so growing the Vec under the frame lock
  cannot re-enter this allocator". `heap::grow` is reached from `alloc` whenever a request does not
  fit.

  Wanted: the frame allocator must not use the heap it supplies - a bitmap, a buddy allocator,
  pre-allocated run descriptors, or metadata in a reserved physical region.

- [ ] **Kernel thread stacks have no guard page.** Each thread's stack is a `Box<[u8]>` from the
  kernel heap. An overflow corrupts neighbouring heap objects or allocator metadata and surfaces far
  from its cause. Wanted: stacks mapped in their own VA range with an unmapped guard page below, and
  an emergency stack for double faults.

- [ ] **`SpinLockGuard` can be moved to another CPU.** It holds only `&SpinLock<T>` and a `bool`, so
  it is auto-`Send` whenever the lock is `Sync` - while its `Drop` restores the interrupt state of
  the CPU that runs the drop. Moving it re-enables interrupts on the wrong core and leaves the
  original one with interrupts off. Wanted: make the guard `!Send` with a `PhantomData`, and record
  the acquiring CPU in debug builds.

- [ ] **A late AP can take another AP's identity and stack.** x86 bring-up uses single global
  statics - `AP_CPU_ID`, `AP_LAPIC_ID` and one trampoline stack - and moves on after a timeout. An
  AP that arrives after the mailbox has been rewritten reads the NEXT AP's identity and stack, which
  can initialise one per-CPU slot twice and run two CPUs on one stack. Wanted: a per-AP mailbox with
  a generation token and `Pending`/`Accepted`/`Expired`, and a late AP with a stale generation
  refused entry to the scheduler.

## Phase 3 - capability and lifecycle transactions

- [ ] **A capability transfer is a clone followed by a close whose result is ignored.**
  `sys_channel_send_caps` builds every `Capability` under the handle-table lock, releases it, sends,
  then re-takes the lock and does `let _ = table.close(...)`. Two consequences, and the second needs
  no race at all:

  Two threads of one process transferring the same handle both find it valid, both clone, both send,
  and only one `close` succeeds - the other failure is discarded. And a single caller may simply
  list the same raw handle twice in one `SEND_CAPS` array: nothing rejects duplicates, so one handle
  becomes two capabilities. Either way a capability is duplicated without the `DUPLICATE` right,
  which is the capability model's central promise.

  Wanted: transactional handle-table operations - `reserve_for_transfer` / `commit` / `rollback`, or
  `take` / `put_back` - a batch transfer that refuses duplicate entries, removes all capabilities
  atomically, returns them all if the send fails, and never transfers by cloning.

- [ ] **`SYS_HANDLE_DUPLICATE` walks past the handle limit.** `HandleTable::duplicate` finishes with
  `self.insert(...)`, the unbounded variant, while `try_insert` exists beside it. A process holding
  one handle with `DUPLICATE` can exceed `PROP_HANDLE_LIMIT` indefinitely. The plain `CHANNEL_RECV`
  path and some bootstrap paths use the unbounded insert too. "A transfer must always succeed" is
  not an invariant that can hold when the receiving table can be full.

- [ ] **Receive removes the message before it knows it can deliver it.** `recv_caps` dequeues first
  and only then discovers that the payload does not fit, or that handle quota is short, or that some
  capabilities cannot be installed. A too-small buffer returns an error with the message already
  gone; short quota installs a prefix and drops the rest. Wanted: a peek that reports payload size
  AND capability count, target handles reserved before the dequeue, and an all-or-nothing receive.

- [ ] **A failed thread creation can lose the bootstrap capability.** `SYS_THREAD_CREATE` moves the
  capability into the child and closes it in the parent BEFORE creating the thread. If the thread
  quota or the stack allocation then fails, the capability sits in the child with no thread to
  receive its raw handle, and the caller no longer has it. Wanted: reserve the thread and the handle
  slot before committing the transfer, or make the whole sequence one rollback transaction.

- [ ] **A terminal state is published before the cleanup it promises.** `mark_exited` stores
  `exited = true` and only then calls `close_all()`; `terminate()` sets `killed` before unmapping
  objects and closing handles. A waiter can observe a finished process whose mappings and
  capabilities still exist, and a concurrent syscall can create a mapping or a thread that the
  cleanup snapshot has already passed. Wanted: `Running → Terminating → Terminated`, the terminal
  state published last, and every mutating syscall refused from `Terminating` on.

- [ ] **Mapping an object is a check followed by an act.** `is_mapped_in` and `add_mapping` take the
  lock separately, so two threads can both find an object unmapped and both map it.
  `forget_memory_mapping` then uses `retain` to drop EVERY reference to that object while the object
  side removed only one - so the second mapping stays in the page tables, leaves the process cleanup
  list, outlives the object, and later points at frames belonging to something else. Wanted: an
  atomic `Absent → Reserved → Mapped` reservation, per-mapping identifiers so cleanup removes
  exactly one, and every create/map refused once terminating.

- [ ] **Dynamic modules reserve a count, not a slot.** A process carries `dynamic_modules:
  AtomicUsize` and no record of which biases are taken. Two loads at the same bias both pass the
  count check, both map the same addresses, the second overwrites the first's PTEs, and either
  one's rollback unmaps the other's. `resolve_dynamic_symbol_by_suffix` promises uniqueness in its
  comment and returns the first match. Wanted: a locked `slot → ModuleState` table with atomic
  reservation, and an ambiguity error from the suffix resolver.

- [ ] **A domain can outlive its parent.** A child holds its parent `Weak` while the parent holds
  children strongly, so a child can survive a parent it can no longer charge through - after which
  the enclosing limits stop applying. `kill()` also flags, snapshots, then kills the snapshot, so a
  process registered concurrently escapes; neither `new_child` nor `register_process` refuses an
  already-killed domain. Wanted: one direction strong and the other weak (or a central tree owner),
  and an atomic register-unless-killed.

- [ ] **The loader leaves live PTEs pointing at freed frames.** `load_image_into` maps the ELF
  segments into the process address space and then maps the stack; when `map_stack` fails it calls
  `free_frames(frames)` and unmaps nothing. The segments' page table entries still name frames that
  are back in the allocator - a use-after-free of physical memory as soon as they are handed out
  again. `map_stack` has no rollback of its own, and `SYS_PROCESS_LOAD` is not visibly restricted to
  one `Created → Loaded` transition.

  Wanted: a loader transaction recording every PTE created, every data frame, every page-table
  frame and every symbol registered, unwound in reverse on any failure - and an atomic process image
  state so a second load cannot overwrite the first.

- [ ] **`DeviceMemory` does not know which address space it is mapped in.** It stores only
  `mapped_at: AtomicU64`, and `Drop` calls `paging::unmap_page(base)`, which acts on whichever
  address space is ACTIVE when the last `Arc` goes away - a supervisor, another thread, another
  process entirely. The unrelated process loses that virtual address, the driver's real mapping
  survives, and the VA range returns to the pool while it is still mapped. Wanted: mappings that
  carry their address space and are torn down with `unmap_page_in`, owned by the process rather
  than by the globally shared MMIO object.

## Phase 4 - the wait subsystem

- [ ] **Arming a timer wakes nobody.** `Timer::set` stores the deadline and the armed flag and does
  not call `wake_object`. A thread already parked on an unarmed timer's KOID stays parked after
  another thread arms it. `WAIT_ANY` also does not fold timer deadlines into the scheduler deadline
  it computes, so without an external timeout it does not wake at expiry either. Wanted: `set` and
  `cancel` wake the KOID's waiters, and `WAIT_ANY` takes the minimum of its own timeout and every
  timer in the set.

- [ ] **A process group is not told when its members die.** A waiter registers on the group's KOID
  while member termination wakes only the process KOID, and nothing registers the group as an
  observer. A group can report `finished()` while a waiter without a timeout waits forever. Also
  `size()` is documented as the original fixed membership while `live()` prunes dead weak references
  out of the same vector, so it changes. Wanted: member termination propagated to the group, or
  waits decomposed onto member KOIDs - and the original size stored separately.

## Hardening and portability

- [ ] **Introspection ignores revocation.** `lookup` checks `Capability::is_valid()`; `info`,
  `rights_of`, `badge_of` and `entries` check only the slot and its generation, so a revoked handle
  still reads as live in the System Graph. Wanted: one validation path used by every accessor.

- [ ] **Generations are 32-bit and wrap.** Object and handle-slot generations both wrap, so after
  2^32 recycles an old token matches again - reachable by deliberate churn. Wanted: 64-bit
  generations, and a slot retired rather than wrapped.

- [ ] **Raw frame deallocation is a safe function.** `pub fn deallocate(phys: u64)` takes a bare
  physical address and is safe, though correctness needs the caller to own the frame and free it
  exactly once. Wanted: an owning `Frame`/`FrameRun` type, `unsafe` on the raw form, and an
  ownership bitmap in debug builds.

- [ ] **Resource accounting can wrap and hides underflow.** `charge` is `used.fetch_add(amount,
  AcqRel).saturating_add(amount)` - the saturation applies to the value computed from the result
  while the atomic itself can wrap - and `uncharge` uses `saturating_sub`, so a double refund
  silently reads as zero. Wanted: checked CAS, invariant assertions, and fail-stop in debug and test
  builds. An accounting bug should not be masked by the accounting.

- [ ] **The scheduler migrates threads while parts of the code assume it does not.** A wake enqueues
  the woken thread on the waker's CPU, so a thread can resume on a different core than it left.
  Some comments and synchronisation choices are written for the opposite. Wanted: either migration
  supported and every per-CPU state, TLB assumption, syscall stack and interrupt state audited for
  it, or a `home_cpu` and affinity that puts the thread back.

- [ ] **`USER_VMAP` is one global pool for every process.** Userspace mmap addresses come from a
  single `VaPool` spanning `USER_MMAP_BASE..USER_VA_END`, though two address spaces may safely use
  the same virtual address. It contends globally, lets one process exhaust the VA space for all of
  them, and complicates range lifetime for nothing. Wanted: a `VaPool` per address space.

- [ ] **MMIO mapping ignores a non-page-aligned physical base.** `DeviceMemory` keeps `phys_base` as
  given and maps by pages; nothing records `phys_base % PAGE_SIZE` or rounds the length up around
  it. A BAR or sub-region that does not start on a page boundary yields a virtual address that does
  not point at the register the caller asked for. Wanted: map from `align_down(phys_base)`, span
  `align_up(offset + len)`, and return `va + offset`.

- [ ] **RISC-V ignores `NO_CACHE`.** `leaf_bits` builds `PTE_V | PTE_A | PTE_D | PTE_R` plus W, X and
  U and never consults `NO_CACHE`, relying on the platform's physical memory attributes. That holds
  on QEMU virt and is not a general answer: MMIO without correct attributes can be reordered or
  cached. Wanted: Svpbmt/PBMT where available, platform PMA otherwise, and a clear error when the
  requested semantics cannot be guaranteed.

- [ ] **ACPI parsing trusts firmware lengths and addresses.** The SMP path reads RSDP/RSDT/XSDT/MADT
  through raw HHDM pointers with some minimum-length checks and no checksum validation, no bounds
  against the memory map, and no overflow guards. A damaged table can send the kernel outside the
  direct map. Wanted: one validated reader with checked arithmetic, region bounds and checksums.

- [ ] **AArch64 NX reporting does not match the mapper.** The paging code sets execute-never
  attributes while the helper used to report NX support does not derive its answer from them, so a
  test can skip the check or the system can report NX inactive while leaves use it. Wanted: derive
  the helper from the translation controls actually programmed.

- [ ] **The privileged console and display syscalls are not capability-gated.** The comments say so
  themselves - gating was deferred. `SYS_FRAMEBUFFER_MAP` checks a buffer and whether the console is
  disabled and nothing else, so any process can take the display before ConsoleService does;
  `SYS_CONSOLE_FEED` can inject keyboard and serial input into a privileged console; and
  `SYS_CONSOLE_ATTACH` can redirect the console sink and silence kernel output. Wanted: distinct
  `DisplayController`, `ConsoleInputSource` and `ConsoleSink` capabilities endowed only to the
  services that should hold them.

## The tests this needs, which are not the tests it has

The audit's closing observation is the one worth keeping: the gap is not the NUMBER of tests, it is
their kind. The kernel has many, and they exercise happy paths, fault handling, SMP bring-up and
ring-3 entry. Almost nothing here is reachable that way. These findings need a deterministic
interleaving, a fault injected at a chosen N-th allocation, two genuinely concurrent CPUs, an
invariant checked after a rollback, or churn under load.

- [ ] **Capability transfer**: two threads transferring one handle; the same handle listed twice in
  `SEND_CAPS`; a send that fails on a full queue leaving every handle with the caller; a receiver
  short of quota; a receiver whose buffer is smaller than the payload; a thread creation that fails
  after the bootstrap transfer is staged.

- [ ] **Page tables**: mapping over a mapped VA must report `AlreadyMapped`; a user API must refuse
  the kernel half; a malicious `ET_EXEC` with a high `p_vaddr`; a segment overlapping the stack or
  the mmap window; OOM at each individual level of hierarchy creation, with the rollback leaving
  every prior mapping untouched.

- [ ] **TLB and SMP**: two threads of one process on two CPUs; CPU A unmaps and the frame is
  immediately reallocated; CPU B must not reach the old translation after the shootdown ACK; the
  same again through process teardown and stack growth.

- [ ] **Loader OOM injection**: fail deterministically at the first ELF data frame, at each
  intermediate page-table frame, at the first stack frame, mid-stack, at symbol registration, and at
  dynamic module mapping - and after every one, the page tables, the frame count and the process
  metadata must equal their state before the call.

- [ ] **Scheduler**: two last threads exiting together; a thread woken onto a different CPU; two
  CPUs waking one thread; starting an already-started thread; a kill during a map syscall; a kill
  during thread creation; an AP arriving after the boot timeout.

- [ ] **Wait subsystem**: a timer unarmed at the start of a wait and armed later; `WAIT_ANY` with
  only a timer and no external timeout; a process group finished by its last member; a channel
  closing exactly as a waiter registers; a stop/continue between the readiness check and the park.

- [ ] **Fuzzing**: ELF headers and program headers, dynamic relocation tables, syscall arguments and
  lengths, capability transfer arrays, the ACPI/MADT parser, map/unmap sequences, and handle
  generation churn through close and duplicate.

## What this audit does not say

Nothing here was reproduced at runtime; the audit was static and so was this verification. Of the 37
findings, 27 were checked line by line against the code they name and every one held. The remainder
- parts of the thread-start path, the receive ordering, the heap's alignment-prefix loss, and the
process-group and domain lifetime details - were read but not traced end to end, and are recorded on
the audit's reading rather than on an independent one. They are marked by nothing special because
the fix for each begins with confirming it, which is where the work starts anyway.

The severity ordering is the audit's and is worth keeping: the boundary comes first, because until
`ET_EXEC` validation, the mapper's address bound, the syscall origin and fault-safe user copies are
done, everything else is a correctness problem inside a system that is not isolated to begin with.
