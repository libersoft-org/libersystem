# P02M0135 - Foreign graphics-stack prerequisites

Status: FUTURE TRACK. INDEPENDENT OF P02M0103 AND NOT A PHASE-2 COMPLETION GATE.

Split out of `P02M0103` on 2026-08-15. It lived there as `P02M0103a2` and nothing in `P02M0103`
depended on it - the software 2D and 3D stacks are `no_std` Rust and never needed a C++ substrate.
Keeping it there meant a milestone about building a 2D/3D library also had to be about cross
compilers, ELF TLS and upstream license provenance, which is two milestones wearing one number. The
split changes no content and no decision; it changes what each milestone is answerable for.

Needed before importing Mesa, a Vulkan loader or any upstream C/C++ graphics stack. It gates none of
`P02M0103`, and `P02M0103` gates none of it: the two can be built in either order or at the same
time.

- [ ] Prepare the foreign-library and toolchain substrate, but import no stack. Pin cross C/C++
  compiler and archive/link steps for the three targets; provide EXACTLY the foreign ABI facilities
  the pinned upstream configuration requires - allocator, memory/string/math, monotonic time,
  atomics, threads, mutex/condition/event waits, mapped MemoryObjects and dynamic-provider lookup,
  plus thread-local storage only under the condition the next item sets. Maintain an exact
  required-symbol inventory derived
  from a chosen Mesa or Vulkan-loader configuration; do not grow a general POSIX layer or expose
  ambient files, processes or devices. Host build tooling must accept reproducible Meson/CMake object
  lists without bypassing P02M0096a identity, relocation, W^X, provider and license audits. Audit
  the ABI and not only the symbol list: exception and unwind tables, RTTI, static initialisers and
  their ordering, `atexit` registration and the `errno` model are what a C++ stack needs from a
  platform, and a required-symbol inventory does not mention any of them.

- [ ] Resolve the TLS blocker before promising the substrate, and resolve it as ONE of two variants
  rather than as both at once. `docs/DYNAMIC_LINKING.md:197` refuses TLS relocations by name. TLS is
  MANDATORY if and only if the selected binaries emit `PT_TLS`, TLS symbols or TLS relocations, and
  which of the two variants applies is a decision this milestone makes rather than discovers:

  - VARIANT A - support it: `docs/DYNAMIC_LINKING.md` changes with a stated design covering `PT_TLS`
    segments, the architecture-specific TLS relocations for all three targets, the per-thread block
    allocation and its accounting, and thread teardown.
  - VARIANT B - avoid it: the inventory is built against a configuration that emits ZERO TLS
    requirements, and the audit PROVES their complete absence rather than assuming it - no `PT_TLS`
    segment, no TLS relocation, no TLS symbol in any pinned object.

  Whichever is chosen, the required-symbol inventory and the substrate item above are built to match
  it; a substrate that promises TLS while the audit is meant to prove there is none is neither.

- [ ] Record the dependency and licensing policy before selecting upstream code. LiberSystem-owned
  implementation stays Unlicense; imported Mesa, Vulkan loader, compiler runtime or conformance
  sources keep their own compatible notices with exact source, version and patch provenance. The
  image identity records bind generated objects to that inventory, and the build rejects an
  unreviewed license, a downloaded-at-build source or a copied implementation with lost attribution.
  This milestone imports none of those projects; its synthetic build proves the audit path.

- [ ] Reserve loader/ICD discovery under P02M0097's system layout, and reserve the POLICY rather than
  designing the schema. Freeze what is already decidable without an upstream stack in hand: paths are
  package-owned and identity-checked, metadata is bounded and versioned, and there is no
  environment-variable search path, no current-directory plugin load and no arbitrary `dlopen`. The
  exact manifest fields - API name and version, architecture, entry provider, backend identifier,
  required extensions - are designed against the Vulkan loader or Mesa configuration this milestone
  actually pins, by the same rule that deferred `P02M0103`'s adapter/device/context/queue vocabulary:
  a manifest whose only consumer is the synthetic provider written to exercise it earns an adapter
  between it and the real one. Only a synthetic provider is discovered and selected or rejected in
  tests; no GL or Vulkan ABI is exported.

- Done when: the foreign-driver/provider integration substrate has a reproducible synthetic proof, a
  resolved TLS variant, a recorded licensing and provenance policy, and no accelerated API
  implementation.
- Explicitly deferred: actual EGL/OpenGL/OpenGL ES/Vulkan entry points and conformance; Mesa/Gallium,
  LLVM shader compilation, GLSL/SPIR-V compilation, virglrenderer/Venus, virtio-gpu
  context/blob/3D command execution, and native hardware drivers. Each requires a separately approved
  milestone and must consume P02M0103's contracts rather than weakening capability, validation,
  accounting or identity gates.
- Concept: P02M0103 (the graphics platform this would eventually plug into), P02M0093/P02M0096a
  (shared providers and PIE ownership), P02M0097 (final userspace/system layout),
  `docs/DYNAMIC_LINKING.md` (the relocation set and its refusal of TLS).
