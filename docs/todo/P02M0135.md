# P02M0135 - Foreign graphics-stack prerequisites

Status: FUTURE TRACK. INDEPENDENT OF P02M0103 AND NOT A PHASE-2 COMPLETION GATE.

Split out of `P02M0103` on 2026-08-15. It lived there as `P02M0103a2` and nothing in `P02M0103`
depended on it - the software 2D and 3D stacks are `no_std` Rust and never needed a C++ substrate.
Keeping it there meant a milestone about building a 2D/3D library also had to be about cross
compilers, ELF TLS and upstream license provenance, which is two milestones wearing one number. The
split changes no content and no decision; it changes what each milestone is answerable for.

Needed before importing Mesa, a Vulkan loader or any upstream C/C++ graphics stack. It gates none of
`P02M0103`, and `P02M0103` gates none of it: the two can be built in either order or at the same
time.

## What this milestone claims, and what it does not

Corrected 2026-08-30 after the 2026-08-30 plan audit. The first version promised an "exact
required-symbol inventory derived from a chosen Mesa or Vulkan-loader configuration" and, four
bullets later, that it imports none of those projects and that a synthetic build proves the audit
path. Both cannot be true. An inventory derived from nothing is a guess, and a guess is exactly what
the first real import discovers - which is the failure this milestone exists to prevent.

The claim is therefore narrowed and made derivable:

**This milestone prepares the substrate for ONE NAMED, PINNED upstream configuration, and says so.**
It does not prepare "Mesa, a Vulkan loader, or any upstream C/C++ graphics stack". Evidence gathered
against one configuration cannot carry a claim about the others: they differ in libc surface, C++
runtime use, TLS models and discovery layout, and those differences are the substance of the work.
A second consumer earns a second, separately approved profile that reuses this milestone's
mechanisms and re-derives its own inventory.

**The pinned upstream is an AUDIT-ONLY, COMPILE-ONLY input.** It is fetched once, offline, from a
recorded archive digest, cross-compiled to objects, and inspected. It is never linked into anything,
never staged, and never enters the system image. That is what makes "derive the inventory" and
"import no stack" compatible instead of contradictory.

**The final-link closure is NOT this milestone's, and cannot be.** The audit asked for the inventory
to be derived from the complete three-target object AND final-link closure. The object closure is
derivable here; the final link is not, and asking for it is circular - a final link needs the
substrate whose contents this inventory is supposed to decide. The object closure yields the
undefined-symbol set, which is the input the substrate is built from; the final link is the
IMPORTING milestone's gate and is named as such below.

## Items

- [ ] **Pin the upstream reference configuration, and record everything the inventory is derived
  from.** Before any substrate work, choose ONE of Mesa or a Vulkan loader - not "or" - and record,
  in this file and in a checked-in lockfile the build reads:
  the project, the exact upstream version and the SHA-256 of the source archive; the ordered patch
  series with a digest per patch, or the explicit statement that there is none; the Meson or CMake
  option set in full; the three cross files or toolchain files, one per target; the compiler,
  archiver and linker versions and their flags; and the compiler-runtime component the configuration
  requires and where it comes from. Sources are fetched ONCE and vendored or content-addressed;
  a build that downloads is a build that is not reproducible, and it is refused by the licensing
  item below.
  This input is AUDIT-ONLY: compiled to objects for all three targets, inspected, and discarded.
  Nothing it produces is staged, linked into an image, or named by any manifest.

- [ ] **Derive the required-symbol and ABI inventory from that configuration rather than declaring
  it.** For each of the three targets, compile the pinned configuration to its complete object
  closure and record: every undefined symbol with its type and binding; every symbol the
  configuration expects from a compiler runtime; every TLS symbol, `PT_TLS` segment and TLS
  relocation form; every relocation form used; the C++ ABI facilities actually referenced -
  `__cxa_*`, unwind personality/RTTI symbols, `.init_array`/`.fini_array` entries, `atexit`
  registration, `errno` access; and the discovery-metadata layout the configuration reads at
  runtime. The three targets are recorded SEPARATELY and the differences between them are part of
  the evidence: an inventory that is the same on all three has not been derived from three builds.
  The inventory is a generated artifact with a digest, regenerated rather than edited, and a
  regeneration that differs from the recorded one fails the gate.

- [ ] **Provide EXACTLY the foreign ABI facilities that inventory names, and nothing beyond them.**
  Allocator, memory/string/math, monotonic time, atomics, mapped MemoryObjects; threads and
  mutex/condition/event waits ONLY under the thread prerequisite below; thread-local storage ONLY
  under the TLS item below; provider lookup ONLY under the discovery item below. Do not grow a
  general POSIX layer and do not expose ambient files, processes or devices. A facility that the
  derived inventory does not name is not built: this milestone's scope is the closure of one
  configuration, and every symbol outside it is a POSIX layer arriving one function at a time.

- [ ] **PREREQUISITE, NOT OWNED HERE: a self-thread runtime.** The substrate cannot promise threads,
  mutexes, condition variables or event waits, because nothing beneath them exists. A new process
  receives only its bootstrap channel; `SYS_THREAD_CREATE` requires `MANAGE` on an explicit Process
  handle, which an ordinary application does not hold over itself; the only runtime wrapper,
  `rt::process_prepare`, is the process-LAUNCH path and always uses the one `USER_STACK_TOP`; demand
  stack growth is bound to that same single span, so a second thread cannot have a growable stack;
  Thread is not a waitable object, so there is no join; and Event is a latched boolean whose only
  reset is `#[cfg(test)]`, so there is no reusable wakeup. Granting each application broad Process
  `MANAGE` authority over itself, or inventing private stacks and polling inside the foreign shim,
  would violate the capability and accounting model and still leave lost wakeups and shutdown
  undefined.
  THIS MILESTONE DOES NOT BUILD THAT. It requires a separately approved milestone - not yet created
  or numbered - owning: narrow self-spawn authority that is not process-management authority;
  independently placed guarded stacks with their own accounting; join and detach with a defined exit
  and failure-propagation contract; per-thread runtime state initialisation; and blocking
  synchronisation with a stated memory-ordering and wakeup contract, including a resettable or
  paired wakeup object. `P02M0103` needs the same mechanism for its renderer worker pools and must
  consume the SAME contract; two private thread runtimes for one system is the failure this
  paragraph exists to prevent.
  If the pinned configuration turns out to be single-threaded, this prerequisite is dropped and the
  inventory item PROVES the absence of every thread and synchronisation import instead - the same
  standard the TLS item applies to itself.

- [ ] **Decide the C++ ABI, mechanism by mechanism, rather than listing what to inspect.** Exception
  tables and unwinding, RTTI, static initialisers and their ordering, `atexit` registration, and the
  `errno` model each get ONE of two answers, written down: the supported ABI with its named owner,
  or the exact compiler flags plus the artifact check that forbids it. Neither answer may be
  "audit it".
  The tree's current state is the reason this cannot be deferred: `liber_rt_start` performs the ABI
  check and calls the program entry directly, so no constructor or destructor runner exists at all,
  and all three ordinary userspace linker scripts `/DISCARD/` every `.eh_frame*` section - so a C++
  object that compiles and links silently loses its unwind metadata. A symbol-complete synthetic C
  program passes every check this milestone would otherwise run while real C++ is broken.
  Where a mechanism IS supported, state: once-per-process init and fini ordering across the provider
  DAG, what happens when initialisation fails part way, normal exit versus crash semantics, and the
  unique owner and licence of the compiler-runtime, C++ ABI and unwind components. Where it is
  forbidden, the artifact check is a build-time refusal with a watched-fail mutation, on every
  target.

- [ ] **Resolve the TLS blocker as ONE of two variants, and make each variant's evidence
  executable.** `docs/DYNAMIC_LINKING.md` refuses TLS relocations by name, and the package audit and
  runtime loader share that one relocation policy. TLS is MANDATORY if and only if the derived
  inventory shows `PT_TLS`, TLS symbols or TLS relocations. Which variant applies is decided by that
  inventory, and the substrate and inventory items above are built to match it.

  - VARIANT A - SUPPORT IT. `docs/DYNAMIC_LINKING.md` changes, AND the mechanism is implemented and
    proved, because a design document is not TLS. It states: the supported code-generation models
    and the exact relocation forms admitted per target; the TCB, DTV and module-offset layout; the
    initialisation image and its alignment rules; how the initial thread and every later thread are
    set up; the thread-pointer set/save/restore contract on x86_64, aarch64 and riscv64; the policy
    for dynamic accessors; per-thread block allocation, its Domain accounting, and teardown
    including TLS destructors. The package audit and the runtime loader must both ADMIT the chosen
    forms - the two share one policy and changing one without the other is an image that stages and
    will not run, or runs and will not stage. Positive evidence is per-thread isolation observed in
    a guest, not a document.
    Variant A therefore depends on the thread prerequisite above; without threads there is no second
    thread to isolate and Variant A cannot be proved.

  - VARIANT B - AVOID IT. The configuration is pinned such that it emits ZERO TLS requirements, and
    the audit PROVES the absence rather than assuming it. The scan covers every admitted `ET_REL`
    member INCLUDING compiler-runtime and generated objects, and the final linked and staged ELF -
    not a standalone inventory taken once - looking for `PT_TLS`, `STT_TLS` symbols and every TLS
    relocation form. The complete scan input list and its result are bound into the cache key and
    the image identity, so a flag, a compiler-runtime change or a new generated object that begins
    emitting TLS invalidates the evidence instead of silently outliving it. Both the build-time and
    the runtime refusal are mutation-tested and watched to fail.

  Whichever is chosen is named in the Done condition. A substrate that promises TLS while the audit
  is meant to prove there is none is neither.

- [ ] **Define how foreign artifacts enter the manifest, build, cache and identity graph - as a
  first-class kind, not as an exception.** "Host build tooling must accept reproducible Meson/CMake
  object lists without bypassing the identity, relocation, W^X, provider and licence audits" names
  the requirement and no mechanism, and no mechanism exists:
  every manifest source must contain a `Cargo.toml` and every library destination is derived from a
  Rust source-ownership category; `build-shared.sh` asks Cargo for the dependency closure and
  inventories only Rust/Cargo/linker inputs; and the identity record is a fixed-order, Rust-specific
  grammar - `rustc-commit` as 40 hex digits, `rustflags` that must start with
  `-C relocation-model=pic`, non-empty Cargo `features` - which both the packager and ProcessService
  enforce exactly. A foreign artifact can therefore only enter by forging meaningless Rust fields,
  by being appended after identity generation, or by a private fork of the staging graph. All three
  put source, patches, compiler output, providers or licence obligations outside cache invalidation
  and runtime verification.
  This milestone owns the representation:
  a foreign source and artifact kind in the system manifest with a deterministic, ordered object-list
  format; a language-neutral image identity - a new version, not a reinterpretation of the existing
  one - binding the exact compiler, archiver and linker artifacts and flags, the target and sysroot,
  the configure inputs and generated files, the complete source/patch/licence closure, the final
  objects, and the direct providers; and the coordinated changes across `system-manifest`,
  `build-shared.sh`, `mkpackages`, ProcessService, the shared ELF/identity parser, the
  staged-consistency gate and the cache keys, each named. Negative identity tests are part of it:
  a foreign artifact with a malformed, absent or wrong-target record is refused at packaging AND at
  launch, watched to fail.
  Foreign artifacts pass the EXISTING relocation, W^X, export-owner, provider-closure and runtime
  revalidation paths. They do not get a parallel audit, because a parallel audit is the thing that
  drifts.

- [ ] **Choose ONE loader/ICD discovery model, and prove the selected provider actually loads.**
  The policy this milestone freezes is unchanged and stays right: paths are package-owned and
  identity-checked, metadata is bounded and versioned, and there is no environment-variable search
  path, no current-directory plugin load and no arbitrary `dlopen`. What was missing is the loading
  and authority model, without which selection proves nothing: the current model loads the exact
  manifest and `DT_NEEDED` provider closure, verifies each identity edge, and starts the first
  thread only after every eager relocation completes, with lazy binding, replacement, unload and
  search paths all forbidden. There is no `dlopen`/`dlsym` seam, no declared role for a metadata
  file, and no owner holding a narrow capability to enumerate candidates. A post-start loader cannot
  add an ICD without bypassing the identity closure; handing the application StorageService
  authority to scan candidates recreates the ambient-file policy this milestone forbids.
  Pick one and write it down:
  (a) PRE-LAUNCH SELECTION - ProcessService, or a narrow registry it consults, selects the ICD
  before the process starts and adds it to the verified closure. This is the only option that
  requires no new loader mechanism, and it is the recommended one.
  (b) DECLARED CANDIDATE SET - a finite set of candidates declared eagerly in the manifest, all
  verified and loaded, with lookup limited to that closure.
  (c) OUT-OF-PROCESS PROVIDER - the ICD runs as its own governed process and is reached over a
  channel, so nothing is loaded into the consumer at all.
  Whichever is chosen states: the metadata owner and its P02M0097-compatible path and manifest role;
  the capability flow; deterministic duplicate, version and extension selection; the binding between
  the metadata and the code it names, and how that binding resists a change between check and use;
  export-collision behaviour; and accounting and rollback on a failed selection.
  The exact manifest FIELDS - API name and version, architecture, entry provider, backend
  identifier, required extensions - are still designed against the configuration this milestone
  pins, by the same rule that deferred `P02M0103`'s adapter/device/context/queue vocabulary. What is
  no longer deferred is the mechanism the fields are carried by. Selection and refusal are exercised
  through the real launch path with a synthetic provider; a synthetic in-process parser choosing a
  record is not evidence that the record's code can be loaded. No GL or Vulkan ABI is exported.

- [ ] **Record the dependency and licensing policy FIRST, before any upstream source is fetched.**
  LiberSystem-owned implementation stays Unlicense; imported Mesa, Vulkan loader, compiler runtime
  or conformance sources keep their own compatible notices with exact source, version and patch
  provenance. The image identity records bind generated objects to that inventory, and the build
  rejects an unreviewed licence, a downloaded-at-build source and a copied implementation with lost
  attribution. This item precedes the pinning item above in ORDER, because a policy written after
  the source has been chosen is a policy fitted to the choice.
  This milestone imports no upstream project into the image; the pinned configuration is an
  audit-only input under the same licence review as anything else that enters the tree.

## Done when

Named gates, in three tiers. Each is registered in the verification model and wired into
`verify.sh`'s freshness and selection so it runs when its subject changes.

**Host and build gates.**
- The pinned configuration compiles to objects for x86_64, aarch64 and riscv64 from the recorded
  digests, offline, and a repeat build produces an identical inventory digest.
- The regenerated inventory equals the recorded one, per target, symbol for symbol.
- The declared substrate surface EQUALS the derived undefined-symbol closure - no missing symbol and
  no symbol built that nothing requires.
- The selected TLS variant's scan passes: Variant A's admitted forms, or Variant B's proof of
  absence over every admitted `ET_REL` member and the final staged ELF.
- The C++ ABI decision matrix is enforced: every mechanism marked forbidden fails the build when
  reintroduced, watched.
- An attempted build-time download is refused, watched.

**Package gates.**
- A synthetic foreign artifact stages through the real manifest as its declared foreign kind, with a
  language-neutral identity record, and passes the existing relocation, W^X, export-owner and
  provider-closure audits.
- Each of these is refused, watched to fail: a prohibited relocation, a W+X mapping, a wrong-target
  or wrong-architecture identity, a malformed or absent identity record, malformed discovery
  metadata, and an unreviewed licence.

**Guest gates.**
- The synthetic foreign consumer LAUNCHES on all three architectures through ProcessService, its
  provider closure verified, and performs a bounded lifecycle: allocate, map, use each admitted ABI
  facility, and exit cleanly.
- Discovery selects the synthetic provider through the chosen model's real path, and refuses a
  candidate that fails identity, watched.
- Under Variant A, per-thread TLS isolation is observed between two threads in a guest. Under
  Variant B, no such test exists and its absence is the point.
- Under the thread prerequisite, a bounded create/join/shutdown cycle completes with accounting
  returning to its starting values.

The milestone is done when those gates pass for the ONE pinned configuration, the TLS variant is
resolved and named, the licensing and provenance policy is recorded, and no accelerated API is
implemented.

- Explicitly deferred: actual EGL/OpenGL/OpenGL ES/Vulkan entry points and conformance; Mesa/Gallium,
  LLVM shader compilation, GLSL/SPIR-V compilation, virglrenderer/Venus, virtio-gpu
  context/blob/3D command execution, and native hardware drivers. Each requires a separately approved
  milestone and must consume P02M0103's contracts rather than weakening capability, validation,
  accounting or identity gates.
  Also deferred, by name: the FINAL-LINK closure of the pinned configuration and the import of its
  code, which belong to the importing milestone; a second upstream profile; and the general POSIX
  layer this milestone exists to avoid.
- Required and NOT owned here: the self-thread runtime, which has no milestone yet and must be
  approved and numbered before either this milestone's thread facilities or `P02M0103`'s worker
  pools can be built.
- Concept: P02M0103 (the graphics platform this would eventually plug into), P02M0093/P02M0096a
  (shared providers and PIE ownership), P02M0097 (final userspace/system layout),
  `docs/DYNAMIC_LINKING.md` (the relocation set and its refusal of TLS).
