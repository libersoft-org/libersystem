# P02M0161 - Every driver family invents its own online-and-stop wire

Status: PLANNED AFTER P02M0098. THE DRIVER PROTOCOL. SECOND OF SEVEN SLICES - see P02M0098 for the split.

## Goal

One handshake between DeviceManager and a driver, versioned, with the binding's generation on
everything either side says. Small enough to read in one sitting.

The claim this milestone may make: after it, a driver's start, its report and its stop are the same
three exchanges whatever the driver is, a message from a replaced process cannot be mistaken for the
replacement's, and a driver built against a different version of the protocol is refused before it is
given a device.

## What is there now

- **EACH DRIVER SPEAKS ITS OWN DIALECT.** A driver receives `DEVICE` plus its `DeviceInfo` and a
  capability, and then says something. `virtio-blk` sends `driver.virtio-blk: online (00:02.0)` and a
  block-service channel; `virtio-input` sends a different string and sometimes a channel; `xhci`
  sends its own. DeviceManager matches on the text and on whether a handle came with it.
- **THE REPORT IS A HUMAN SENTENCE DOING A MACHINE'S JOB.** The boot-report milestone changed those
  strings for readability, and every change had to be chased through the assertions that parse them -
  which is what a report used as a protocol costs.
- **THERE IS NO VERSION AND NO GENERATION.** A driver from an older image and a driver from this one
  are indistinguishable to the manager, and a message from a process it has already replaced is
  accepted as the replacement's.

## Work

- [ ] **M1 - one handshake, in one place, with a version.** DeviceManager sends the binding: its
  identity, its generation, the matched registry entry, and the resource capabilities the claim
  granted. The driver answers `READY` or `FAILED`. A driver whose declared protocol version this
  manager does not implement is refused BEFORE the claim is made, because refusing after it means
  taking a device away from something that never should have had it.

- [ ] **M2 - the generation is on everything, and an old one is ignored.** Every message either side
  sends carries the binding generation from M1. A `READY`, a failure, an exit notification or a
  provider event stamped with a generation that is no longer current is dropped and its handles are
  closed. A process that is being replaced cannot touch its replacement's state.

- [ ] **M3 - the message set is the smallest one that works.** `READY`, `FAILED`, `STOP`, `STOPPED`,
  and the provider events P02M0164 adds. Heartbeats belong to the watchdog and `SUSPEND`/`RESUME` to
  power - both are P02M0165's, and adding them here would be designing for a caller that does not
  exist yet.

- [ ] **M4 - a driver's report is not a sentence.** The human line stays and stops being the protocol:
  what DeviceManager acts on is the typed message, and what it prints is its own. A change to the
  wording of a boot line must not be able to break binding.

- [ ] **M5 - the message is hostile input.** Every field is bounded and validated before it is used:
  a length, a count, a name, a handle count. A driver is a separate process that may be wrong or
  malicious, and a manager that trusts its numbers is one a driver can hang or exhaust.

- [ ] **M6 - the artifact is the one the registry named.** A driver's ELF is checked against the
  digest the generated registry carries for it before it is spawned. A substituted driver is refused
  before it holds a device rather than after.

## Definition of done

- One handshake serves every driver in the image, and the per-family strings are gone from the
  binding path.
- A driver declaring an unimplemented protocol version is refused before any claim is made.
- A message carrying a stale generation is dropped and its handles closed, proved by a test that
  replays one from a replaced process.
- A malformed or oversized field is refused rather than trusted, with a host test per field.
- A driver whose staged bytes do not match the registry's digest does not run.
- Changing the wording of a driver's boot line breaks nothing.

## What the audit found before implementation (2026-08-26)

- **THE PREMISE IS TOO KIND TO THE CURRENT CODE.** This milestone says the handshake is a text
  comparison; it is not one. `launch_one` calls `recv_blocking` and treats `Received::Message` as
  success whatever it contains - it stores the handle, prints the bytes and returns true. So a driver
  sending nothing recognisable is a driver that came up. The test for M1 must therefore refuse an
  unknown opcode, not merely show that changing the text breaks nothing.

- **NOTHING SAYS WHERE THE PROTOCOL VERSION COMES FROM BEFORE THE CLAIM.** A manager that refuses a
  version it does not speak has to know the version before it hands anything over, and the registry
  does not carry one. The smallest answer is a fixed ELF note - `{magic, protocol_version}` - read
  from the staged driver before `device_acquire`, with the handshake confirming what the note
  claimed. Without this the version check happens after the authority has already moved.

- **M6 HAS A BUILD-ORDER CYCLE AND LEAVES THIS MILESTONE.** It wants the registry to carry a digest
  of the staged driver, and the registry is generated when the services are built while the staged
  bytes exist only after stripping and packaging. Closing it means reordering the pipeline so the
  final staged drivers exist first and the registry is generated from them - which is artifact
  integrity, not a protocol. It belongs with the work that owns staging.

- **THE MESSAGE SET IS `BIND`, `RESOURCE/OFFER`, `READY`, `FAILED`, and it carries a handle.** A
  provider handle has to cross in M161 because the system needs a working intermediate state and
  today's drivers hand one back. Dynamic `ADD`/`REMOVE` is P02M0164's; `STOP`/`STOPPED` is P02M0165's
  entirely.

- **THE WIRE FORMAT IS EXACT OR IT IS NOT A PROTOCOL.** A fixed header `{magic, version, opcode,
  generation, payload_len}`, at most one capability handle per frame, a stated size for every
  payload, and every handle closed on refusal. A message that is refused must not leave a capability
  behind.

- **PROCESS EXIT IS NOT A DRIVER MESSAGE.** It arrives on the process handle, not the channel, and
  correlating it with a generation is the state machine's job. It moves to P02M0162.

## What this milestone refuses, and why

- **A general IPC schema or an IDL for drivers.** The tree has LSIDL for services; the driver
  handshake is a handful of messages on one channel and does not need a language.
- **Designing the power and watchdog messages now.** They are named in P02M0165 and will be added by
  the milestone that has a caller for them. A protocol with unused verbs is a protocol nobody has
  tested.
- **Migrating drivers to new capabilities.** This changes how a driver is started and answers, not
  what it is given. The resources are P02M0098's and the binding unit is P02M0163's.
