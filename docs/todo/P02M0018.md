# P02M0018 - FAT / exFAT filesystem backend (read foreign removable media)

Status: COMPLETE.

LiberFS is the system's own filesystem; interop needs the family that USB sticks, SD cards and
install images actually carry. Per the layering principle, FAT sits behind the same Volume API as
just another backend - **no new app-facing API.**

*Condensed 2026-08-08. The nine later audit passes (P02M0056-P02M0065) are where this backend became
hostile-media safe.*

The backend parses the boot sector and auto-detects FAT12, FAT16, FAT32 and exFAT, walks the cluster
chain, and reads the root and subdirectories including VFAT long names. Write support - allocation,
freeing, writing every FAT copy, creating and clearing entries with long names - covers the classic
families; **exFAT stayed read-only** at this point.

**It is host-testable through the same `BlockDevice` trait as LiberFS**, driven against one image
fixture per family, with a live read of a FAT-formatted device in the guest as the end-to-end check.
That decision is why the FAT audit track could later run nine full passes with tests for each finding
without booting anything.
